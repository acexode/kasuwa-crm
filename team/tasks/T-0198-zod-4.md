# T-0198 — zod 3 to 4

**id** T-0198 · **status** `assigned` · **owner** Cursor · **priority** P1 (S0, before S1 and before 2026-12-31) · **module** Repo (all packages) ·
**PRD** Phase 3 plan S0; D-L206 · **deps** T-0153 · **budget** 3 sessions

## Goal

GHSA-mrhx-c7xc-m3w5 (zod 3.25.76, CVSS 8.2) is fixed, not accepted. Every package runs zod 4.6.6 or later, the lockfile has
no 3.x copy, and the entry is gone from `osv-scanner.toml`. S1 then writes the commerce, portal and inbox schemas for zod 4.

## Context

- Eleven package.json files declare zod; about a hundred TypeScript files import it. The wire contract of every endpoint,
  queue payload and config schema must not change: a schema that accepts or rejects differently after the upgrade is a bug.
- Migrate; do not shim. No `zod/v3` imports. Known v4 changes: single-argument `z.record()`, `errorMap` became `error`,
  `.merge`, `.strict` and `z.nativeEnum` are deprecated, error and issue shapes differ, so check `details[].code` mapping.
- `@kasuwa/config` parses the environment with zod, so `pnpm test:unit` and a booted API are the first signal.
- The 512 KiB body cap (`json-body-limit.ts`) stays. Split the work into PRs of about 600 lines or less (structural PRs
  are exempt: say so).

## Acceptance tests

Committed and failing. Do not edit them. Every existing unit, integration and isolation suite must pass unedited.

- `tests/acceptance/platform/zod-4.acceptance.test.ts`

## Non-goals

Changing any endpoint contract, limit or error code; any other dependency; new schemas for S1.

## Definition of done

The named suite passes unmodified; CI green; the OpenAPI files unchanged; `team/reports/T-0198.md` lists every behaviour
difference found and how it was kept the same.
