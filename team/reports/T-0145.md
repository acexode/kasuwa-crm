## What grew, and what I removed

Measured cause, gate vs the T-0127 baseline (724bd7e, the commit D-L199's pins were measured on), board as the example (+90 KB):
- fonts +48 KB;
- JS +24 KB;
- CSS +12 KB;
- document +3 KB;
- API +2 KB;
- prefetches +1 to 2.5 KB.

What went, per item. No visual changes.

1. **JetBrains Mono carved like D-L44** (`packages/ui/scripts/fetch-fonts.mjs`, generalised from `currency: true` to `carveOuts`).
   - Every CRM page downloaded the whole 31.7 KB Latin file for the shell's "Ctrl K" hint, and the board, the deal and onboarding also downloaded the 11.6 KB Latin-Extended file for one ₦.
   - Three small `text=` faces now cover what screens draw:
     - *figures* (7.7 KB): digits, amount, phone, date and range separators, ₦ ₵ $ £ €, the masked-password bullet, the letters of "Ctrl K", and the space;
     - *capitals* (3.0 KB): currency codes, compact suffixes, ids;
     - *letters* (4.9 KB): lowercase plus `_ @ { } ’` for identifiers and merge fields.
   - The large files stay, with those code points cut from their ranges.
   - Finding: Chrome downloads the face that covers U+0020 for any mono element, even an empty one (the sign-in password box). That is why the space lives in the figures face.
   - Effect: −24 KB to −36 KB per page.
2. **No ICU parser and no intl-messageformat in the browser** (`packages/i18n`).
   - `bundleMessages` (server-only) now sends ICU messages as their `IntlMessageFormat` parse trees. `createBundleTranslator` formats the trees with its own ~100-line formatter, which copies intl-messageformat 10.7's `formatToParts`/`format` step by step.
   - Effect: −11.8 KB on every page, sign-in included; trees add under 200 bytes per page.
   - Safety: `bundle.test.ts` formats every ICU message in every registered locale with varied values, both ways, and requires identical output (over 1,000 comparisons). A mutation (formatting `#` without the locale) makes it fail. Another test fails if a catalogue ever uses an element kind the formatter does not handle (number, date, tag).
   - Catalogue survey: only plural, select, plain arguments and `#` are used; no skeletons, ordinals, offsets or tags. No plain message changes when parsed.
3. **`next/dynamic` replaced by React's own `lazy`** (`apps/web/lib/client-lazy.tsx`: `clientLazy` matches `ssr: false`, `serverLazy` matches the default).
   - Every use was a sheet, dialog, view or flagged panel.
   - Effect: removes `next/dynamic`'s loader from every page that used it (−1.8 KB).
4. **Shared code that one import pulled in whole:**
   - the P01 `LanguageMenu` came onto every CRM and admin page through `chooseLanguage`/`BetaBadge` (now `auth/language-choice.tsx`);
   - `StillConnecting` came from the admin panel (now `admin/still-connecting.tsx`);
   - `listMyProgrammes` came from the whole accounts client (now `lib/my-programmes-api.ts`);
   - `requestRecords` came from the contacts client (now `lib/records-request.ts`);
   - the clock helpers came from `record-core` (now `lib/clock.ts`);
   - `identifierShaped` came from the search query model (now `lib/identifier-shaped.ts`);
   - `STILL_CONNECTING_MS` came from the admin resource hook (now `lib/still-connecting.ts`).

   Every old module re-exports what it lost, so no caller had to change unless it wanted the smaller import.
5. **Loaded on first press:** the account menu's items and the phone nav sheet. They open once the code has arrived, so they are never drawn empty, and focus behaviour is unchanged. A failed fetch is retried on the next press.
6. **Board:** the phone filter form (with `Select`/`TextField`) and two flag-off D-L194 placeholders (summary line, USD switch) are now in `pipeline/board-extras.tsx`, loaded on demand.
7. **Prefetches:** `prefetch={false}` on the shell rails, bottom bar, phone sheet, brand, admin nav, breadcrumbs and record links. Each shell page had been prefetching five route payloads. Main's T-0148 asked for the same.
8. **Hidden text:** the list count's screen-reader sentence ("25 loaded, and more to come") was laid out in mono, which pulled in the letters face; it is now in the sans face. It stays visually hidden.
9. **The "requests still in flight" failures** came from the shell's unread `/auth/me` refusal body. Main's T-0148 fix landed at the same time, and I took main's version.

## Visual parity

The comparison: this branch against main's own build (bc28fde), every budget page with its spec's mock, at 1440/1024/360, light and dark, with the clock fixed. Pixel diff in-browser.

- Most screens differ only by anti-aliasing on mono text.
- To isolate the cause, I re-ran with the new mono faces' requests answered by the committed Latin file.
  - Every difference then drops to at most 2/255 per channel, which is rasterisation noise.
  - So no layout, size, colour or spacing changed.
- The one rendering difference: Google's `text=` subsets are the same release (2.211), but draw about 0.9% less ink per glyph with identical advances. Google's dynamic subsetter appears to remove contour overlaps.
  - At 4× zoom it cannot be seen.
  - It is exactly how D-L44's Noto currency subset already behaves, and the brief prescribed that method.
  - To get byte-identical outlines I would need a subsetter run on the committed files. fontTools is not available here, and adding it would be a new tool dependency. Your call if you want it.
- Icon fonts are byte-identical. `pnpm ui:fetch-fonts` re-downloaded them slightly different, so I restored the committed files.

## Left out, and options if you want more margin

The board is at 295,844, 1.4% under its 299,500 pin. Remaining levers, each needing your decision:
- **Split Noto Sans Latin** into ASCII-plus-punctuation (24.6 KB) and Latin-1 letters: about −11.5 KB on every page in English. Cost: kerning is lost where accented letters meet their neighbours in fr/yo/ig text, a small visual change in those languages. I did not do it.
- **Icon faces per screen area** (about −10 to −15 KB). Ligature fonts cannot fall back per icon, so one missing glyph shows the icon's name as text. This changes D-L198's two-face ruling.
- **Message strings for lazy dialogs** still travel in the first document (about 1 KB on the board). Deferring them needs a way to fetch a bundle later.
