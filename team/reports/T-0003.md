## What changed

**Design export committed unchanged** under `docs/design/v1.1/` — all four
files, byte-for-byte. `.gitattributes` exempts `docs/design/**` from
line-ending normalisation, or git would have rewritten the HTML on checkout and
"unchanged" would have been false the moment anyone cloned on Linux.

**`packages/ui` regenerated from the import.**

- `scripts/import-design-tokens.mjs` parses the export into
  `src/tokens.colours.generated.ts`: 7 scales × 11 steps, and 53 semantic
  tokens × 2 themes.
- `src/tokens.ts` adds the hand-encoded half — type scale, spacing, radius,
  elevation, motion — each citing the export section it came from.
- `src/css.ts` emits `src/tokens.generated.css`: 345 declarations, both themes,
  the `[lang="ar"]` line-height bump, and the reduced-motion layer.
- `src/preset.ts` emits `tailwind-preset.cjs`.
- `scripts/fetch-fonts.mjs` downloads and subsets the fonts.

**Tokens page** (`apps/web/app/page.tsx`) renders every token by iterating the
source: scales with anchor markers, all 53 semantic tokens in both themes, the
contrast contract with live ratios, typefaces, type scale, spacing, radius,
elevation, motion and the chart palette.

## What was hard

**The 3.79 that would not reconcile.** See "Open questions" — this is the one
thing I could not make agree, and I would rather hand it back than quietly
adopt my own number.

**Finding what Nx was doing to the fonts task.** Not in this task, but the same
class of problem as the earlier `NODE_ENV` leak: a generator that works when run
directly and differently under the task runner. Worth remembering that
"it works when I run it" is not the same as "it works in CI".

**Google Fonts serves icon subsets from `/l/font?kit=…` with no file
extension.** My URL regex required `.woff2` and silently matched nothing, so the
subset step reported "no @font-face" rather than a download failure. A parser
that returns empty on an unexpected format is worse than one that throws.

## Open questions

1. **`border-strong on surface` measures 4.12 (light) / 4.56 (dark), not the
   3.79 the hand-off quotes.** Everything else matches to the precision given —
   the text pairs land at 5.54–11.59 against the quoted 5.5–11.6 — so the import
   itself verifies. No pairing of `border-strong` produces 3.79; nearest are 3.88
   against `--k-bg` and 3.62 against `--k-surface-sunken`. I continued rather
   than stopping because the stated requirement (≥3.0) passes with margin in
   both themes and my number is the *safer* one. **If 3.79 was measured against
   a particular background, tell me which and I will add that pair.**

2. **Icon subsetting is now a maintenance obligation.** Adding an icon to a
   screen means adding its name to `packages/ui/icon-subset.txt` and re-running
   `pnpm ui:fetch-fonts`, or it renders as a blank box. That is a footgun with a
   note attached rather than a mechanism. A CI check that scans `apps/web` for
   icon names and compares against the subset list would close it — worth a task
   once there are real screens.

3. **`docs/design/v1.1/support.js` is committed but unused.** It is the runtime
   the `.dc.html` files need to render standalone. Keeping it means the export
   can be opened and reviewed; it ships nothing.

## Risks I am aware of

- **No acceptance tests.** The hand-off said not to touch `tests/acceptance/`,
  so `tests/acceptance/design-system/tokens.acceptance.test.ts` is still
  `it.todo`. Under the D-L23 rule agreed on 2026-09-27, a task is not assigned
  until its acceptance tests exist and fail for a real reason — so this task
  technically ran ahead of its own gate. The substantive verification lives in
  `packages/ui/src/tokens.contrast.test.ts` (32 assertions, CI-blocking), which
  covers what the acceptance stubs describe. **Recommend the lead converts those
  stubs in a follow-up `lead-approved` PR** so the rule is not left with a
  precedent for being skipped.
- Token **values** are machine-extracted, so transcription risk is gone. The
  hand-encoded half (type, spacing, radius, motion) is ~30 values read off
  rendered markup and is the remaining place a human error could hide.
- Changing the CSS variable prefix to `--k-` touched every Tailwind class name
  in `apps/web`. There are only three files today; doing it later would have
  been far worse.
