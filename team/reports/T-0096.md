# T-0096 — the P28 CSV import wizard (Agent 11)

Branch `agent11/T-0096-import-screen`, built against the contract mock (T-0094's API is not merged).

## What changed
- **Flag.** `crm_import` declared identically to T-0094 (off, not production-ready); FEATURES.md regenerated. Expect a trivial rebase.
- **Route.** `/contacts/import` (`app/contacts/import/page.tsx`) calls `notFound()` unless `crm_import` and `crm_records` are on. `crmLiveNav()` lists `import`. No client module names the flag.
- **Screen** (`components/import/`): four steps with a labelled `<ol>`, `aria-current="step"`:
  - upload (programme by name, choosing a file starts the upload, pause/resume/retry/cancel);
  - mapping (one native select per header prefilled from the suggestion, reuse via `fromImportId`, a name-only checklist, restrict-only note, a field refused with 403 is never offered or sent again);
  - phones and duplicates (NG/GH/KE/ZA, the rule as a sentence);
  - run and report (polled with a 600 ms to 20 s growing interval, live counts in a status region, cancel, counts and `{row, column, code}` rows, D-L151 note, link to `/contacts?importId=`).
  - History lists past imports; an erased one has a neutral label and is never offered for reuse. Headers and filenames render as text.
- **Client** (`lib/imports-api.ts`, `lib/import-model.ts`, `lib/import-upload.ts`): Zod-parsed, same-origin, no scope argument. The uploader slices the file and PUTs it with XHR (progress), two parts at a time, no header, up to 5 tries per part, expired URLs re-issued for the parts still to go, complete once. The page never reads file bytes.
- **Contacts list (P04).** The import action is a link where `live.includes('import')`, keeping `data-action`/`data-requires-connection` (`aria-disabled` offline). `importId` is sent on the read only where the import is live, and a one-line "filtered by one import" chip clears to `/contacts` (N9).
- **i18n.** About 130 `import.*` keys in all 8 catalogues (en-XA regenerated). Passthroughs declared for proper nouns and pcm loanwords. The truncation and status labels carry no placeholder (the journeys compare the raw text).
- **Harness.** `run-e2e.mjs` serves `crm_import` on the records process and publishes `webImportUrl`; `support/stack.ts` types it.

## D-L171 review fixes
- **B1.** `leave()` and an unmount effect cancel the uploader (a no-op once it completed); history "Open" is disabled while an upload runs.
- **N1.** `resume()` resets re-issues as well as tries. A part's URL is re-issued before sending once the URLs are five minutes old. This is measured by this clock from the time of issue, not from `expiresAt`, which a phone's clock can be minutes away from.
- **N2.** A network failure on `complete` reads the job, and carries on when it is past `awaiting_upload`.
- **N3.** `complete` in flight is in the view (`completing`): Cancel and Pause are hidden and `cancel()` is a no-op.
- **N4.** `readAgain` moves to the run step for `queued` and `running` too.
- **N5.** `giveUp` reports once.
- **N6.** Polling pauses while the tab is hidden and resumes when it is shown.
- **N7.** Part URLs are `z.string().url()` plus a check: https, and never this page's origin. Plain http is admitted only to a loopback host when the page is itself on one, which is how the dev stack looks. There is no configured storage origin in the browser, because the slice may not read S3 config. The mock uses https://storage.example.
- **N8.** Uploader state-machine tests with a fake XHR: bounds, pause and resume, expiry re-issue, a single `complete`, give-up once, cancel. B1 and N1 to N3 were checked to fail with their fix removed. There are also `isPartUrl` tests.
- **N9.** The chip: its two words are bundled only where the import is live.
- **N10 to N12.** Percentages use `Intl.NumberFormat` percent. The status region says what the upload is doing, the number is in the progressbar's `aria-valuetext`. The limit says MiB. The 409 copy points to the recent imports list.
