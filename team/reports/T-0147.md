## Failures, one by one

### p06-deal.spec.ts (32 at the gate)

- **bug fixed:** 26 journeys failed on "GET /api/v1/pipelines is not an operation the deal detail uses".
  - Covers flag-on, shell, money, dates, links, locked, checks, edit ×4, reassign, requirements, unmet, move-refused,
    move-stale, timeline ×3, log ×3, the two states journeys, offline, hidden and the paint-time journey.
  - Cause: T-0135 added `usePipelineChoices()` to the deal screen only to qualify the breadcrumb's pipeline name by
    programme. That reads the pipeline list, a board read.
  - Fix: the breadcrumb now names the pipeline that `getPipeline` served.
- **bug fixed:** the move journey failed because a lost deal named no stage.
  - The lost stage is on no step of the chevron path, so `[data-field="stage"]` disappeared once the deal was lost.
  - Fix: a lost deal now shows a danger `Pill` with the stage name under the title.
- **bug fixed:** the header and 360 px journeys failed axe `color-contrast` (4.44:1).
  - The cause was the path's "Not allowed yet" sub-label: `opacity-90` on `text-text-muted` over `surface-sunken`.
  - Fix: the fade now applies only to the solid current step.
- **bug fixed:** the pseudo journey found "Oct 31" in the header ("closes Oct 31"), a date that was not inside a
  `<time>`. It is now `<time dateTime>`.
- **bug fixed:** in the same pseudo journey, the requirement prompt's "{pipeline} · {stage} rules" was marked
  `data-record-text`, but it is translated copy, so the check counted it as forged record text. The marker is
  removed (`requirement-prompt.tsx`, shared with the board).
- **skipped:** the byte budget (T-0145).

### p06-pipeline.spec.ts (12 at the gate)

- **bug fixed:** the totals, money, drag and create journeys failed because money was compact or whole-unit
  ("₦37.9M", "GH₵1,251").
  - D-P19 and D-L130 R5 rule that money is exact and never compact.
  - Fix: the column totals, the won box, the cards, the list amounts and the flagged summary line are now exact.
    `Money` and `AmountValue` lose their `shape` prop, so nobody can pass it again.
  - `lib/deal-money`'s whole and compact formatters stay, because P03's deals widget uses the whole one.
- **bug fixed:** the not-editable and locked journeys failed with "the Won column never drew".
  - An empty Won column drew no `column-empty`.
  - Fix: the green won box carries `data-testid="column-empty"` when the column has no cards.
- **bug fixed:** in the rotting journey, the chip said "15d · stale", which is not the "Going stale" / "Rotting" label.
  - The shorthand is now `aria-hidden`. A screen reader hears "Going stale 15d in stage" (`pipeline.rotting.*` plus
    `pipeline.card.inStage`).
  - The design's look is unchanged. The deal unit test's `NOT_DRAWN_HERE` gains the two ids, because the deal never
    draws the chip.
- **bug fixed:** the pseudo journey failed in three places.
  - The owner avatars put a person's name in `aria-label` and `title`. Attributes cannot be marked as record data, so
    the name is now a `data-record-text` sr-only span inside the toggle. The card avatar's `title` is gone; its
    sr-only name stays.
  - The list's stage options ("Proposal · 50%") were marked `data-record-text`. Only the bare lost-stage name keeps
    the marker now.
  - The prompt's rules line, as above.
- **bug fixed:** the 360 px journey failed axe `target-size`.
  - The card's sub-line had `-mt-1`, which put the name link and the account and contact links 22.5 px apart, centre
    to centre. Removing the margin gives 26.5 px.
- **bug fixed (found once the list journey got further):** the filter card's "17 deals" also drew in list view,
  against D-P13 / R13. It now draws on the board only.
- **spec amended:** the filters journey, three changes (T-0135, D-L193).
  - The owner select with Me and Unassigned is now only in the phone's Filters sheet. P06/01 draws only owner avatars
    on a desktop.
  - The journey now checks Me and Unassigned at 360 px through the sheet, with the same assertions, and choosing Me
    still sends `owner=me`.
  - It then checks the desktop avatars: every option is a uuid, and toggling one sends that id as well as `me`.
  - The withheld-owner check now also refuses the avatar group, which is stricter.
  - `closeInput` picks the "Choose dates" preset when the close-date control is a `<select>`.
- **spec amended:** the list journey (T-0135, D-L193). The stage cell is now P06/03's select pill, so a SELECT is read
  by its chosen option's text. The check that the lost stage is named still holds.
- **spec amended:** `openMoveSheet` (T-0135). A card has two move controls: the desktop drag handle and the phone's
  Move stage button. One is always hidden, so the helper now takes the visible one (`shown(...)`). Without this the
  360 px journey clicked the hidden handle.
- **skipped:** the byte budget (T-0145).

Each amendment has a one-line `T-0147` comment in the spec. No assertion about data, scope, contract conformance,
i18n or accessibility was relaxed.

## Notes for the lead

- I dropped the breadcrumb's programme qualifier for two pipelines with the same name. The detail cannot call
  `listPipelines`, and the breadcrumb names one pipeline rather than offering a choice. If the qualifier matters
  there, it needs a contract field: `programmeName` on Pipeline, or a lookup through `listMyProgrammes` by the
  pipeline's `programmeId`. `listMyProgrammes` is allowed, so the second option would work without a contract
  change.
- Money is exact on the board, so the totals are longer than the design's compact figures. The columns wrap them
  through `flex-wrap`. This is D-P19 against the design, and the D-L195 cut table may want a line for it.
- During the runs I added temporary axe node logging to both specs to find the failing elements. I removed it before
  committing; the committed spec has only the amendments above.
