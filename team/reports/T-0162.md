## What changed

- **`tests/e2e/support/bff-session.ts`: the TOTP claim is atomic across processes.** `nextTotp` read the step file, chose a
  step, then wrote the whole file back. That is a read-modify-write. Two Playwright processes that sign in as the same user
  (the `@p02-live` and `@bff-session` runs share this file) can choose the same step, and the second code is a replay. It also
  loses an update for a different user. The claim now runs under a lock directory (`mkdir` is atomic) with a 10 s stale
  takeover, and the file is replaced by rename. The step choice is unchanged (current step, or next, else wait), as is the
  65 s timeout. I kept the single shared file rather than one per tag, so the "last step used per user" record stays one
  fact.
- **`tests/e2e/p05-account.spec.ts`: comments only.** The `ACCOUNT_RECORD_BUDGET_BYTES` doc comment and the "WHY 245,000"
  block now say what the pin is today and that 245,000 was the first, provisional figure. No code, no literal.
