## What changed

- **`packages/db/migrations/0038_search_prefix_columns.sql`** (expand only)
  - Lines 150–691: lock order, then six `text COLLATE "C" GENERATED ALWAYS AS (...) STORED` columns named
    `<source>_search`. Each folds its own source column only, with the fold written inline (R3: no function). The four
    contact columns are added in one `ALTER TABLE`, so contact is rewritten once.
  - Lines 694–705: six B-trees `<table>_<column>_idx` on `(tenant_id, programme_id, <col> COLLATE "C", id)`. The
    trailing `id` makes `ORDER BY <col>, id LIMIT 3` come straight from the index, which keeps the result deterministic
    even across thousands of identical names (`Zqcommon`).
  - Three `DO` self-checks:
    - shape, collation, generated kind, and a `pg_depend` check that each column depends on exactly its own source;
    - all six expressions are the same fold;
    - index keys, collations and options match;
    - `proleakproof` holds for the operators served;
    - RLS is enabled and forced, and kasuwa_app can SELECT the columns.
  - The header carries the D-L65 note (a stored column rewrites the table under ACCESS EXCLUSIVE, so this is acceptable
    only while no cell is populated) and the `CREATE INDEX CONCURRENTLY` recipe as a later `0038a_…` no-transaction
    file.
  - **The fold matches JavaScript's `/\p{M}/u` byte for byte on R2's corpus** (also checked by hand on a throwaway
    postgres:16-alpine, including Greek final sigma).
    - Marks: a bracket of all 310 ranges of Unicode General Category M, generated from Node's Unicode 15.1.
    - Lower-casing: `lower(... COLLATE "und-x-icu")`, the ICU root locale, which is locale-independent.
    - Whitespace: ECMAScript's `\s`, through `translate` and then `' {2,}'`, then `btrim`.
    - There is an ASCII fast path (`octet_length = char_length`) that gives the same result. The full path measured
      about 2 s per 100k values, the fast path a fraction of that.
- **`packages/domain/core/src/search/search-fold.ts`**
  - `foldSearchText` is the query-side twin of the fold.
  - `prefixUpperBound` increments the last code point, skipping surrogates and carrying past U+10FFFF.
- **`packages/domain/core/src/search/search.repository.ts`**
  - `firstThree` (line 106): one LIMIT 3 range scan per (programme, readable field) branch, each with scalar
    `tenant_id = $t AND programme_id = $p`. The branches are combined with UNION ALL, then `GROUP BY id ORDER BY
    min(k), id LIMIT 3`, then joined back to the table by primary key under the session scope. This is provably the
    global first three by (least readable matched key, id), so a withheld field never decides the choice.
  - `searchContactsByPrefix` (181), `searchAccountsByPrefix` (300), `searchDealsByPrefix` (338).
  - `lookupContacts` (244) does one `MATERIALIZED` read for both the contact and lead groups (window ranks), which
    halved lookup latency. Phone matching uses `phones @> [{e164}]`; email uses `lower(e) = lower($1)` over
    `jsonb_array_elements_text`.
  - Every branch's programme is checked against `tx.session.programmeIds`.
- **`packages/domain/core/src/contact/phone.ts:165`** `wholePhoneE164` is stricter than `phoneSearchE164` (R10):
  - the national significant number must be 7–10 digits for NG/GH/KE/ZA and must not start with 0;
  - for any other code, at least 10 digits in total;
  - `+`, `00`, a trunk 0, or the country code typed without `+` are all accepted, as is `+234 (0) 803…`;
  - with no default country, a national form is never treated as whole;
  - the tenant's country comes from `loadTenantDefaultCountry` (R20).
- **`apps/api/src/search/`**
  - `search.controller.ts:49` holds the OpenAPI-annotated `searchRecords` and `lookupRecords`, guarded by
    `@UseGuards(KasuwaAuthGuard, SearchThrottleGuard)` with the tenant transaction interceptor, `AdminErrorFilter` and

## What was hard

- **Collation in a generated expression.** I needed a locale-independent lowering, so I used ICU `und-x-icu`. But
  `CASE` branches with two different explicit collations are refused, so the ICU branch ends in `COLLATE "C"`.
- **Cost.** My first expression made the 120k seed time out. A micro-benchmark showed that a regex with a large
  whitespace class costs as much as the marks bracket, and that `translate` is fast only on the non-ASCII path. That
  led to the ASCII fast path. Most of the remaining write cost is the maintenance of four new B-trees on contact, which
  the suite pins.
- **`@Inject(Reflector)`.** Vitest emits no decorator metadata, so a constructor-typed `Reflector` arrives undefined.
  Every request then 500s, and the RecordingLogger swallows the reason.

## What I left out, and why

- **Deal hits ignore listDeals' closed-deal window** (closed deals from the last 90 days by default, D-L88). R12 is about
  readers, and the contract says nothing about recency for search. A deal closed long ago is found by name even though
  the board hides it. Tell me if R12 means that literally.
- **A malformed JSON body to lookup is answered 400 `invalid_json` by the global body parser**, before authentication
  and the throttle. The parser is middleware and runs before guards. So a throttled or unauthenticated caller sending
  broken JSON gets 400, not 429 or 401. Fixing this means moving body parsing, which is outside this task.
- The counter is per process, like the sign-in throttle (a Redis counter once there is more than one instance).
- The folded columns are not mirrored in `packages/db/src/schema.ts`. Drizzle's `generatedAlwaysAs` would need the
  expression duplicated in TypeScript, and no test or caller needs the mirror.
