# T-0014 — Per-process environment schemas (Agent 1)

**State:** merged to `main` (#79). It answers D-P8.

**What changed:**
- **Schemas.** `apiEnv`, `workerEnv`, `realtimeEnv`, `webEnv` and `migratorEnv` now sit over one shared base. Every one of them runs `assertAuthModeIsSafe`. The `stub` default lives in the base, so an unset auth mode in production refuses to start in every process.
- **What the web process refuses.** `webEnv` refuses the DB URLs, the KMS master key, the S3 credentials, `REDIS_URL` and `OPENSEARCH_URL`. It names the offending variable and never echoes its value.
- **No more implicit `.env`.** Importing `@kasuwa/config` no longer loads `.env`. Server processes and CLIs call `loadWorkspaceEnv()` themselves; the web process imports `@kasuwa/config/web`, which loads nothing.
- **Enforcement:**
  - lint bans the main entry under `apps/web/**`;
  - `build.mjs` passes an allowlist of variables to `next build`;
  - `next.config.mjs` reads no `process.env`;
  - `instrumentation.ts` also calls `webEnv()`.
- **Lint coverage.** `no-restricted-syntax` now covers every extension and every way of reaching the environment. The blanket `*.config.*` exemption is gone.

**Evidence:**
- **Acceptance:** the lead suite passes 36/36. Its 15 scanner self-tests show the scanner can fail.
- **Security review:** passed with findings. All three majors and four minors are fixed.
- **Builder's checks:**
  - unit tests: 755 passed;
  - integration: 98 passed;
  - `pnpm build`, including a run against a deliberately polluted `.env`: passed;
  - e2e `@p01`: 29 passed.

**Hard part:** the web schema has to be plain JS (`// @ts-check`). Next imports `next.config.mjs` natively, and Node 22.16 can't import TypeScript, so `tsconfig.base.json` gains `allowJs`.

**Open:**
- The suite's `SKIP_DIRECTORIES` doesn't include `.next-self-serve`. The harness deletes that folder at teardown, but the robust fix is to add it to the suite (a lead edit).
- `apiEnv` could refuse `DATABASE_MIGRATION_URL` outright under production.
