# T-0006 — CI fails on an icon outside the font subset (Agent 11)

**State:** merged to `main` (#74).

**What changed:**
- **`tools/verify-icons.mjs`:** a plain-Node script with no new dependency and a small lexer. It scans every `.ts`/`.tsx` file under `apps/` and checks each icon reference against `packages/ui/icon-subset.txt`.
- **References it recognises:**
  - `<Icon name>` literals, including tags spread over several lines;
  - each literal arm of a ternary, including nested ones, but never a literal in the condition, and correct after `?.`;
  - the literal fallback of `??`, `||` and `&&`;
  - `k-icon` ligature text.
- **Exit codes:** 1 when a subset icon is missing, with one line per offence giving the file and line; 2 when the check cannot run; 0 otherwise.
- **Unused subset icons** print a warning but do not fail the check.
- **Also added:**
  - the root script `pnpm verify:icons`, and a blocking step in the CI `lint` job;
  - an update to `packages/ui/CLAUDE.md` invariant 5, which now points at this mechanism;
  - a fix to the stale glyph count in `components/icon.tsx`.

**Evidence:**
- **Acceptance suite** (`lead/T-0006-acceptance`): 9/9. The suite reads the committed WOFF2's GSUB ligatures directly.
- **Unit tests:** 8 new.
- **Deliberate failure:** planting `rocket_launch` and a raw `k-icon` `pets` in the real repo makes the check exit 1, with file and line for each. Reverting the plants brings it back to exit 0.

**Hard part:** deciding which `?` starts a ternary (not `?.` or `??`), and matching the `:` at the right depth when ternaries are nested.

**Open:**
- 37 subset glyphs have no reference; they are design v1.1 icons for screens not built yet. Prune or regroup them once those screens land, or the warning will be ignored.
- The T-0006 task file and the suite header still quote the old 69 glyphs / ~14 KB. Cosmetic.
