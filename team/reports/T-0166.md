# T-0166 — In-app discount approvals

## What changed

- Migration `0049_quote_approvals.sql`: `approval_rule` and `quote_approval`,
  programme-scoped, RLS enabled and forced, D-L210-style grants (no DELETE;
  column UPDATE only). Seeded A1 rule at 1500 bps / `programme_manager`.
- Drizzle mirror and `TENANT_SCOPED_TABLES` entries.
- Domain repository: request / decide / list; effective discount = max(quote,
  lines); typed `quoteApprovalRequestedEvent` stub plus `appendOutboxEvent` for
  `quote.approval_requested` (ids only, D-P29).
- Programme action `quotes.approve` (admin / team_lead / programme_manager /
  tenant-admin). Request still uses `quotes.write` (D-L211).
- API controllers, Zod closed bodies, OpenAPI three operations, flag
  `quote_approvals` (off by default; on in demo).
- Acceptance suite with rulings R1–R10; unit tests for totals-style effective
  discount and 404-before-403.

## Hard parts

- Shared `/workspace` was contended by parallel S1 agents; finished in an
  isolated worktree on `cursor/s1-a3-t0166-approvals-e3f2`.
- Notification table kinds (migration 0044) do not yet include approvals, so
  the outbox event is registered and appended, but the notifications consumer
  skips it until a later slice expands kinds. Documented; no substitute bus.

## Left out

- In-app notification row delivery / WhatsApp notify (needs notification kind).
- Admin API to upsert `approval_rule` (seed + observer for tests).
- Gating `setQuoteStatus` → `sent` on missing approval (T-0167 territory).
- Route gating on `quote_approvals` (same pattern as catalogue/quotes: flag
  registered, API always mounted).

## Open questions

- Should decide additionally require the caller's permission-set key to equal
  `approval_rule.approver_permission_set_key`, or is `quotes.approve` enough?
  This build uses the permission action; the role key is stored for UI/routing.
