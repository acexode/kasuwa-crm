## What changed

- **`packages/permissions/src/policy.ts`:** the `SET_PERMITS` allow-list gains `team_lead` and `programme_manager`, each
  holding `contact.claim_and_set_status` and nothing else. The comments on the action and the file header now name all
  three holders. `contact.write`, `contactUpdateWithinClaim` and `canUpdateContact` are unchanged, and nothing was
  reorganised, so T-0055's `account.write` addition should merge cleanly.
- **`packages/permissions/src/policy.test.ts`:**
  - "gives the %s set nothing but contact.claim_and_set_status" now runs for `agent`, `team_lead` and `programme_manager`.
  - The read-only list is now `qa_analyst`, `client_portal`, an unknown key, `constructor`, `__proto__` and NULL.
  - A new `canUpdateContact` test runs for each new set. Status alone and owner-to-self are allowed. Another owner, a
    cleared owner, `tags`, and status mixed with another field are refused. The grant does not reach another programme.
  - "keeps ... read-only, even for status alone" now covers `qa_analyst`, `client_portal` and NULL.
  - Without the policy change, 4 of these tests fail.
- **`packages/permissions/src/index.ts`:** the header comment names the three holders.
- **`docs/api/records.openapi.yaml`:** the `updateContact` paragraph is now "Agents and supervisors (D-P14, T-0051;
  D-P18, T-0077)". It names `agent`, `team_lead` and `programme_manager`, and says `qa_analyst` and `client_portal`
  remain read-only. Description text only.

No API, service, migration or dependency change. The contacts service already calls `canUpdateContact`.
