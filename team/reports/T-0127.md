4. **`feat(ui)`, D-L198** (402715d):
   - **Two icon faces.**
     - `'Material Symbols Rounded'`: all 198 glyphs, static FILL 0, 21,820 bytes.
     - `'Material Symbols Rounded Filled'`: only the 13 names in the new `packages/ui/icon-subset-filled.txt`,
       with the FILL axis, 4,944 bytes. `.k-icon-filled` switches to that family and sets `'FILL' 1`. A browser
       downloads a face only when an element uses its family. Rendered in Chromium, a page with no filled icon
       requested only the main file; a page with one requested both.
     - The 13 filled glyphs: the bell (`notifications`), `gpp_maybe` and `lock` from P26, plus the bottom-tab icons
       that can be active: `home`, `forum`, `contacts`, `person_add`, `domain`, `event_note`, `handshake`,
       `confirmation_number`, `headset_mic` and `menu`. I left out `notification_important` (P26): it isn't in the
       main subset, and the rule below requires that it be. T-0137 adds it to both lists.
   - **The blank-box risk is closed by four mechanisms:**
     - **Types.** The generated `FilledIconName` union. `<Icon>`'s props are `{ name: IconName; filled?: false } |
       { name: FilledIconName; filled: boolean }`. I compiled a scratch file to check: `<Icon name="add" filled />`
       and `<Icon name="search" filled={a} />` are type errors; `home` and `notifications` compile.
     - **Generator.** `fetch-fonts` refuses a filled name that `icon-subset.txt` lacks. When `filled={active}` is
       false the main face draws the glyph, so it must have it.
     - **verify-icons.** `tools/verify-icons.mjs` fails a filled reference outside the filled list: a bare `filled`,
       `filled={expr}` (every literal arm is checked; `{false}` is ignored), or text in a `k-icon-filled` element.
       It also fails a filled list naming a glyph the main subset lacks. The filled list file is optional, so the
       T-0006 `--root` fixtures still work. Its warning avoids the word "unused": the T-0006 suite reads any
       "unused" line naming `menu` as a false alarm.
     - **Tests.**
       - `verify-icons.test.ts` gains 7 cases.
       - `fonts.test.ts` gains 5:
         - `.k-icon` sets no weight and no synthesis rule;
         - `.k-icon-filled` uses the filled family at FILL 1;
         - the main WOFF2 has no `fvar` table and the filled one does;
         - every filled name is in the main list;
         - both generated unions equal their committed lists, so a list edited without re-fetching fails.
   - **Weight (D-L198): icons inherit the weight of their surroundings.** `.k-icon` no longer sets `font-weight`
     or `font-synthesis`. Before T-0127 it forced `font-weight: normal`. In the rendered exports the face is weight
     400 only (`document.fonts` reports `w=400`), icons inherit the 600 or 700 of the text around them, and
     Chromium synthesises bold. Ours now does exactly that; I rendered it in Chromium to confirm. The original
     defect was the type-scale size classes imposing their own weight on the icon. The `text-icon-*` utilities set
     only a size, so inheritance now reproduces the export. The comments in `tokens.ts`, `preset.ts`, `icon.tsx`
     and the fidelity test now say this.

So a page with no filled icon pays **+7,580 bytes**, and a page with one pays **+12,524**. The first version cost
+16,176 on every icon page. WOFF2 is already compressed, so transfer cost is about the file size. Today nothing
draws a filled icon, so every current page pays only +7,580 until T-0130 builds the bottom bar and bell. The other

of latin-ext (D-L44).

The filled face carries the FILL axis (0..1) rather than a static FILL 1, as ruled. A static FILL 1 face would be
3,944 bytes (about 1 KB less), but `fetch-fonts.mjs` would then no longer fetch the FILL axis, which the T-0127
acceptance suite asserts.

## What was hard

1. **The icon face claimed the naira sign.** `fonts.test.ts` (D-L44) failed once the subset passed 20 KB. Google
   sends no `unicode-range` for an `icon_names` subset, so the face claimed every code point, ₦ and ₵ included. It
   only passed before because the font was 14 KB. The browser would never actually fetch the icon font for a ₦ in
   Noto Sans text, but loosening the test would have hidden the next real D-L44 breach. So the face now states what
   it covers:
   - the characters the names are spelled with;
   - plus the space, because CSS takes an element's line metrics from the first font covering U+0020.

   Rendered in Chromium, old font against new: the icon box is in the same place and the same size (top 128, height
   20). The ligatures, the filled face and the digit names (`battery_5_bar`, `signal_cellular_4_bar`) all render.
   The filled face gets its own range the same way.
2. **The icon component ships in client bundles.** A value import from the `@kasuwa/ui` barrel would pull every
   colour plus the CSS and preset builders into them. So `icon.tsx` imports types only. `const ALIAS: typeof
   ICON_SIZE_ALIAS` still pins its mapping to the package's, value for value, at compile time. `Record<IconSize, …>`
   makes a new `ICON_SIZE` entry without a class a compile error.
3. **Finding every glyph.** The exports are bundles that unpack at runtime: the CSS isn't greppable, and frames only
   mount when scrolled into view. I scrolled each export in Playwright and read the computed `font-family` of every

## Visual changes to existing screens (all intended, all small)

- Icon weight now follows the surrounding text, as in the exports (D-L198).
  - `md`, `lg` and `xl` icons no longer take 600 or 700 from their size class.
  - An icon inside 600 or 700 text, such as a semibold button or a chip, is now synthesised bold, where it used
    to be forced to 400.
  - Net effect: icons in bold contexts get heavier and icons in regular text get lighter, matching the export.
- Dialogs, the palette and the admin drawer dim with the scrim instead of the inverse colour. In dark mode the
  page darkens instead of washing cream. In light mode the tint is the scrim's, not 60% inverse.
- Unclassed text is 14/20 instead of the browser's 16/normal.
- `text-h6` eyebrows render in caps: the MFA "alternatives" heading and the P02 programmes eyebrow.
  `text-mono` gets tabular figures in the admin screens.
- The Home and Activities nav glyphs change.
