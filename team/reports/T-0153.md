# T-0153: the osv-scanner baseline must not simply expire

Cursor, branch `feat/T-0153-osv-baseline`, from main `9a6fdcdc`. Acceptance suite:
`tests/acceptance/platform/osv-baseline.acceptance.test.ts` (merged in #217, unedited).

## What changed

**The baseline was not the whole problem.** I ran the scanner the CI job pins (osv-scanner 2.6.0, the Windows build,
checksum checked against the release's `SHA256SUMS`) on `main`'s lockfile with an empty config. It reports **56
advisories**, not the 33 in the baseline. Twenty-three were published after the baseline was written, and they are not in
`osv-scanner.toml`, so the `Dependency scan` job was already red today, apart from the 2026-10-31 expiry. Several are in
runtime code, including **Next.js 15.5.26: unauthenticated remote code execution in the Image Optimization API when SVG
files are used (CVSS 9.5, fixed in 15.5.28)**.

**Fixed by an upgrade (entries deleted or never needed)**, all same-major patch fixes:

| Package | From, to | Where | Path |
|---|---|---|---|
| next | 15.5.26, 15.5.28 | `apps/web` (`^15.5.28`) | runtime |
| sharp | 0.35.4, 0.35.5 | via next | runtime |
| multer | 2.4.0, 2.5.0 | override (`@nestjs/platform-express` pins it exactly) | runtime |
| body-parser | 2.3.0, 2.4.0 | override (express) | runtime |
| fast-uri | 3.1.8, 3.1.9 | override | runtime |
| esbuild | 0.24.2, `^0.25.12` | `apps/api`, `apps/realtime`, `apps/worker` | build |

| picomatch | 4.0.2, 4.0.7 | override (nx pins it exactly) | dev |

| source-map-js | 1.2.1, 1.2.2 | override (next's postcss) | build |

Eight root `pnpm.overrides` were added to `package.json`. They exist because a parent pins the old version exactly, and each
can be deleted when its parent moves. `GHSA-vfj7-8cjw-p6xm` (braces) was **withdrawn upstream** and no longer reported, so
its entry went too.

**Re-accepted: 39 advisories, one entry each**, to **2027-01-31**, every one with a scope, a `not reachable:` analysis and a
`fix:`. They are all in vitest 2 / vite 5 / tinypool (dev), nx 21 (dev), testcontainers' undici 5, uuid 10 and
@fastify/busboy (test), esbuild 0.18/0.21 and Next's pinned postcss 8.4.31 (build). `postcss 8.4.31` is scoped
`build-only`, as the lead asked on #217. I did **not** override it: Next pins it exactly, and a different postcss changes the
CSS pipeline that the PRD 2.13 byte budgets are measured against (the pipeline board has zero headroom).

## What is left: two runtime findings, accepted until 2026-12-31 (D-L206)

Two **runtime** findings are fixed only by a **major** upgrade. The lead accepted them as `runtime-bounded` until
2026-12-31 (suite rule 4a, merged in #220). Each entry says what caps the triggering input and names the task that ends it.

| Advisory | Package | Bounded because | Ended by |
|---|---|---|---|
| GHSA-mrhx-c7xc-m3w5 (CVSS 8.2) | zod 3.25.76 | Every JSON body is capped at 512 KiB in `apps/api/src/common/json-body-limit.ts` before zod runs. | T-0198 (zod 3 to 4) |
| GHSA-8cw4-87c7-c6xx (CVSS 6.9) | csv-parse 5.6.0 | `csv-stream.ts` never sets `columns`, and records are capped at 64 KiB. | T-0197 (csv-parse 5 to 7) |

The zod argument covers request bodies only. I did not audit other zod inputs (queue payloads, webhooks), so T-0198 is the
real fix, and the entry expires before it can become permanent.

## What was hard

- The task text said "33 findings". The real number was 56, and I only found out by running the scanner.
- `pnpm update` does not re-resolve a transitive dependency whose range is already satisfied, so five of the fixes needed
  overrides rather than a plain update.
- pnpm 9.7 rewrote one optional peer range in the lockfile (`fdir`: `picomatch ^3 || ^4` became `4.0.7`) when the
  picomatch override was applied. It is lockfile metadata only and still satisfies `^3 || ^4`.

- Any CI or scanner change.
