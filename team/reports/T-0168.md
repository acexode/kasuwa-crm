## Open questions

1. **i18n locale copy already names Paystack / Flutterwave** in
   `packages/i18n/src/locales/*.json` (`notifications.prefs.event.paymentBody`).
   The acceptance vendor scan excludes locale catalogues and treats that as
   display copy, not an integration. Should those strings move behind a
   provider-neutral phrase, or stay as product copy?
2. **`PAYMENT_PROVIDER_IDS` is exported** so T-0169 can route
   `/webhooks/<provider>/<tenantSlug>` without spelling vendor names in app
   source. Confirm the API should import the id union from this package (not
   redefine string literals).
3. **Webhook verify returns `boolean`** (false on bad signature) and only
   throws when the provider is unavailable — so unknown slug and bad signature
   can share one response (D-L205). Prefer throw-`InvalidSignatureError` instead?
4. **Sandbox credentials** for real Paystack / Flutterwave remain with
   @acexode (PLAN § External sandboxes); T-0169 builds against the fake until
   they arrive.
