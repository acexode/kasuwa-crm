# UI fidelity audit: P26 Notifications, P27 Search / command, P28 Data management

Auditor group: p26-p28. Read-only. Pixel values are measured from the 1440x900 design frames (1 px = 1 px) unless noted.
Context: several design frames were deliberately left out by earlier lead decisions (D-L133 for search, D-L128 Q6 for
import, the P26 centre's own "Absent on purpose" note). They are still listed below as differences, marked
"(overruled: D-L…)", because D-L193 now asks for exact design fidelity. The lead must decide whether those rulings stand.

---

### Shell (shared, seen on all three screens; the shell audit has the full list)
- [layout] Design: 72 px icon rail with a 10–11 px label under each icon (Home, Inbox, Contacts, Deals, Tickets, Reports, Settings), a 60 px top bar, the logo plus the word "Kasuwa" in bold. App: a 224 px sidebar with labelled rows (Home … Reports), a 64 px top bar, and "Kasuwa" in regular weight.
- [missing] Design top bar: a search field about 560 px wide on the left (`Search contacts, deals, tickets…`, with a `/` key hint), then a "Commands  Ctrl K" button, the bell, and a 36 px avatar circle with initials (AO, on accent-soft). App: an outlined "Search" button, the bell, an "EN" language menu, the low-bandwidth button and a "Sign out" text link. The design has no language menu, low-bandwidth button or Sign out in the top bar.
- [icon] Bell. Design: a borderless 20 px bell glyph. When there are unread items it sits on a 40 px primary-soft rounded square, with a red pill badge (danger bg, white 11 px bold text, for example "8" or "99+") overlapping its top-right corner. App: a 44 px bordered surface button with the badge inline next to the glyph (`bell.tsx` uses `border border-border bg-surface` and an inline `<span>`).
- [responsive] Phone. Design E2 (390): a bottom tab bar of Home / Inbox (red count badge) / Deals / Alerts (bell, with a badge, active in primary) / More. App 360: Home / Inbox / Contacts / Deals / Reports. There is no Alerts tab, and the notifications are not reachable from the tab bar.

- [missing state] A, focused with nothing typed: RECENT SEARCHES chips (with a "Clear" link) and RECENTLY VIEWED rows. Not built (overruled: D-L133, R19).
- [missing state] A2 phone-aware search: an info-soft strip ("Phone number search. 0803 456 also matches +234 803 456…") and highlighted digits. The app refuses partial numbers ("Keep typing the whole phone number") (overruled: D-L133).
- [missing state] A3 filters: the owner menu, the date menu (Any time / Last 7 days / Last 30 days, with a check), the "Owned by me" active state (primary-soft outlined button). Not built.
- [state] A4 loading. Design: an inline spinner + "Searching contacts, deals, tickets and more…", then skeleton group headers and rows with a right-aligned time stub. App: 3 skeleton rows, no text line, no group header stubs.

### Responsive / dark
- [responsive] 360: the app renders `/search` as a page. Hit titles truncate with an ellipsis ("Kano Groundnut Traders: ha…"), and the three "See all" links stack. No design phone frame exists. Under v1.1 mobile patterns, search should be a full-screen sheet from the tab bar or header and rows should wrap to 2 lines rather than truncate to about 20 characters.
- [dark] App dark: the focus ring on the input renders **yellow/amber** (`outline-focus` maps to the accent in dark), and the active "Search" header button is a dark indigo tint. The design has no dark frame. v1.1 uses the primary-tinted focus ring in both themes; confirm the `focus` token in dark (shared token issue).

Likely fix locations: `apps/web/components/search/{search-panel,command-palette,search-screen}.tsx`, `apps/web/components/crm/crm-shell.tsx` (top-bar search field, `/` shortcut, Commands button; shared), `apps/web/lib/search-api.ts`, i18n `search.*`. Highlight, status pills and the kbd component should come from `packages/ui` (shared).

## Shared/foundation issues seen

1. **App shell does not match the design shell**: a 224 px labelled sidebar vs a 72 px icon rail; no top-bar search field, "Commands Ctrl K" button or avatar; extra EN, low-bandwidth and Sign out controls in the top bar; the bell is a bordered button with an inline badge vs a borderless glyph with an overlapping red pill; the phone tab bar lacks Alerts and More. Affects every screen. `apps/web/components/crm/crm-shell.tsx`, `crm-nav.ts`.
2. **Admin "Data management" shell is missing**: the Admin badge, section title, data-residency pill, secondary nav with count pills, and the sticky bottom action bar.
3. **Page header scale**: app H1 `text-h2` (about 36 px) vs design about 28 px bold; design headers also carry a subtitle and a right-aligned secondary/primary action group.
4. **Chip style**: the app's active chip is an outlined primary-soft pill; the design's active chip is a solid primary pill with white text, and inactive chips show counts. `components/records/list-classes.ts` and `notifications/classes.ts` (CHIP_ON).
5. **Missing primitives in `packages/ui`**: toast stack, critical banner, stepper (circle + connector), stat tile, radio card, status pill (success/warning/danger/neutral), kbd chip, highlighted-match text, icon tile with type tint, sticky action bar, the v1.1 empty-state block (icon in a tinted circle + title + sentence + action).
6. **Empty states** across all three screens are bare text or an untinted glyph, not the v1.1 pattern.
7. **Dark tokens**: the `surface-sunken` vs dark page bg contrast is too low (step tiles invisible), the focus ring renders amber in dark, and disabled controls are made with opacity rather than a disabled token.
8. **Lists vs tables**: the design uses bordered table cards with a sunken header row (mapping, recent imports, duplicates, results); the app uses `<ul>` card stacks or plain rows.
9. **Many design frames were deliberately cut by earlier decisions** (D-L133, D-L128 Q6, D-L87, the centre's C2–C4). D-L193 needs a lead ruling on whether they are now required, because several need API work (counts, recent searches, partial phone match, sample values, dry-run review, confidence scores, 3-way merge).
