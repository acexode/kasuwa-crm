# Foundations audit: tokens, fonts, icons, components, app shell

Sources compared: `docs/design/v1.1/*.dc.html` (DS, Components, Patterns) and screen exports `docs/design/P*/*.html`, against `packages/ui/src/{tokens.ts,tokens.colours.generated.ts,css.ts,preset.ts,fonts.generated.css,icons.generated.ts}`, `packages/ui/icon-subset.txt`, `apps/web/components/{icon.tsx,crm/*,admin/admin-shell.tsx,auth/button-classes.ts,records/list-classes.ts}`. Frames: ds/*.png, design/P02,P03,P04,P05,P07 vs app/p02-admin, p03-home, p04-leads/contacts, p05-contact, p07-activities at 1440/1024/360, light and dark.

Overall: **the token values are right, but the app does not use the design's real vocabulary.** All 53 semantic colours (light and dark), the shadows, motion and the DS type ramp match the source exactly. The big differences come from three places. (1) The screen exports mostly use sizes that are not in the DS ramp: 13/15/11 px text, 28 px/800 page titles, 36/40 px desktop controls, 6/10/14 px radii. The app snaps all of these to the nearest token, so everything comes out bigger and looser. (2) Hand-rolled class strings stand in for the components and get their specs wrong: button and badge padding, focus style, segmented controls, table header. (3) The app shell is a different design from the one in the exports: a labelled 224 px sidebar instead of the 72 px rail, a 64 px header instead of 60 px, and the desktop header still showing at 360 px.

## 1. Design tokens: Minor gaps (values right, vocabulary missing)

Matches exactly (no action): every `--k-*` semantic token in light and dark (`tokens.colours.generated.ts` against the DS root `style=` blocks). Also exact: shadow-1/2/3 for both themes, scrim, chart-1..7, the type ramp display through mono (56/64/800/-2%, h1 40/48/700/-1%, h2 32/40, h3 24/32, h4 20/28/600, h5 18/26/600, h6 14/20/700/+6% caps, body-lg 18/28, body-md 16/24, body-sm 14/20, caption 12/16/500, mono 14/20 tnum), the spacing ramp 4..64, radius sm 4/md 8/lg 12/xl 16/full, motion 100/160/240 ms with cubic-bezier(.2,.8,.2,1), and the reduced-motion layer.

Mismatches and missing tokens, worst first:
- [type] **Screen exports use off-ramp text sizes, and the app has no token for them.** Counts across P01–P28: 13px ×813 (meta, toolbar buttons, chips, helper text, lh 19/18/20), 15px ×242 (button labels and input values, lh 22), 11px ×231 (overlines, kbd, bottom-nav labels), 10px (rail labels), 17px, 22px, 26px and 28px (page titles). The app uses only `text-body-sm` 14 (×548), `text-caption` 12 and `text-body-md` 16, so labels end up 1 px larger and meta text 1 px smaller or larger throughout. Add steps such as `label` 15/22/600, `meta` 13/19, `overline` 11/16/700/.06em caps, `title` 28/36/800/-.01em, `title-sm` 26/34/800 and `card-title` 16/24/700. Fix: `packages/ui/src/tokens.ts` TYPE_SCALE. Shared.
- [type] **Page title.** The design h1 is 28/36/**800**/-.01em on lists (P04, P07) and 26/34/800 on records and admin (×12). The app's h1 is `text-h2` 32/40/**700** (15 uses) or h3/h1, so titles are larger and lighter. Shared (needs a token).
- [type] Card and section titles in the design are 16/700 (h2 ×21). The app uses `text-h4` 20/600 or `text-h5` 18/600 ("Setup health", "Details", "Activity").
- [border] **Radius 10px (×254), 6px (×144) and 14px are missing.** The design uses 10 for menus/popovers, toasts, table wrappers, rail items, mobile primary buttons and sheets; 6 for menu rows, segmented items and chips; 14 for dialogs. The app has only 4/8/12/16, so popovers become 12 (`POPOVER rounded-lg`), menu rows 8 and dialogs 12. Add `radius-6`, `radius-10`, `radius-14`. Fix: `tokens.ts` RADIUS. Shared.
- [spacing] Gaps of 6px (×585, the single most common), 10px (×275) and 14px (×80) are not tokens. Tailwind's default `gap-1.5/2.5/3.5` still exist because the preset only extends, but the app never uses them (gap-2 ×429, gap-1 ×246), so groups come out 8 instead of 6 and 12 instead of 10. Either add 1.5/2.5/3.5 to SPACING or tell builders the defaults are allowed. Shared.
- [layout] **No control-height tokens.** The design uses 36 px for compact desktop controls ("36px compact size is desktop-only and keeps a 44px hit area": toolbar chips, Columns, segmented items, Clear all), 40 px for header search, menu rows and table header, 44 px for form controls and standard buttons, and 48/52 px for mobile icon and primary buttons. The app has `min-h-touch` 44 on 158 elements and nothing else, which is why every desktop toolbar is taller than the design (Status/Owner chips 44 against 36). Add `control-sm 36`, `control-md 40`, `control 44`, `control-lg 48`, `control-xl 52`. Shared.
- [state] **Focus ring is the wrong shape.** Design buttons, checkboxes and radios use `box-shadow: 0 0 0 2px var(--k-surface), 0 0 0 4px var(--k-focus)` (a 2 px surface gap, then a 2 px ring). Inputs and selects in focus use `border:1px solid var(--k-primary)` plus `box-shadow: 0 0 0 3px var(--k-primary-soft-strong)`. Focused chips use `0 0 0 2px var(--k-focus)`. The app applies `outline-2 outline-offset-2 outline-focus` everywhere (57 copies, transparent gap), and fields get the same outline instead of the primary border plus soft halo. Add a `ring-focus` utility and a `field-focus` utility to the preset. Shared.
- [type] FONT_WEIGHTS lacks 500 and 700, although the caption step uses 500 and the design uses 700 ×624 and 500 ×19. Cosmetic: Tailwind's `font-bold` works. Add the weights for completeness.
- [layout] No shell dimension tokens: header 60, rail 72, rail item 56×52, admin nav 272, bottom bar 64, mobile header 56. The app hard-codes h-16 (64), w-56 (224) and w-72 (288) instead.
- [colour] The table header shadow `0 2px 4px rgba(0,0,0,.06)` and the toggle knob `0 1px 2px rgba(0,0,0,.3)` are literals in the design and have no tokens. Minor.

## 2. Fonts and icons: Minor gaps in fonts, Major gaps in icons

Fonts: **Match.** The design loads Noto Sans 400–800, Noto Sans Arabic 400/600/700 and JetBrains Mono 400/600. `fonts.generated.css` self-hosts variable files for Noto Sans 400–800, Arabic 400–700 and Mono 400–600, plus a ₦/₵ currency subset. The family stacks are identical. There is no body default for size or line height: `<body>` in `apps/web/app/layout.tsx` sets only `font-sans`, so unclassed text renders at the browser's 16 px with `normal` line height, while the design body is 14 px with line height ≥1.4. Add `text-body-sm` (or a base layer) on body.
- [type] Phone numbers, money, IDs and counts are JetBrains Mono in the design (lists, timeline, rows-per-page, "Showing 1–25 of 64"). In app list rows, phones render in Noto Sans (p04-leads, p04-contacts, p05 details). `font-mono` is used in 40 places, but not on those columns. Screen-local, but recurs.

Icons: **Major gaps.**
- [icon] The style matches: Material Symbols **Rounded**, opsz 24, wght 400, FILL 0, GRAD 0, the same axes as the design's `@24,400,0,0` link.
- [icon] **Icon sizes are snapped to type steps.** `icon.tsx` offers sm 18 (body-lg), md 20 (h4), lg 24 (h3) and xl 32 (h2). The design uses 20 (×293), 18 (×271), **22 (×123: rail, header buttons, icon buttons, bottom nav)**, 16 (×107: table sort, chip close, badge icons), 15 (×63: consent pills), 14 (×53), 24, 17 and 28. As a result every 22 px rail, header and icon-button glyph renders at 18 or 24, and 14–16 px inline icons render at 18. Give the icon its own size scale (14/16/18/20/22/24/28/32) rather than borrowing type steps. Fix: `apps/web/components/icon.tsx`, `tokens.ts`. Shared.
- [icon] **Probable faux-bold glyphs.** Using `text-h4`/`text-h3`/`text-h2` as the icon size also applies `font-weight: var(--k-font-weight-h4)` (600 or 700). Utilities load after `.k-icon{font-weight:normal}`, so they win. The subset has only a static weight 400, so md/lg/xl icons get synthetic bold. Set `font-weight:400 !important` (or the variation setting) on `.k-icon`, or stop using type classes for icon size.
- [icon] **The FILL axis is not shipped.** The subset is fetched at `FILL@0` only (`packages/ui/scripts/fetch-fonts.mjs:324`). The design uses `font-variation-settings:'FILL' 1` for the active bottom-tab icon and the bell (P26) and for the `gpp_maybe` security banner. Fetch `FILL 0..1`.
- [icon] **Glyphs missing from the subset** (the design uses them, `icon-subset.txt` lacks them), limited to built screens: P01 business_center, content_copy, gavel, mark_email_read, share · P02 apartment, design_services, undo · P03 dashboard_customize, push_pin, signal_cellular_4_bar, trending_up · P04 battery_5_bar, bookmark, bookmark_add, check_box, import_export, layers, link, swipe_left, upload, view_column, work · P05 account_balance, account_tree, dashboard, receipt_long, thumb_down, thumb_up, trending_up · P06 add_circle, approval, menu_book, move_up, thumb_down, view_kanban · P07 add_circle, content_copy, event_available, event_busy, flag, link, photo_camera, schedule_send, snooze · P10 alt_route, assignment_turned_in, badge, call_end, event_available, groups, publish, published_with_changes, radio_button_checked, refresh, sync_alt · P18 add_link, arrow_upward, assignment_ind, dashboard, design_services, hub, list, mobile_off, request_quote, rule, schema, science, swap_horiz, workspaces · P26 bedtime, flashlight_on, gpp_maybe, photo_camera, settings · P27 badge · P28 account_tree, badge, bookmark_add, join, link, notifications_active, replay, science, signal_disconnected, undo · v1.1 sticky_note_2 and signal glyphs. The design has 204 distinct names; the subset has 121.
- [icon] Nav icon substitutions: app Home uses `space_dashboard`, design `home`; app Accounts uses `domain`, P04 design `apartment` (P05/P06 use `domain`); app Activities uses `task_alt`, design `event_note` (P07). Fix: `apps/web/components/crm/crm-nav.ts`.

## 3. Components: Major gaps

There is no component library. `packages/ui` exports only tokens. Controls are class strings: `apps/web/components/auth/button-classes.ts` (PRIMARY/SECONDARY/QUIET_BUTTON, FIELD, LINK), `components/records/list-classes.ts` (CHIP, MENU_ROW, POPOVER), plus ad-hoc strings in every screen. That is why the specs drift.

- [spacing][type] **Buttons.** Design: height 44, padding `0 12px`, radius 8, **15/600**, gap 6, icon 22. Hover: primary-hover; secondary bg surface-sunken; ghost bg **primary-soft**. Active: primary-active, translateY(1px); secondary bg border; ghost primary-soft-strong. Disabled: **bg disabled-bg, text disabled-text** (secondary keeps a border-colour edge), loading keeps width. App: `px-4` (16), `text-body-md` 16/600 (sometimes `font-bold`), ghost hover surface-sunken, no active or pressed state, disabled via `disabled:opacity-60` (×70). The result is wider, larger buttons with washed-out disabled states (see "New contact" in p04-contacts-1440-dark). Compact 36 px desktop buttons do not exist.
- [border][state] **Text field and select.** Design: 44 h, padding 0 12, 1 px border-strong, radius 8, value 15 px, label **14/600** with a 6 px gap. Hover border text-2. Focus border primary plus 3 px primary-soft-strong halo. Error **2 px danger border plus trailing `error` icon**, helper 13 px danger-text. Disabled: disabled-bg, border, disabled-text. App FIELD: 16 px text, outline focus, 1 px `border-danger` error with no icon, no hover state. Select menu: design panel radius 10, padding 4, shadow-2, rows 40 h, radius 6, 14 px, selected primary-soft with 600 weight and a `check`. App MENU_ROW: 44 h, radius 8, panel `rounded-lg p-2` (12 radius, 8 padding).
- [spacing] **Badges and status pills.** Design: 12/700, **padding 3px 10px**, radius 999. Square tags (VIP, Hot, P1) are radius 4. Count badge is 20 h, min-width 20, 11/700. Consent pills are 12/600, padding 3/9, with a 15 px icon. App: `px-2` and **no vertical padding**, a mix of `rounded-sm` and `rounded-full`, some `uppercase` (`rounded-sm bg-surface-sunken px-2 text-caption font-bold uppercase`). Pills look cramped and flat in p04-leads ("Contacted", "Qualified").
- [layout] **Filter chips.** Design: 36 h, padding `0 8px 0 10px`, radius 999, 13/600, 18 px leading icon, 1 px border-strong (primary when active). App CHIP: 44 h, px-4, 14/600, border `border` (lighter than border-strong), no leading icons.
- [state] **Segmented control and view switcher.** Design: track surface-sunken, padding 3, radius 8, gap 2–4. Items 36 h (30 for rows per page), radius 6, 13/600. **Active item: surface background plus shadow-1**, text colour unchanged. App (Table/Board, p04): white bordered container with a **primary-soft, primary-text** active item.
- [state] **Tabs.** Design record and activity tabs are underline tabs: 14/600, active primary-text with a 2 px primary underline (P05 composer tabs, P07 My tasks/Calendar/Check-in). App p07 uses pill buttons ("My tasks" primary-soft pill with border).
- [layout][type] **Table.** Design: wrapper border, radius 10. Header row sticky, **40 h**, bg surface-sunken, **12/700 uppercase, letter-spacing .04em, colour text-2**, vertical cell dividers, 0 2px 4px shadow. Rows **52 h comfortable / 36 h dense**, with a density toggle, a 44 px checkbox column (18 px box, radius 4), 14 px cells, and a footer (56 h) holding "Showing" in mono, a rows-per-page segmented control and pager buttons. App leads/contacts: header is `text-caption` sentence case, colour text-muted, no tracking (only 7 of 10 tables add `uppercase`), no dividers. Rows ≈ 57–61 h (p-3 plus 32 avatar). No density toggle, no checkbox column, no footer or pager.
- [shape] **Avatars.** Design 44 (record and presence) and 32 (rows), initials 14/700 on primary-soft-strong/accent-soft/info-soft/success-soft by hash, with presence dots of 14 px plus a 2 px surface ring. App: 32 px everywhere in lists, always primary-soft, with no presence variant. The header avatar is missing (see shell).
- [radius][spacing] **Menus and popovers.** Design: radius 10, padding 4–6, surface or surface-raised, border, shadow-2, overline 11/700 caps section labels. App POPOVER: radius 12, p-2.
- [radius][layout] **Modals, drawers and sheets.** Design (Components and DS 08): dialog radius 14, padding 22, max-width 360 for confirms and 440–640 for forms, max-height 85vh, fixed header and footer with a divider and shadow that react to scroll. Destructive dialogs get a 40 px danger-soft icon disc. Drawer 400 px (max 90vw). On mobile the modal is full-screen, with a 48 px close button and 52 px full-width primary. App dialogs: radius 12, padding 16/24, `bg-surface` in some places and `bg-surface-raised` in others (a visible difference in dark mode: #1E1A17 against #29241F), no sticky header or footer.
- [dark][colour] **The scrim is wrong in dark mode.** Six overlays use `bg-inverse opacity-60` instead of `bg-scrim`: crm-shell palette, admin-shell drawer, admin/dialog, activities/activity-dialog, pipeline/pipeline-dialog, search/command-palette. In dark mode `--k-inverse` is #F3F0EB, so the page **lightens to a cream wash** behind dialogs. The design uses `--k-scrim` rgba(0,0,0,.62). Four other places already use `bg-scrim` correctly.
- [layout] **Toasts.** Design: radius 10, padding `10px 8px 10px 14px`, 14 px, 20 px status icon, shadow-2. Success toast on inverse with an underlined Undo; error and info toasts on surface-raised with a border; warning on warning-soft with shadow-1. Placement: bottom-centre on mobile, bottom-right on desktop. Auto-hide 6 s; errors persist. App: an inverse full-width bottom bar (`fixed inset-x-0 bottom-0 … bg-inverse p-4`, ×4) and one `rounded-lg bg-inverse p-3` card. There is no shared toast with these variants or placement.
- [missing] **Empty states, skeletons, offline.** The DS and Patterns specify skeletons that match the final layout (sunken blocks, 1.4 s shimmer, "Still loading on a slow connection…" after 8 s) and empty states with an icon disc, a title, a body and one primary action. The app's leads empty state uses a 64 px `rounded-lg` square icon tile and a `text-h3` (24) title. The design uses a circular disc and a 16–18 px title (check per screen). Toggle (44×26 track, 20 px knob), checkbox and radio (20 px, 2 px border-strong, radius 4) are not shared components. Each screen styles its own.

## Shared/foundation issues seen
1. Missing token steps: text 11/13/15/16-bold/26/28-800; radius 6/10/14; control heights 36/40/48/52; icon sizes 14/16/22/28. Builders round to the nearest step, so everything is bigger and looser. (`packages/ui/src/tokens.ts`, `preset.ts`)
2. No component layer: Button, Field, Select, Chip, Badge, Segmented, Tabs, Table, Avatar, Menu, Dialog/Drawer/Sheet, Toast, EmptyState, Skeleton should be built once in `packages/ui` (or `apps/web/components/ui`) to the Components page spec, replacing `button-classes.ts`, `list-classes.ts` and the inline strings.
3. Focus style: build a 2 px surface + 2 px focus box-shadow ring for controls and a primary border + 3 px soft halo for fields, replacing the global outline.
4. Disabled style: replace `disabled:opacity-60` (×70) with disabled-bg/disabled-text tokens.
5. Scrim: replace `bg-inverse opacity-60` (6 files) with `bg-scrim`. This is a visible dark-mode bug.
6. Shell rebuild: 60 px header with inline search + Ctrl K + avatar; 72 px sunken icon rail at ≥768 px; per-screen 56 px app bar and pill bottom nav (Home/Inbox/current/Deals/More) at 360; admin header with tenant switcher and help; 272 px admin nav, full height, drawer at ≤1024.
7. Icons: add ~90 missing glyphs, ship the FILL axis, decouple icon size from type steps, and stop type classes from making icon glyphs faux-bold.
8. Mono for phone, money, ID and count columns; body default 14 px.

**Effort: XL.** The tokens are a small change (S). The component library is L. The shell rebuild is M–L. Re-skinning every screen onto the components afterwards is the bulk of the work.
