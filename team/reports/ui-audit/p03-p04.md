## P03 Home dashboards — `/` (signed-in) — Not built

Frames compared: all 31 P03 frames -> `p03-home-{1440,1024,360}-{light,dark}.png`. The app shots are the **Leads list**, not a Home.

### Evidence it is not built
- `apps/web/app/page.tsx` is the sign-in page. With a session cookie it calls `redirect(await landingPath())`.
- `apps/web/lib/server/landing.ts`: `landingPath()` returns the first `CRM_NAV` entry whose `href` is non-null and whose flag is live, else `/admin`. The comment cites D-L172: "ADR-0019 leaves the landing page unruled".
- `apps/web/components/crm/crm-nav.ts`: `{ id: 'home', ..., href: null }`. `null` means "NOT BUILT", so the entry renders as a disabled non-link. Inbox is the same. So `/` lands on `/leads`.
- No `app/home` route and no home or dashboard components exist. `en.json` has no home or dashboard keys apart from `records.nav.home`.
- Scheduling: there is **no task file**. `grep P03 team/tasks` finds nothing. `T-0031-admin-home.md` is the admin console home API, not P03. P03 appears only in plans:
  - `team/ROADMAP.md:83`: "Home dashboards (P03) | grow as modules arrive".
  - `team/HANDOFF.md:152`: item 5, "Home dashboards (P03, exported). Build the agent and SME variants first."
  - `team/DESIGN-QUEUE.md:64`.
  - `team/DECISIONS.md:1168`, listed as part of the "Next slice".
  - It was planned and never turned into a task.

### What building it would involve
1. A task plus an acceptance suite (D-L23), and a ruling that `/` (or `/home`) is the landing page. This supersedes the D-L172 "first live nav entry" rule in `lib/server/landing.ts`.
2. A `crm_home` flag. Then set `CRM_NAV` home `href: '/home'`.
3. A widget framework: a 12-column grid, a `WidgetCard` (header, overflow menu, empty, loading, lite variants) and a per-user layout persistence API with a new table. That needs a migration, RLS and the `TENANT_SCOPED_TABLES` entry. Plus the Customise mode and the Add-widget drawer/sheet.
4. Shared header controls: a period segmented control and a currency toggle (USD needs FX, which D-L69 says returns 501 until M05).
5. Widget data APIs. Most depend on modules not yet built:
   - Tickets/SLA/CSAT: M-tickets.
   - Queue sizes, AHT, QA, adherence, schedule: telephony and WFM adapters.
   - Approvals: not built.
   - Quota/forecast: no quota model.
   - Next best actions and AI usage: M17.
   - Cost to serve and profitability: M05 billing.
   - Buildable now from existing data: Today's agenda (activities), Deals needing attention (pipeline), Pipeline by stage, WhatsApp awaiting reply (only if channels exist; otherwise the empty state).
6. Role to default-layout mapping from the permission set.

**Effort: XL** (L for the framework plus sales rep and manager on existing data; the rest is gated on other modules).

## Shared/foundation issues seen
1. **App shell diverges from the design everywhere.** 224px labelled sidebar vs a 72px icon rail; 64 vs 60px top bar; search button vs a wide Ctrl-K search field; language menu and "Sign out" text vs an avatar; the mobile bottom bar has the wrong item set and no active pill; there is no mobile title bar (hamburger, title, subtitle, bookmark, ⋮). This affects every CRM screen.
2. **Page title scale**: `text-h2` (32/700) is used where the design uses 28/800.
3. **Chip geometry**: 44px full pills with no icons vs the design's ~40px icon-led chips.
4. **Mono numerals for phones and money, plus network badges**: the design uses mono for phone numbers, counts and amounts. The app uses the proportional font.
5. **Programme scope copy and pattern**: a generic "Your programmes" pill vs the design's programme switcher pill plus a specific scope line (or nothing for non-BPO tenants).
6. **Disabled-not-built controls at 60% opacity** look broken. The design draws them at full fidelity. A decision is needed: hide them or draw them faithfully.
7. **Design vs decision conflicts** need lead rulings before fixing: totals and pagination (D-P13), Map (D-L69), bulk actions (T-0057), score and Health (M17), the Home landing page (D-L172).
8. **Landing**: there is no Home, so `/` lands on Leads.
