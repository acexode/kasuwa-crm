## Decisions I made that you may want to overrule

1. **Cadence 45 s** (C1 allows 30–60). Back-off after n failures is `45 s × 2^n`, capped at 300 s, with no jitter. A 429 waits `max(Retry-After, cadence)`, capped at 15 min against a nonsense header, and does not grow the failure count. A wake cannot cut a 429's wait short.
2. **Wake coalescing is 5 s**, so ten focus events are one read. A wake while failing may read even inside the failure back-off (it only ever follows a real show or focus).
3. **Writes are drawn only when answered.** There is no optimistic UI, which the throttle and lost-answer journeys require.
4. **A lost write is resent with the same body**, at +1 s and +3 s (inside the 10 s the suite allows). If it still fails, the screen shows a translated failure and asks for a count re-read.
5. **A 429 on a write is not resent by itself.** The reader's click is the resend. The list retries by itself, with the same cursor.
6. **Mark-all is bounded by the newest id the server served**, including an item of a kind this client ignores. The mock demands it, and a hidden newer unread item would otherwise be left behind.
7. **`current="notifications"`** is passed to the CRM shell. It matches no nav item, so nothing is highlighted. That is correct, since there is no nav entry for the centre.

## Round three (D-L182): the bell costs nothing where its flag is off

**Cause.** Three things made the shared bundles heavier, and the biggest was not the bell's own code. (1) The bell was a static import of the shell. (2) The new  route did not use the shared button class () that every other route loads. Next's `commons` chunk is the modules every route uses, so one route not using one made it leave `commons` and land in every list page's own chunks: about 1.4 KB on /contacts, /accounts and /leads. The centre now uses `SECONDARY_BUTTON`, with a comment saying why. (3) Utility classes the bell and centre added to the one global stylesheet, and a Retry-After read I had put in the shared `requestRecords`.

**Fix.**
- The bell is a `React.lazy` import in both shells (not `next/dynamic`, whose runtime would itself cost every page), rendered only where the server-side flag says so. It is a chunk of its own, with the store, poller, count and strings.
- `lib/records-api.ts` is back to main, byte for byte. The notifications client has its own small `request`, so a bare 429's `Retry-After` costs no other page anything. It imports no value from the record lists either.
- The notification classes and the 8 error codes are copies, not imports of `records/list-classes` or `RecordsErrorCode`.
- The dropdown is a bottom sheet built only from classes the stylesheet already had (the old popover's 19 new rules are gone), and the stylesheet is now unchanged.
- The admin pages read their two flags with `Promise.all`. A second sequential `await` delayed Next's metadata past the first flush, which made it stream and added a 1 KB runtime script to `/admin` and `/admin/custom-fields`.
- **N7, honestly.** To hold /contacts/import to the 200-byte rule, `use-import-job` treats `too_many_requests` as keep-polling on the schedule's own growing wait (up to 20 s). It does **not** read the server's `Retry-After`, because carrying it through the shared client costs every records page about 80 bytes. D-L179 asked for the wait honoured; this meets the rule but not that clause, so say if you want it back and which budget pays.
