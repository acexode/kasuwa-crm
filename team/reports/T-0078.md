## What changed

### The build (b884da7)
- `apps/api/src/admin/audit/audit-field-security.ts`: judges every audit change for the READER, per event, in the event's programme, at read time. `AUDIT_VALUE_POLICY` is a `Record<AuditObjectType, …>`: configuration objects pass unchanged, contact/account/activity are field-secured, and a new object type does not compile until it is classified. An unknown object type has every value redacted.
- `audit.service.ts`: `listAuditEvents` applies it after the page and cursor are cut, so paging, cursors and filters are identical whatever the matrix says (F8).
- `Cache-Control: no-store` on all four audit handlers; `admin.openapi.yaml` describes the redaction and the header.

### Hardening after the security review (54c4d39)
1. **No load oracle.** `objectsToLoad` no longer looks at the stored changes: the contact matrix is loaded whenever the page holds a contact event with a programme. Whether it is loaded (timing, or a load failure) no longer depends on whether a stored change carried a value.
2. **A per-object VALUE allow-list, intersected with the matrix.** Contact: D-L72's value fields (`CONTACT_AUDIT_VALUE_FIELDS`, each mapped wire name -> `field_def.api_name`). Account and activity: none, until a decision says otherwise (D-L78). A stored value on a name part, phone, email, owner, account, subject or body is redacted even for a reader at `read`/`edit`. Account and activity events therefore never need their matrix loaded.
3. **`no-store` before the guard.** `NoStoreMiddleware`, applied by `AdminAuditModule.configure` to every `AuditController` route, runs before `KasuwaAuthGuard`, so the guard's 401 and its scope-header 400 carry the header too (`@Header` only reaches answers that go through the handler). `admin.openapi.yaml` gains a `components.headers.NoStore` and `AuditValidationFailed`/`AuditNotAuthenticated`/`AuditNotFound`/`AuditNotPermitted` responses (the same bodies and examples as the shared ones, plus the header), used by the four audit operations. Response examples are unchanged against the previous spec, so the generated admin mock does not move.
4. **No test seam in production.** `listAuditEvents(tx, query)` takes no loader; it always judges against `loaderFor(tx)`, the session's own matrix. The export-worker comment on `createAuditExport` now says the worker must re-resolve the requester's scope AND field-security matrix, open a tenant transaction as the re-resolved requester, and pass every event through `applyAuditFieldSecurity(entries, loaderFor(tx))` inside it.

### After the re-review (d7b474e)
5. **`applyAuditFieldSecurity(entries, tx)`** takes the tenant transaction and reads that session's own matrix through `loaderFor(tx)`; it no longer accepts a loader, so the future export worker cannot pass a forged or cached matrix. The pure `redactForReader` and `objectsToLoad` stay for unit tests. The export-worker comment says the worker passes the transaction it opened as the re-resolved requester.
6. **`tenant` events are fully redacted (pinned, conscious fail-closed).** `provision-tenant.ts` writes `objectType: 'tenant'` with values (slug, region, ids), and `tenant` is not in `AUDIT_OBJECT_TYPES`, so it falls under the unknown-object rule. It is deliberately NOT added to the list here; the lead records it as a follow-up.
