# T-0130 — App shell (CRM and admin) to the designs

Branch `agent11/T-0130-app-shell`. Visual verification only (D-L201); no suites run, no tests written.
Compared against P03/01, P04/01, P04/02, P04/06 (dark), P02/01, P02/02 and P18/01–02 at 1440, 1024 and
360, light and dark. Screenshots: `.artifacts/parity/app/p04-leads-*`, `p02-admin-*`, `p02-programmes-*`,
plus states `p02-drawer-1024-light`, `p02-tenant-1440-light`, `p04-avatar-menu-1440-dark`,
`p04-more-sheet-360-light`, `p27-palette-1440-light`.

## What matches

**CRM shell, 1440 and 1024** (`components/crm/crm-shell.tsx`, `crm-nav.ts`)
- 60px top bar, padding 0 12 0 16, gap 8.
- 32px logo tile (17/800 accent on primary) and the 16/700 wordmark.
- Inline search field: `basis-shell-search` (420), ms-5, 40px, radius 8, sunken, 20px icon, the 14px
  muted placeholder and the T-0128 `Kbd` "Ctrl K". It is still a link to `/search`: a plain press opens
  the existing palette, a modified press opens a new tab.
- Spacer, then the labelled Lite mode switch (44px, 0 10, 13/600, `network_check` 20; accent when on, as
  P03/24), a 44px ghost bell, and the 36px accent-soft avatar with 13/700 initials.
- The avatar opens a menu: the user's name, the language list (endonyms, Beta badges, the help link) and
  Sign out. The language button and the Sign out link are gone from the bar.
- 72px sunken rail with a right border, padding 12/0, gap 4. Items are 56×52, radius 10, a 22px icon over
  a 10/600 label; active is primary-soft/primary-text, inactive is text-2. It stays at 1024.
- Items: Home, Inbox, Leads, Contacts, Accounts, Activities (`event_note`), Deals, Tickets, Calls, Reports.

**CRM shell, 360**
- No global top bar. The one `<header>` becomes a 56px app bar: a 48px menu button (or a back link), the
  title (18/700) and subtitle, and 48px trailing actions.
- The `appBar` prop is the slot screens fill. Until a screen fills it, the bar shows the screen's nav
  title, a search icon (where `crm_search` is on) and the bell.
- 64px bottom bar: Home, Inbox, the current object (Contacts when the screen has none), Deals and More.
  Each item is a 52×28 radius-14 pill behind a 22px icon. The active pill is primary-soft with the filled
  face, and labels are 11px (700 active, 500 inactive). Content padding clears the bar.
- More and the menu button open one bottom sheet: every nav entry, then lite mode, the language list and
  Sign out.
- FAB slot: `fab` prop plus `CrmFab` (56px, 0 20 0 16, radius 16, primary, 15/700, `add` 24). It sits
  80px above the bottom and 16px from the end edge.

**Admin shell** (`components/admin/admin-shell.tsx`)
- 60px bar, padding 0 16, gap 12.
- Logo and wordmark, then the "Admin" pill (primary-soft, 12/700, radius 6).
- Tenant switcher: bordered 36px, `apartment` 18, the tenant name from the admin summary, `expand_more`.
  It shows from 1280 up, as P02 does; P02 drops it at 1024. Its menu lists the current workspace only.
- Residency pill: "Data stored in: **South Africa (af-south-1)**" from one translated sentence, with the
  region in bold. Icon only below `md`, keeping its accessible name.
- A 44px help button, the bell, and the avatar menu. The avatar menu also holds lite mode, because the
  admin bar has no lite switch in P02.
- Settings nav: 272px and full height (a stretched column with a sticky inner list), padding 12/10/32,
  gap 2.
  - A 40px "Find a setting" field with a 20px search icon.
  - Group rows are 40px, 14/600, 20px icons, the warning dot and a muted chevron. Groups with no items
    have no chevron. An open group holding the current page is primary-text.
  - Item rows are 36px, padded 40 at the start, 14/500 text-2; the current item is primary-soft 700.
- Below 1280 the nav is a drawer behind the hamburger, so at 1024 the content gets the full width
  (P02/02). Drawer behaviour and test ids are unchanged.
- P18 slots: `section` (a divider plus a 15/700 title with a primary icon), `breadcrumb` (the 44px surface
  strip) with `AdminBreadcrumb` (13/600, primary links, muted `chevron_right`), and `nav={false}`. Not
  wired into the studio yet: that is T-0142's screen.

**Bell** (`notifications/bell.tsx`, trigger only): 44px ghost, 22px glyph in text-2. While the dropdown is
open it is primary-soft with the filled icon (P26). The count shows in a danger pill ringed in surface at
the glyph's shoulder. The `notifications-badge` text contract is kept.

## What does not match yet

- **Accounts icon:** `domain`, not P04's `apartment`. P05/P06 use `domain`, and only `domain` is in the
  filled face that the bottom bar needs.
- **Presence pill ("Available", P04/06 dark):** not built. There is no availability API; it is a
  D-L194 candidate.
- **Phone title duplication:** screens still draw their own h1 under the default app bar. Each screen task
  should pass `appBar` (title, subtitle, actions) and drop its phone h1.
- **Admin pill height:** 20px instead of 22. No token gives 22 with 12px text; it would need a token.
- **Admin help:** a disabled 44px button ("Not available yet"). There is no help destination.
- **Admin bell:** 44px, against 40 in P02. It is shared with the CRM bar, where the design draws 44.
- **Bell badge:** 20px with a 2px ring, against the design's 18px plus ring. No 18px token.
- **Home:** drawn disabled until T-0132 gives it an `href`. It is not flagged; T-0132 owns its flag.
- **Arabic RTL:** `?locale=ar` did not switch the CRM pages on my dev server, so RTL was not proven
  visually. Everything uses logical properties, and the back arrow and breadcrumb chevron mirror.

## Flags added (D-L194)

`crm_inbox`, `crm_tickets`, `crm_calls`, `crm_reports` in `@kasuwa/feature-flags`. All default off and
not production-ready; all are added to `tools/demo.mjs`.

On, the rail and phone sheet draw the entry disabled (not a link, announced "Not available yet"). Off, the
entry is not drawn. `crmLiveNav()` reports each as `placeholder:<id>`.

## i18n

New keys, in every locale and inserted after `records.nav.reports` to stay clear of other builders' tail
appends:
- `records.nav.calls`, `records.nav.more`;
- `shell.search.placeholder`, `shell.menu.open`, `shell.menu.close`, `shell.back`;
- `admin.shell.tenant`, `admin.shell.tenant.current`.

Three are declared pcm passthroughs, with reasons. The kbd reuses `design.components.kbd.search`.
`pnpm --filter @kasuwa/i18n validate` is clean.
