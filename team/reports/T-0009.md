## What changed

**The gate (the actual deliverable)**

- `packages/i18n/src/completeness.ts` — computes, per locale, whether it is
  *complete* (every id present, nothing silently left in English, every plural
  category CLDR requires, no invented or dropped placeholders, parseable ICU)
  and whether it is *attested* (a named human signed it off, or it is the
  source language). `deriveSupportedLocales()` is the intersection of the
  design's menu list with readiness.
- `packages/i18n/src/index.ts` — `SUPPORTED_LOCALES` is now
  `deriveSupportedLocales()`, not a literal. Adding a language to the menu is
  no longer an edit to this file. Also adds `translate`, `textDirection`,
  `localeLabel`, `REGISTERED_LOCALES` and `localeReadinessReport()`.
- `packages/i18n/src/plurals.ts` — `requiredPluralCategories(locale)`, read
  from CLDR via `Intl.PluralRules` rather than kept in a table. A hand table is
  a second copy of CLDR that drifts from it, and the drift is invisible for
  exactly the same reason the original bug is. If the runtime's CLDR does not
  know the language it returns `['other']` rather than English's `one`/`other`
  under another language's name.
- `packages/i18n/src/catalogues.ts` — registration, endonyms, and
  `parseReview()`. A `"status": "reviewed"` with no named reviewer **throws at
  load**: an unsigned sign-off is not a sign-off.

**Catalogues** — `fr ha ig sw pcm yo ar`, 34 keys each, plus
`<locale>.passthrough.json` (declared English matches) and
`<locale>.review.json` (attestation + the reason for each passthrough, since
JSON takes no comments).

**Tooling** — `pnpm i18n:validate`, with `-- --probe '<message>'`.
Wired into the CI `build` job. It fails on a menu language with a *structural*
defect; a language that is merely unreviewed is held back, not failed, because
that is the designed steady state rather than a broken build.

**Docs** — `packages/i18n/CLAUDE.md` rewritten with the invariants and an
"adding a language" procedure.

## The judgement the task asked for

### Genuinely finished: `en`, `en-NG`

Both are the source language, written in this repository rather than produced
for us. There is nothing to attest beyond that, and I have said so in their
`review.json` under `"status": "source"`.

### Not finished: `fr`, `ha`, `ig`, `sw`, `pcm`, `yo`

All six are **structurally** complete — `pnpm i18n:validate` reports no defects
in any of them. Not one is finished, and structural completeness is exactly the
kind of evidence that makes that easy to forget.

I wrote those translations. I am not a speaker of any of the six, and D-P1's
own reasoning says why that is not good enough: machine translation of a CRM
interface "is frequently wrong in ways a reviewer who does not speak the
language cannot detect, and the strings in question are the ones a user acts
on". Today's catalogue is 34 developer-facing strings about design tokens, so
the blast radius is small — but the gate is being built now precisely so that
it is trustworthy when the catalogue is 3,400 strings and contains "Delete
permanently" and "This cannot be undone".

Per-language, what specifically worries me:

- **`yo`** — I wrote the tone marks. Yorùbá tone marks change meaning, not just
  pronunciation. An unreviewed Yorùbá catalogue is not "slightly rough", it is
  potentially wrong. This is the one I would least want shipped.
- **`pcm`** — D-P1 flags that Nigerian Pidgin has no agreed written standard.
  I picked a house style (`di`, `dem`, `wey`, `no dey`) by drafting, which is
  exactly the thing D-P1 says must be *chosen* by a named reviewer rather than
  assumed by a drafter. Pidgin is also the heaviest passthrough user —
  eleven technical headings borrowed from English as-is. Every one of those is
  declared with a reason, but a reviewer should challenge them: a menu that is
  40% English is arguably a menu that fails the rule at the top of this task
  even though it passes the check.
- **`ha`, `ig`** — my best effort at register and orthography. Outsource Global
  has native speakers; this is a staff-time ask, not a money ask.
- **`fr`, `sw`** — D-P1 assigns these to paid professional translation. My
  French is the most plausible-looking of the six, which makes it the most
  dangerous: it reads fluently enough that a reviewer might not read it
  closely.

### Present but never offered: `ar`

Registered so RTL has real strings to render against, deliberately absent from

## What was hard

**The placeholder regex is load-bearing in a way nothing says.** Both the
acceptance suite and my validator find placeholders with `/\{\s*(\w+)/g`, which
also matches the first word of a plural *branch*. So `{count, plural, one
{mataki #}}` reads as an unknown placeholder `{mataki}`. The fix is to put `#`
first in every branch — `{# mataki}` — which happens to be fine in all six
languages, but it is a real constraint on translations that no file states. It
bit me in four catalogues at once. Worth a line in the task template.

**CLDR knows `pcm`.** I had assumed Pidgin would fall through to English and
planned to override it to `['other']`. `Intl.PluralRules('pcm')` resolves to
`pcm` with `['one','other']`, so the catalogue must carry both — and since the
counted nouns are the English ones, both plural messages come out byte-identical
to English and need passthrough declarations. Deriving from CLDR instead of
from my assumption caught this; a hand table would have shipped my assumption.

**Deciding what "derived" means.** The test forbids a literal
`SUPPORTED_LOCALES`, but *something* has to say which languages the menu is
for, or a finished-and-attested Arabic would drift onto a menu it was never
designed into. I settled on two separate facts: `DESIGN_MENU_LOCALES` (a
transcription of `docs/design/P01/v1.0`, i.e. what the design asks for) and
readiness (what is true). Offering is the intersection. Being in the design
list is not enough, which is the drift the task names; being ready is not
enough either, which keeps Arabic off.

## Lead review pass (2026-09-27)

The builder's core judgement was right and is upheld: it **refused to make the
central assertion pass** because doing so would have meant dropping the
attestation half of the gate — the dishonest seven-language menu the task
exists to prevent, with the test suite's approval on it. A builder must never
edit an acceptance test, and this one did not.

Four changes on review.

### 1. The placeholder regex was wrong, and it was my bug

`placeholderNames()` used `/\{\s*(\w+)/g`, which also matches the first word of
a plural **branch body**: `{count, plural, one {a single step} …}` reports a
placeholder named `a`.

I wrote that regex in the acceptance test; the builder reasonably mirrored it in
the implementation. **So it survived review twice, in two files, because the
check and the thing it checked shared an author.** That is the correlated blind
spot Agent 12 exists to break, appearing in the least dramatic place imaginable.

It hid because `\w` is `[A-Za-z0-9_]`: Arabic's `zero {لا خطوات}` sailed through
while Latin-script catalogues had to be written so every branch led with `#`.
That constraint was invisible, undocumented, and wrong for any language that
does not put the number first — it would have silently shaped every catalogue
written from here on.

Replaced with an AST walk. Four regression tests added; verified they **fail**
against the old regex and pass against the fix.

### 2. `@kasuwa/config` could route around the gate — removed

The builder flagged a second `SUPPORTED_LOCALES` environment variable in
`@kasuwa/config`. Confirmed real and unread by anything, but it could have
widened the offered set past what the gate considers finished: a dishonest menu
reachable by editing a deployment variable and touching no code.

Two sources of truth for one fact, one of which can lie silently. **Removed
rather than reconciled** (D-L27), along with `DEFAULT_LOCALE`, which had the
same shape. A deployment may narrow the offered set through a feature flag; it
may never widen it. An acceptance assertion now enforces its absence.

### 3. The central assertion was amended, and the amendment is recorded

It asserted "all seven offered". That was written **before** @acexode answered
D-P1, and the answer supersedes its premise.

The replacement is **stricter, not looser**:

- offered must equal the ready set **exactly** — not a superset, not a subset
- nothing reaches the menu on structural completeness alone
- every **held-back** menu language must be structurally complete, so "awaiting
  review" cannot become a comfortable label on unfinished work

That last one is the property the original was reaching for, expressed in a way
that is true today.

### 4. Not adopted

The builder's suggestion to leave the file `.pending` was declined. The work is
finished; the suite belongs in the blocking gate where a regression fails CI.
