## Decisions worth knowing about

**The health score is not computed in the browser.** The contract says so and
the screen obeys it: it renders `score`, `pointsAvailable` and one row per named
check. A second implementation of the rules in the client is a second one to
keep in step, and the one that drifts is the one the admin is reading.

**Three nulls are rendered as "not known", never as a value.** `presence`
(telephony adapter, ADR-0003), `needed` (WFM forecast, same ADR) and
`usageCount90d` (interaction aggregate). The e2e suite has a scenario
(`unknownSources`) that forces all three at once, because the spec's examples
show the normal case and the abnormal one is what matters here. A supervisor
told an agent is offline when the truth is that we lost the feed makes a
staffing decision on a fiction; an admin told a busy disposition is unused
deletes it.

**Out of scope is `404`.** `getProgramme` renders `admin.error.not_found` and
there is no `403` branch on that screen. Switching is on `error.code`, never on
`message`.

**The FLS write was left alone** (D-P9). Nothing was built for `P02/D` at all,
so there is no programme selector to have added.

**"Still connecting" is built and tested.** `useResource` goes skeleton →
message → offer of low-bandwidth mode at four seconds, the P01 number kept. The
e2e suite reaches it with a deterministic 6 s mock delay rather than by waiting
and hoping.

**SLA durations are parsed, not typed as seconds.** The wire is integer seconds
(the contract is explicit) and the design's field is free text, so the client
owns the translation. The accepted unit words come from `Intl.NumberFormat`'s
CLDR data for the active locale, plus the ASCII English forms always — an alias
table of `sec / min / h` written by an English developer silently rejects a
French or Hausa user's input. An unparseable value marks the field invalid and
disables Save; it never guesses, because guessing that "2" means minutes turns a
2-second contractual target into one nobody chose.

**Unsaved changes are four things, not one.** Amber marks per field, a bar that
counts and names them, Save *and* Discard, and a guard that asks before leaving.
The guard is a capture-phase click listener plus `beforeunload`, because the App
Router has no navigation-guard API — `useRouter` exposes no before-route event
and `popstate` fires after the URL has already changed. It is off when nothing
is dirty: a confirmation people see when they have changed nothing is one they
learn to click through.

## i18n

269 new ids under `admin.*`, added to **all nine catalogues**. That is forced by
`completeness.test.ts`, which asserts fr/ha/ig/sw/pcm/yo stay structurally
complete; English-only would have made six languages incomplete in one commit.

- Plural categories are per locale from CLDR. Arabic carries all six on the
  three plural messages; French carries `many`. Only three messages use plurals
  at all — the rest were phrased to avoid them, which is cheaper than getting
  six categories right in seven languages.
- Keys that came out identical to English are declared in each locale's
  `passthrough.json` with a reason in `review.json`. Pidgin has 111, which is
  what an English-lexified language honestly looks like.
- **None of the seven becomes offered.** They are machine drafts of exactly the
  status the existing ones carry — `awaiting-review`, no named reviewer — and
  D-P1 keeps them off the menu. Treat the admin translations as no more
  trustworthy than the auth ones already in the repository, and less
  trustworthy for Hausa, Igbo, Yoruba and Swahili, where I am not a competent
  reviewer. Arabic was written because RTL has to be exercised against real
  strings; `/admin?locale=ar` renders the whole console right-to-left and there
  is an e2e assertion on it.

## The mock

`tests/e2e/support/admin-mock.generated.ts` is generated from the spec by
`tests/e2e/scripts/generate-admin-mock.mjs` (41 operations), as
`docs/api/README.md` requires. `admin-mock.ts` holds only the state the contract
describes in prose: per-user alert dismissal, deletion and deactivation, and
`q`/`status` filtering.

**One thing I deliberately duplicated.** `generate-admin-mock.mjs` is a near-copy
of `generate-auth-mock.mjs` rather than a shared module, because merging them
would regenerate `auth-mock.generated.ts` — which is committed and diffed for
drift — as a side effect of adding a second spec. Factoring the two together is
a small task of its own and I did not want it inside this diff.

### The low-bandwidth numbers, measured

Against a production build (`pnpm --filter @kasuwa/web build`, then
`next start`), cold cache, admin reads stubbed so the figure is the shell's
weight and not the API's latency:

| Route | Transferred | FCP unthrottled | FCP at 256 kbps / 300 ms |
|---|---|---|---|
| `/admin` | 266,632 B | 120 ms | **1,972 ms** |
| `/admin/programmes/{id}?tab=sla` | 274,158 B | 128 ms | **1,920 ms** |

PRD 2.13 caps the critical path at 300 KB gzipped, so admin home has about 13%
of headroom and the programme screen about 11%. The console is heavier than the
sign-in page (256,948 B) by roughly 10–17 KB, which is the settings menu and the
admin client island. Under two seconds to a usable console on the network the
PRD commits to holds because strings are resolved on the server and only the
ones a screen asked for cross the wire.

## Two bugs this build hit, both worth knowing about

Both were found by the e2e run and both now fail in the fast suite instead.

**A screen asked for a message id it had not bundled.** `AdminShell` rendered
`t.t('admin.prog.unknown')` for the residency badge and that id was not in
`ADMIN_SHELL_MESSAGE_IDS`, so every admin route threw on first render. `tsc` is
happy — the id is a valid `MessageId` — and lint has no opinion about which
bundle a screen asked for. It presented as twenty unrelated-looking e2e
failures. `components/admin/message-ids.test.ts` now reads the component source
and fails in milliseconds on the same mistake, including for a new component
added without a bundle declared. **This is worth generalising to
`components/auth/` too; I did not, to keep the diff to P02.**

**A server component imported a function from a `'use client'` module.**
`page.tsx` called `isProgrammeTab()` to read `?tab=`, and a client module's
exports are client *references*: the call failed at request time with a 500,
not at compile time. It is the same trap `components/auth/message-ids.ts`
carries a warning about, and the warning did not stop me. The guard moved to
`components/admin/programme-tabs.ts`, which has no directive.

Both are the same shape of defect — a mistake that typechecks, lints and only
shows up in a browser — and both cost a fourteen-minute e2e run to locate. A
cheap lint rule for the second one (a server file importing a value, not a
type, from a `'use client'` module) would be worth somebody's afternoon.

## Open questions for the lead

1. **Nothing owns the setup-health rules.** T-0021 raised it; the screen now
   renders them, which makes the gap visible rather than theoretical. Same for
   the alert aggregation (six modules, no owner) and M23 usage, which has no
   task at all.
2. **Every write on these screens is `501`.** "New programme", "Add agents",
   "Add disposition", "Pause", "Archive", "Edit" and "Client portal" are
   rendered as visibly disabled rather than as buttons that fail when pressed.
   If you would rather they were absent entirely, say so — I took visible-but-
   disabled as the more honest of the two, but it is a product call.
3. **Menu entries that point at nothing are not links.** 41 of the 42 settings
   items have no screen, so they render as non-interactive text. Same rule as
   the language menu: a menu entry that navigates to a 404 is worse than one
   that is visibly not ready.
4. **`pnpm test:unit` had a transient failure** in
   `packages/auth-crypto/src/password.test.ts` — `RangeError: Invalid typed
   array length: 19923968` from hash-wasm — while several agents were building
   at once and 1.1 GB of 15.8 GB was free. It passed on every run afterwards and
   is unrelated to this branch, but a memory-sensitive test in the *fast* suite
   will keep doing this on a shared machine, and it reads as a real failure.
5. **`generate-admin-mock.mjs` duplicates `generate-auth-mock.mjs`.** Factoring
   them together means regenerating `auth-mock.generated.ts`, which is committed
   and diffed for drift, as a side effect of adding a second spec. Small task,
   worth doing before a third spec arrives.
