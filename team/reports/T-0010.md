from `lead/T-0010-acceptance`. Nothing under `tests/acceptance/` was edited.

## The numbers

| | bytes |
|---|---|
| Measured sign-in critical path, gzipped transfer | **240,015** |
| Same resources, decoded | 612,207 |
| `SIGN_IN_CRITICAL_PATH_BUDGET_BYTES` | **250,000** (9,985 headroom, under 10 KiB) |
| PRD 2.13 ceiling | 300,000 (50,000 above the budget) |

Measured against `next build` + `next start`, cold cache, at 256 kbps / 300 ms.
The figure was identical, to the byte, on six runs. 16 requests, all counted:
the document (6,261 B), eleven scripts (142,799 B), one stylesheet (8,617 B)
and three fonts (82,338 B: Noto Sans latin, JetBrains Mono latin, the Material
Symbols subset). FCP came in at 2,028–2,276 ms.

The critical path is **not** over the ceiling, so nothing goes to
`DECISIONS.md`.

## What changed

- `tests/e2e/support/critical-path.ts`: the interface from the acceptance
  header (`CRITICAL_PATH_RULE`, `measureCriticalPath`,
  `SIGN_IN_CRITICAL_PATH_BUDGET_BYTES`, `assertCriticalPathWithinBudget`). It
  also holds the CDP capture (`captureCriticalPath`) and `servedBuildId`, which
  reads the build id from the served document's App Router flight payload
  (`"b":"<id>"`) rather than from disk. Playwright is imported for types only.
- `tests/e2e/byte-budget.spec.ts`: the `@byte-budget` spec. It writes
  `.artifacts/critical-path.json` before asserting, so a red run still shows
  which request grew. It also guards against a vacuous pass: the document and at
  least one script must be counted.
- `tests/e2e/scripts/run-e2e.mjs`: every non-`@over-budget` run does
  `node build.mjs` (apps/web's NODE_ENV-pinning wrapper) and then `next start`.
  `next dev` is gone. CI and local runs go through this one path.
  `NEXT_PUBLIC_API_URL` is passed at build time as well, because `next build`
  resolves the `/api/v1` rewrite into the routes manifest. That means the API
  port is picked before the build. A stale `critical-path.json` is deleted at
  the start of each run.
- P01 and P02 byte budgets: the `test.fixme` lines are gone, so seven tests are
  live. Each one passed against the production build, by these margins:

  | route | measured | budget |
  |---|---|---|
  | `/` (P01/1) | 240,015 | 270,336 |
  | `/admin` | 219,637 | 224,000 |
  | `/admin/programmes` | 217,168 | 222,000 |
  | `/admin/roles` | 219,491 | 224,000 |
  | `/admin/field-security` | 252,266 | 257,000 |
  | `/admin/audit` | 252,106 | 257,000 |
  | `…?tab=scripts` | 261,820 | 266,000 |

  The P02 numbers match the P02 builder's recorded production figures to
  within a few hundred bytes, so these passes are honest.
- Comments updated in the README, `stack.ts`, `metrics.ts` and the two specs.
- `.github/workflows/ci.yml`: **not changed.** The harness now builds the app
  itself, so the e2e job (and the isolation job, which runs the harness) gets a
  production build with no workflow edit. That also keeps me out of Agent 13's
  way.

## Findings (not fixed — reported to owners)

1. **`next build` inside the harness crashed once and hung once.** The first
   version ran the build alongside the Testcontainers start. The build worker
   died once with a V8 fatal (exit 2147483651) and hung in `compile` once. Run
   on its own, the same build passed every time (~36 s warm). I can only show
   correlation, not cause; the machine was heavily loaded and Docker was failing
   at the time. The harness now builds first and then starts the container.
2. **Font fallback to Google (`packages/ui/src/fonts.generated.css`).** Every
   `@font-face` lists `https://fonts.gstatic.com/...` as a second `src`. If a
   self-hosted woff2 fails to load, the browser fetches from Google. That is a
   third origin on the 300 ms link, and it sends user IPs to a third party
   (NDPA). Owner: `packages/ui` / Agent 11.
3. **The P01 budget is slacker than its own comment says.** It was pinned at
   270,336 against a recorded 256,948. The page now weighs 240,015, which is
   12.6% headroom. The new critical-path budget covers the same route more
   tightly, but the P01 number should be re-pinned by its owner. I did not
   change it.
4. **P01/P02 budget tests overwrite the harness's own metrics.** They call
   `recordProfileMetrics('default', …)`, so after a full run
   `harness-metrics.json`'s `default` entry holds whichever route ran last.
   This is harmless to the acceptance suite, which reruns only `@harness`, but
   the artefact is misleading. Owner: the spec authors (Agent 11).
5. **Live data does not exercise the lazy-chunk exclusion.** The sign-in page
   requests nothing after first paint, so `excluded` is empty in the real
   capture. The exclusion is proven only by the acceptance fixture. This is
   legitimate today, but it is not coverage of a real lazy chunk.
6. **Fonts are requested only 40–220 ms before FCP.** They are discovered at
   layout, which comes before paint, so they should always count. If timing
   ever flipped them past the cutoff, the figure would *drop* by up to 82 KB
   and the check would pass, not flap red. Worth knowing if the number suddenly
   falls.
7. **Cost.** `next build` also runs ESLint and `tsc` (~36 s warm, longer cold).
   The isolation suite now builds twice (the `@harness` run and the
   `@byte-budget` run), and CI's `build` job builds a third time. I did not
   de-duplicate this; it is a caching question for Agent 13's work.
