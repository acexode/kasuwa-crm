## What was hard

- **The id-rotation bypass (review M1).** It was a real hole I had missed. With NO ACTION, the guard
  watches `parent_account_id`, but a statement can re-point children without writing that column.
  - I had kept NO ACTION because I believed 0019's reasoning, that RESTRICT breaks offboarding by cascade
    order. The reviewer showed RESTRICT does not break it. My test covers tenant offboarding and a
    multi-row parent-and-child delete.
- **A test-ordering trap.** A one-statement id swap trips the primary key (23505) unless the row losing
  the id is visited first. The depth-7 test therefore creates the subtree first: ids are UUIDv7, so the
  subtree root sorts, and is stored, before the leaf.

## What I left out, and why

- **The Accounts API** (T-0055).
- **D-L67 in the database.** T-0055's repository checks it.

- **No CONCURRENTLY `0027` file.** D-L74 allows plain indexes in 0026.
- **The phones CHECK is not split into NOT VALID plus VALIDATE.** Inside one transaction that would hold
  the same ACCESS EXCLUSIVE, and the empty-list short-circuit already makes validation cheap. The header
  says so.
- **0019's `contact_account_same_programme_fk` exposure.** That is the lead's D-L76 follow-up. The
  immutable `account.id` does close the account side of it for `kasuwa_app`.
- **No `sort=updatedAt` index** (review m5). Nothing serves `sort=updatedAt` today:
  - `account_keyset_idx` serves `createdAt`;
  - the new `account_name_keyset_idx` serves `name`.

  T-0055 decides whether `updatedAt` sorting is offered and, if so, adds its index.

## Risks I am aware of

- **Tenancy.**
  - Both FKs are composite.
  - Moving a single linked row across programmes is refused. Moving a whole hierarchy is not (see Open
    question 3).
  - The guard runs under the caller's RLS. The lock is per programme, so it creates no timing channel
    across programmes.
- **Lock impact at volume** (D-L65). About 14 s of ACCESS EXCLUSIVE at 2M rows on this host, mostly the
  name index. Acceptable only while no populated cell exists.
- **Error text.** Neither guard's messages carry ids or names. A CHECK failure's `detail` can carry the
  name and phones; D-L74 already tells T-0055 never to log or return it.
- **Deploy window** (as 0025). The proof now names the remedy.
