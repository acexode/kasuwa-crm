## The flag

- `self_serve_signup` is the first entry in `FLAGS` and names its owner. Its default is OFF.
  The unit test that kept `FLAGS` empty now pins the list.
- **It gates the route.** Each of the three pages calls `notFound()` on the
  server before rendering, so typing the path gets a real HTTP 404 and nothing
  ships. With the flag off, the "Create an account" link on `P01/1` is hidden too.
- **It is switched on per process.** The switch is `KASUWA_FEATURE_FLAGS_ON`
  (comma-separated), read through a new **`@kasuwa/config/feature-flags`**
  entry point. That entry point is separate from `@kasuwa/config`'s index on
  purpose: the index loads the workspace `.env` and demands a `DATABASE_URL`
  that the web process must not have. An unknown flag name stops the boot.
- **Nothing the browser sends can turn it on.** An e2e test sends headers,
  cookies and query strings that ask for the flag, and still gets 404.
- **The e2e run starts two web servers** (`scripts/run-e2e.mjs`):
  - `webUrl` has `KASUWA_FEATURE_FLAGS_ON` forced empty, so a developer's
    shell cannot leak a flag into the default run.
  - `webSelfServeUrl` has the flag named.

  Two `next dev` processes sharing `.next` corrupt each other, so the second
  one gets its own `distDir` and a generated tsconfig. Both are gitignored, set
  through `KASUWA_WEB_DIST_DIR` / `KASUWA_WEB_TSCONFIG` in `next.config.mjs`.
  Next rewrites the tracked `next-env.d.ts` for whichever server starts last.
  The runner restores it once both servers are up, and again at teardown.
- **The `/onboarding` steps are never flag-gated** (D-P2 point 4). An e2e test
  tagged `@self-serve-off` covers each of them.

## Deviations from the board, and why

- **`P01/3` has a Password field.** `SignUpRequest.password` is required
  (minimum 12). This is the same kind of forced deviation as the Workspace
  field on `P01/1`.
- **No carrier badge ("MTN")** beside the number.
  - It would need a prefix table, and Nigerian number portability makes that
    table wrong.
  - The contract has no field for it.
  - The help text no longer claims the country was "picked from your
    location". Nothing detects location, so the default is simply Nigeria.
- **No new icons.** The board uses `mark_email_read`, `gavel`,
  `business_center`, `table`, `link`, `sync`, `content_copy` and `share`.
  - I used existing subset glyphs instead: `mail`, `info`, `domain`,
    `description`, `chat` and `hourglass_top`.
  - Copy and share are dropped with the invite link (below).
  - Why: the icon font loads on every route, sign-in included, and the brief
    was to keep sign-in's weight unchanged. If the designer wants the exact
    glyphs, it costs a few hundred bytes on every page.
- **Things not wired yet say so instead of pretending.** Each of these shows a
  "not ready yet" status in the right words:
  - Meta embedded sign-up (M8)
  - CRM connectors (M20/M21)
  - WhatsApp invite links (no endpoint)

  The board's made-up `kasuwa.africa/j/...` link is not shown, because someone
  might share it.
- **CSV only.** Reading `.xlsx` needs a parser, which would be a new
  dependency. The help line asks people to save Excel files as CSV. I dropped
  "Uploads resume if your connection drops" and "Download our template",
  because neither exists.
- **`P01/6`:**
  - The board's "Ọja Foods is ready" becomes "Your workspace is ready". No API
    gives the name yet.
  - "Go to Inbox" becomes "Go to Home" (`/admin`). There is no inbox route.
  - "Take a 2-minute tour" is omitted. There is no tour.
  - A typed invite reads "People on the invite list", never "sent".
- **"Terms" and "Privacy notice" are plain text,** not links. Neither page
  exists.
- **`P01/6` keeps "This list stays on your Home page".** That is false until
  T-0018 builds server-side state. I kept the design's copy, but it is a
  promise the product does not keep yet. Someone should decide whether to
  soften it until then.

| `/` sign-in, flag on (link shown) | — | 240,401 | +383 | ~1.90 s |
| `/verify` (`P01/2`) | 239,034 | 239,326 | +292 | ~1.96 s |
| `/sign-up` (`P01/3`) | — | 241,157 | | ~1.90 s |

Every new route is under the PRD 2.13 ceiling (307,200 bytes).

is accounted for:

| Source | Bytes | Why |
|---|---|---|
| Global Tailwind stylesheet | +230 | The new screens' utility classes. Tailwind emits one stylesheet for the app, so new classes cost every route. Avoiding this needs per-route CSS, which is a design-system change. |
| HTML / RSC payload | +64 | The flag value passed to the page. |
| `P01/1` page chunk | +43 | The flag-gated link. |

I removed a fourth contributor: +160 bytes from sign-up Zod schemas I had
added to `lib/auth-api.ts`. They now live in `lib/sign-up-api.ts`.

### A design-system finding, bigger than this task

The first measurement of `/onboarding` was **399,576 bytes, over the
ceiling.** The cause:

- The naira and cedi signs (U+20A6, U+20B5) sit in the Latin Extended
  `unicode-range`.
- Noto Sans's file for that range is **168 KB**.
- So rendering one ₦ in the body face downloads more than half the page
  budget.

Fix on this screen: currency symbols and the preview amount are set in
JetBrains Mono. Its Latin Extended file covers the same range in 11.6 KB, and
the board already sets figures in mono. Result: 243,325 bytes.

**Every future screen that shows a naira amount in Noto Sans will pay the
168 KB.** This should be fixed in `packages/ui`, not screen by screen. Two
options:

- add a tiny currency-glyph subset font, or
- narrow the Noto Sans latin-ext `unicode-range` and serve the currency signs
  from a small file.

Yorùbá and Igbo text needs Latin Extended anyway (ẹ, ọ, ṣ), so this will be
paid in those languages regardless. That is another reason to subset it
properly.
