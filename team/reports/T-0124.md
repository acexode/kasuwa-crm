## What changed

**The rule, in one place** (`packages/domain/core/src/contact/contact-fields.ts`):
`DISPLAY_NAME_PARTS`, `displayNameReadable(access, programmeId)`,
`programmesReadingDisplayName`, `displayNameWithheldAnywhere`,
`summaryDisplayName` (name or `null`) and `notEditableContactUpdateFields`.
Every read path below calls these. Nothing restates the rule. Search's
`nameAccess` now calls `displayNameReadable` instead of composing the two parts
itself.

**Whole records: omitted, and listed first in `withheldFields`.** This is
`toContactWire` (contact-wire.ts). It covers listContacts, getContact,
createContact, updateContact, listLeads, listAccountContacts, convertContact's
`contact`, and getContactMergePreview's `survivor` and `merged`.

**Summaries send `null`:**
- deals: `toDealWire` and the board's `toDealWire`, judged in the deal's or the
  pipeline's programme, so getDeal, listDeals, getPipelineBoard, createDeal,
  updateDeal and moveDeal are covered;
- activities: `toMyActivityWire`, so listMyActivities and listCalendar are
  covered;
- duplicates and merges: listDuplicates, and `toContactMergeWire` for
  createContactMerge, listContactMerges and undoContactMerge.

**Sort.** `displayName` and `-displayName` are out of `CONTACT_SORTS`, so
`sort=displayName` is 400 for every caller. listAccountContacts now defaults to
`-createdAt`. `SORT_SPECS` no longer knows `display_name`.

**`q`.** `ContactSearch` gains `displayNameProgrammeIds` and loses its phone
match, and `searchClause` matches `display_name` only in those programmes,
row by row. Both filtering layers stay: the scope predicate, then a per-field
programme list.

**R21.** There is a new `apps/api/src/common/name-query.ts` with
`looksLikeIdentifier`, which moved here from search.schemas.ts and is
re-exported there, plus `nameQuery()`. listContacts and listLeads `q` use it, so
an identifier is `400 validation_failed` with `identifier_in_url` at `q`. The
issue carries a fixed reason and message, never the value. Nothing logs.

**Writes:**
- updateContact: `displayName` from a caller it is withheld from is
  `403 field_not_editable`.
- merges: `standardLevel('displayName')` is `none` when the name is withheld.
  So it is never a default, choosing it is `403` at `choices.displayName`,
  `planMerge` keeps the survivor's name, and undo locks it.

**Timeline.** `visibleChangeFields` omits a `field_changed` item naming
`displayName` when the name is withheld.

**Scripting (amended I13):**
- `script-run.service.ts` `fieldReader`: the old `field !== 'displayName'`
  skip is gone. A branch on a withheld name returns `withheld`, so the run stops
  with `field_withheld`.
- `scripts.repository.ts` `contactFieldFacts`: the hard-coded `withheld: false`
  is gone. `displayName` is withheld when either part's fact is, and it carries
  `standIn: true`.
- `script-publish.ts` `fieldCodes`: a VARIABLE on a `standIn` field is not
  refused. A branch still is, and so is any other withheld variable.
- Web run screen: a withheld `{contact.displayName}` and the header's contact
  name render `scripting.run.withheldName`, with `data-variable-placeholder`
  and `data-withheld-name`. `RunContact.displayName` is optional, and `fill`
  gained a `withheldName` segment.

**i18n.** `scripting.run.withheldName` is in en, fr, pcm, ha, yo, ig, sw and ar.

**OpenAPI:**
- records.openapi.yaml:
  - Contact: `displayName` is no longer required, and the rule text is written
    out.
  - DealContactSummary and ActivityContactSummary are `[string, null]`, and the
    duplicate's text is aligned.
  - The sort enums and the listAccountContacts default are updated.
  - Both `q`s have the R21 `not` pattern and their text is updated.
  - The listContactTimeline text is updated.
  - listContacts has a withheld-name example row.
- scripting.openapi.yaml:
  - the publishScript, advanceScriptRun and getScriptRunScript text;
  - `x-kasuwa-withheld-name-message-id: scripting.run.withheldName` on
    getScriptRunScript.

**Unit tests.** New or extended tests cover the rule (contact-fields.test),
the wire, deals, the board, activities, the timeline, merges, publish,
name-query and the run model. Each fails without its change.

## Decisions the rulings did not cover

1. **The listAccountContacts default is `-createdAt`.** It matches the other two
   lists. The rulings left the key to the lead (I5).
2. **The phone match is removed from the repository** rather than kept
   unreachable. The boundary refuses a 6+ digit `q`, and a shorter one is never
   a whole E.164 number.
3. **A read-only name part leaves `displayName` editable.** Only a withheld name
   is refused on update and merge. I11 leaves this open.
4. **createContact and imports are unchanged** (I11, unpinned). A caller missing
   a name part can still create. The response then omits the name it just sent.
5. **`standIn` is displayName-only.** Every other withheld variable is still
   `branch_on_withheld_field` at publish.
6. **The stand-in translations are machine-drafted:** "the customer", "le
   client", "di customer", "abokin ciniki", "oníbàárà", "onye ahịa", "mteja"
   and "العميل". They need the reviewers named in each `*.review.json`.

## What I left out, and why

**The web screens other than the run screen.** They still assume a contact
always has a name, and some still send things the API now refuses:
- the leads screen offers a name sort (`lib/leads-api.ts:39` `LeadSort`, plus
  `components/leads/leads-model.ts:167-177` and `leads-table.tsx:233`), which is
  now a 400;
- the leads and contacts searches send typed numbers in `q`, which is now a 400;
- these schemas reject a withheld name:
  - `lib/records-api.ts:65`, `Contact.displayName` (`z.string()`);
  - `lib/pipelines-api.ts:118`, the deal contact;
  - `lib/pipelines-api.ts:380`, the picker;
  - `lib/activities-api.ts:42`, `ContactSummary`.

  A page will fail to parse for a caller a name part is withheld from.

These screens are pinned by records-ui suites and by e2e p04-leads, so changing
them needs the lead's re-pins first. I recommend a frontend follow-up task.

**The 0035 `display_name` keyset indexes** are now unused by any list. Dropping
them needs a migration, and the instructions said to stop before writing one,
so they stay.
