# T-0011 — schema hygiene: redundant indexes, maintained updated_at (Agent 1)

**State:** merged to `main` (#78), migration `0018_schema_hygiene.sql`.

**What changed:**
- **Six redundant indexes dropped.** Each was a plain btree tenant-prefix index that is a strict prefix of another index. They are now dropped at the end of the file, per the migration review.
- **`updated_at` is maintained by the schema.** `app.touch_updated_at()` is attached as a BEFORE UPDATE trigger on all 16 tables that have the column. It fires only when the statement left `updated_at` unchanged.

**Evidence:**
- Lead suite (`lead/T-0011-acceptance`): passes 8/8 (4 of these failed on main before).
- EXPLAIN on 1,000 tenants: the query plans are unchanged, and `listFieldDefs` gets cheaper.
- `migration-reviewer`: pass with findings. The one major finding (lock order) is fixed, and the latent version risk is documented in `programme-version.ts`.
- After the fix: four acceptance suites pass 53/53, and integration passes 99/99.

**Hard part:** the programme version is derived from `updated_at`, and the repository writes a strictly increasing value itself. The trigger therefore leaves alone any statement that sets the column; this is done in the `WHEN` clause.

**Open:**
- `create-rls-migration` should tell future tables with `updated_at` to attach the trigger. The suite catches a table that forgets.
- `cli/reset.ts` is missing tables from its drop list (pre-existing, D-L56).
