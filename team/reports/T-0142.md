# T-0142 — P18 Customisation Studio to the design

Agent 11, branch `agent11/T-0142-p18-studio`. D-L193, D-L194, D-L195, D-L201 (no suites run, no new tests).
Design: `docs/design/P18/Kasuwa Customisation Studio.html`, 44 frames at 1440 and 1024. Phone and dark derived
from the v1.1 tokens.

## What matches

- **Studio frame** (every P18 frame): the admin bar with the divider and "Customisation studio" with
  `design_services`, then the 44px breadcrumb strip ("Customisation studio > {object}"). It sits inside the admin
  shell, and the settings menu's Customisation group is the studio navigation (Objects, Fields, Page layouts,
  Validation rules, Record types). Each entry links only where its flag is on.
- **Object page header** (frames 09–24): 52px tile, 26/800 title, mono api name, Standard chip, "All programmes".
  The Activities and Timeline chips show behind `studio_objects`; the Relationships button shows behind
  `studio_relationships`. Below are the tabs: "Fields & relationships {count}" ("Fields" while relationships are
  off), plus Page layouts and Validation rules behind their flags.
- **Toolbar**: 40px search with a leading glyph, which filters by label or api name in the browser. Then the
  "Custom fields {n} of {limit}" meter, which turns warning at 85% and danger when full and uses real figures from
  `limits`. Then New field, which is disabled at the limit with the export's limit banner above.
- **Field table** (frames 09/10): the columns Label (with the help glyph when there is a description), API name in
  mono, Type (glyph and name), Properties (the lock chip for PII and sensitive) and Modified ("2 Oct 2026",
  day-first). Modified only shows from 1280 and with no editor open, as the export draws it.
- **Field editor** (frames 11–19):
  - It is docked beside the table at 480px from 1280 up: in the flow, sticky, and sized to the viewport so the
    footer is always visible. Below 1280 it is the T-0129 Drawer at 460px with a scrim; on phones it is a bottom
    sheet.
  - Header: a 40px tile with the type glyph, the title, and "api · Type" in mono.
  - Tabs: Properties, Security, and Translations (flag), with warning-soft change badges.
  - Properties: Label and API name side by side, with the API name locked on edit. The type picker is the
    export's two-column card grid. The currency select shows Intl-derived labels ("₦ Nigerian naira (NGN)", no
    hard-coded symbol). Picklist values are the numbered rows with "+ Add value". The config sits in the sunken box.
  - Footer: Retire (in the export's Delete position), "All changes saved" or "N unsaved changes", then Close or
    Discard, then Save field. Create shows "Add a label to continue", Cancel and Create field.
- **Security tab** (frame 15): Hidden/Read/Edit segments for each permission set, read from the real
  field-security matrix (`listPermissionSets` and `getFieldSecurityMatrix`, loaded only when the tab is first
  opened). Changed rows turn warning-soft. Changes are saved with the matrix's own write, with its version, after
  the field update. A field the matrix doesn't list says so and links to P02/D.
- **Placeholders (D-L194)**, each drawn empty or disabled with no invented object, rule, layout or number:
  - Object manager `/admin/studio` (P18/A): the four standard objects, counts drawn as "—", New object disabled,
    and the Custom objects meter reading "None yet".
  - Relationships `/admin/studio/relationships` (P18/A2): the four nodes with no edges, disabled zoom, and the
    export's "No relationships yet" wording.
  - Page layouts `/admin/studio/layouts` (P18/C) and the empty builder `/admin/studio/layouts/builder` (P18/C1).
    The builder's palette lists the object's real custom fields.
  - Validation rules `/admin/studio/validation-rules` (P18/D): the export's own empty state.
  - Record types `/admin/studio/record-types` (P18/E).
- Every existing test id and rule is kept: `data-screen="P18/B"`, `data-object-tab` (aria-pressed),
  `field-limit`, `show-retired` (now a `role="switch"` chip), `data-field-row` and its attributes, `field-edit`,
  `field-retire`, `fields-empty`, `field-new`, `field-form` with `data-mode`, the named controls (`type` is now a
  radio group), `picklist-row`/`-add`, the two classification notes, `field-save`/`-cancel`, and the retire
  dialog. With every new flag off, none of R23's "absent" words appear on the studio's surfaces.

## What doesn't match yet

- The settings menu stays at 1440, so the field table is 272px narrower than the export. With the editor docked
  the columns truncate. The export has no menu, but the acceptance shell journey requires it, as does the brief's
  "inside the admin shell".
- Below 1280 the Drawer covers the full height, where the export starts it under the breadcrumb. This is T-0129's
  geometry.
- The rows carry a 44px retire icon column, which the export lacks. `field-retire` needs a per-row control.
- The type picker is not the export's separate first step: Label and API name sit above the cards, because the
  journeys fill the label before choosing a type.
- Classification (None/PII/Sensitive) is a segmented control the export doesn't draw. This is D-L195's closest
  style, the ID-type segment.
- The relationships and builder canvases don't stretch to the bottom of the viewport.
- Not drawn:
  - The type-change impact dialog (frame 23). The type is immutable.
  - The new-object wizard (frames 03–06).
  - The rule editor (frames 39–44).
  - The populated builder canvas, preview and leave dialog (frames 27–35).
  - Each of these is either a cut or depends on data that doesn't exist.

## Found on main after merging (not this task's)

`localeReadiness` reports fr, pcm, ha, yo, ig, sw and ar incomplete on current main. The causes are keys that are
identical to English and not declared as passthroughs: `admin.home.subtitle`, `admin.home.recent.what`,
`admin.audit.summary`, `admin.audit.chip` and others, from the P02 work. If the menu filters on readiness, those
languages fall off it. None of the problems comes from a studio key, and I didn't touch them.
