## Choices the suite left to me
- **Tier is an enum; industry is free text.** P04 shows Enterprise / Mid-market / SME as tier values, so I made those
  snake_case codes. P04 shows FMCG, Agriculture and so on as industries, which is tenant data, so I left it free text.
  **T-0054 must store the tier set exactly as written here.**
- **Account also carries a bare `ownerUserId` beside `owner`,** the same as Contact after T-0043. The two are withheld
  together. Writes set `ownerUserId`; `owner` is read-only.
- **`sort` uses only fields that are never withheld:** `name`, `createdAt` and `updatedAt`, in both directions.
  The default is `name`.
- **There is no `programme` filter on listAccounts.** The suite forbids one (CLAUDE.md 2.2). A screen narrows to one
  programme on the client side.
- **`parentAccountId` must be in the same programme** as the account (I wrote this into the contract). That means a
  caller who can read an account can always reach its parent. An unreachable parent gets `400 unknown_reference`, the
  D-L67 pattern. A parent that would create a cycle gets `400 validation_failed` with `details[].code: parent_cycle`.
  That detail code is new; `details[].code` has no enum.
- **listAccountContacts** returns `ContactPage` by `$ref`, so its rows are exactly Contact. That includes T-0043's
  `owner` once that merges. It checks in this order:
  1. `404` if the account is unreachable.
  2. Then `400 field_withheld` at `accountId` if the contact field `accountId` is withheld from the caller **in the
     account's programme**. listContacts judges "in ANY programme they reach", but here every row is in the account's
     programme, so judging there is exact.

  Its only parameters are `sort` (the listContacts set, default `displayName`), `cursor` and `limit`. It has no
  `q` or filters.
- **The Map view is a 501 stub at a concrete path** (`/accounts/map`). It is listed before `{accountId}` in the file,
  and "map" is not a uuid anyway. **Note for T-0055:** register the `map` route before `:accountId`, or the uuid pipe
  answers 400. Its description says why it is not built: pins per State are a count per group, which is D-P13 by
  another name.
- **Writes are admin-only** (`account.write`, mirroring `contact.write`; D-L63, D-L69). They follow the same
  403-before-body rule, so the `programmeId` rules do not leak programme count.
