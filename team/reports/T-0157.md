# T-0157 report: sign-in reads on the auth pool, secrets revoked from `kasuwa_app` (D-A3)

## What changed
- `AuthService.signIn` phase one (the lock read and the account lookup that joins `user_credential`) runs on `authPool`. `auth.service.pools.test.ts` is flipped to match: sign-in is auth then auth, and only sign-out's `app.resolve_session` stays on the app pool.
- Migration **0046** `0046_auth_secret_read_revoke.sql`, grants only: table-level `REVOKE SELECT` on `user_credential`, `user_mfa_factor`, `user_mfa_backup_code` from `kasuwa_app` and PUBLIC, then `GRANT SELECT (columns)` back for the non-secret columns. A `DO` self-check asserts the secret columns are unreadable, the kept columns readable, and `kasuwa_auth` keeps its SELECT. No policy, function or role changes (still two SECURITY DEFINER functions).
- ADR-0013 decision 6 marked resolved; `packages/db/CLAUDE.md` invariant 9 and `apps/api/CLAUDE.md` invariant 1 updated.

## What was hard / decided
- **Number 0046, not 0045.** T-0159 takes 0045 (`home_layout`). The runner sorts by filename and does not require contiguity, so 0046 can merge first.
- **Revoked, not dropped:** the legacy plaintext `user_mfa_factor.secret`. Dropping is a contract migration of its own and breaks six pinned suites.
- **The kept list is wider than T-0075 said:** `GET /auth/me/mfa` and the admin home also read `user_mfa_factor.id, tenant_id, type` and `user_mfa_backup_code.tenant_id, user_id, used_at`. The suite pins exactly those.
- Moving phase one off the app pool changes the lock-starvation behaviour ADR-0013 decision 6 described. That is the follow-up the ADR and T-0075 named; it is not a new decision.

## Known red (not edited here)
`auth-retention.acceptance.test.ts` part 2 starves the APP pool and expects sign-in to answer 503. Sign-in no longer uses the app pool, so it must be restated to "either pool exhausted gives one 503" (T-0075 says the lead edits it first).

## Left out
Dropping `user_mfa_factor.secret`; any API shape change.

## Verification
The pools unit test passes; lint and typecheck clean. Migration and the acceptance suite need Postgres (Testcontainers) and the dialler's Docker stack is up, so they were NOT run locally; CI runs them. `migration-reviewer` was run on the SQL (result in the PR).
