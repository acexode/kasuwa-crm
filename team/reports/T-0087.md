## What changed

- **Flag.** `packages/feature-flags/src/index.ts:226`, test at `flags.test.ts:182`. The reader is `crmSearchEnabled()` at `apps/web/lib/feature-flags.ts:235`. `crmLiveNav()` lists `'search'` at `:178`.
- **Harness.** `tests/e2e/scripts/run-e2e.mjs:519` adds the flag to the records process, and `:658` publishes `webSearchUrl`. The type is at `tests/e2e/support/stack.ts:90`.
- **Rules.** `apps/web/lib/search-query.ts`:
  - `identifierShaped` (`:33`, D-L135) and `phoneLike` (R27);
  - `planSearch` (`:88`) decides between idle/short, keep-typing, a local refusal, a name search, or a lookup. A lookup value is the input NFKC-normalised and trimmed (R28);
  - `nameFromUrl` (`:110`) accepts a URL `q` only if it is a name;
  - `dropQueryFromAddressBar` (`:122`) uses `replaceState` and keeps every other parameter.
- **Client.** `apps/web/lib/search-api.ts`:
  - it goes through `requestRecords`, so calls are same-origin, `no-store` and carry no scope;
  - the lookup is a POST with the closed body;
  - `SearchAnswer` (`:92`) drops unknown group types and unparseable hits, and cuts each group to 3;
  - `hitHref` (`:140`) links only from a uuid, and never links deals;
  - `seeAllHref` (`:148`) and `personName` (`:161`) use the served `displayName`, else one readable part, else `null`, which draws as a lock.
- **Panel.** `apps/web/components/search/search-panel.tsx` holds the ARIA 1.2 combobox:
  - the listbox is drawn only when it has options;
  - groups follow the APG pattern;
  - option ids come from the group and position, so a lead that appears twice still has unique ids;
  - linked hits are `<a role="option" tabindex=-1>`, which avoids nested-interactive.
  - Its states are `search-loading`, `search-empty`, `search-error` (with retry), `search-invalid` and `search-hint`.
  - "See all" is a row of three links under the listbox, offered for name queries only.
  - The hook is `use-search.ts`: 250 ms debounce for names, 600 ms for lookups. Superseded reads are aborted, and an answer is drawn only if its key matches the current text (R10).
- **Palette.** `apps/web/components/search/command-palette.tsx` holds `data-testid="command-palette"`. It is a dialog with a focus trap, closed by Escape, the backdrop or a close button, and it is unmounted on close (R19).
- **Shell.** `apps/web/components/crm/crm-shell.tsx`:
  - the palette is `lazy(() => import('../search/command-palette'))` at `:35` (R29);
  - `live.includes('search')` at `:114` gates the header entry `href="/search"` (`:165`, with `aria-current` on /search, icon-only below `sm`), the Ctrl/Meta+K listener and the palette;
  - the header, body and bottom nav are `inert` while the palette is open, and focus returns to the opener after close;
  - there is a status fallback while the chunk loads.
- **Strings on every CRM screen.** The panel's strings ride in `CRM_SHELL_MESSAGE_IDS` (`crm-nav.ts:61`). The palette's code loads late, but its words must be on the page in the page's locale or `?locale=` preview.
- **Screen.** The route is `apps/web/app/search/page.tsx`: `notFound()` unless the flag is on, the title comes from i18n, and `q` is passed through `nameFromUrl`. The screen is `components/search/search-screen.tsx` (`data-screen="P27"`), and it strips `q` from the address bar on mount (R12).
- **Gap 3 (R8).** `/contacts`, `/leads` and `/accounts` read `searchParams.q` through `nameFromUrl` as `initialQ` (contacts `:97`, leads `:88`, accounts `:134`). It shows in the box and is sent on the first list read, then `q` is dropped from the address bar, consistent with "a search never enters the URL".
- **Docs.** `apps/web/CLAUDE.md` route table updated.

## Choices made (the builder's)

- `/search` does not keep `q` in its URL. It reads a name `q` once, then drops it.
- A partial identifier is sent to the lookup and the API's refusal is drawn. The one exception is a six-digit run inside letters (`Sample 0803/000/0001`), which is refused locally as `invalid_phone`, because it is neither a name nor a phone.
- No lead status is drawn. The company name is the secondary line when it is served.
- Superseded requests are aborted.

### Fixes, per finding

| Finding | What changed |
|---|---|
| M1 | The palette's Escape is a capture-phase `document` listener that calls `stopPropagation()`, so a popover or dialog behind it never sees the key (`command-palette.tsx`). The shell's shortcut does nothing while an `[aria-modal="true"]` element is present, so the palette never opens over the new-deal form (`crm-shell.tsx`). |
| M2 | The focus trap uses `tabStops()`, which keeps only elements with `tabIndex >= 0`. The option links are `tabindex=-1`, so they are no longer stops. |
| M3 | `/contacts`, `/leads` and `/accounts` key their screen with a fresh key whenever the render carries a `q` (`q:${crypto.randomUUID()}`), and a stable key otherwise. A same-route "see all" therefore remounts with the new `q`, even when the `q` is the same twice, and the screen drops `q` from the address bar. A refresh never carries `q`, because the screen has already removed it. |
| M4 | The palette loads through `loadPalette()`, which is `lazy(import(...).then(ok, () => PaletteFailed))`. A failed chunk shows a retry-or-close dialog, and a retry builds a fresh loader. Both interim states sit in a `PaletteOverlay` that closes on Escape (capture phase) or a backdrop press. |
| M5 | A 429 draws `records.error.too_many_requests`, and Retry stays disabled until `retryAt`. `requestRecords` now carries `retryAt` (`lib/records-api.ts`, additive). A `validation_failed` draws its own message, a lost session draws "sign in", and anything else draws the connection message. |
| L1 | The minimum length is counted as `[...folded(name)].length`. A unit test covers U+1E900 alone (too short) and two such letters (a name). |
| L2 | The shortcut accepts `event.code === 'KeyK'` as well as `key === 'k'`, and ignores Shift. |
| L3 | `CRM_SHELL_MESSAGE_IDS` no longer carries any search string. Every CRM page calls `bundleMessages(locale, withSearchMessages(IDS, live))`, which appends `SEARCH_PANEL_MESSAGE_IDS` only when `live.includes('search')`. The shell names its few search strings through `SHELL_SEARCH_STRINGS`, a unit test checks that each is in the panel bundle, and the shell draws them only when the search is live. |
| L4 | The header `/search` link has `prefetch={false}`. |
| L5 | The dialog is labelled with `aria-labelledby` pointing at its h2. `[data-search-announcement]`, a polite live region, says "{count} results shown" using the number of hits DRAWN, as an ICU plural in every catalogue (ar has six categories, fr three). It replaces the numberless line from round 1. I did not add Escape, Home or End in the combobox (optional). |
| R15 | Deal hits link to `/deals/<id>` only when `live.includes('deals')`, via `hitHref(type, id, dealsLive)`. The screen passes the value from `live`, and the palette receives it from the shell. |
