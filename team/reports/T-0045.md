# T-0045 — Auth-table retention sweep and pool-exhaustion 503 (Agent 1, with a lead-applied role)

**State:** merged to `main` (#84). Migration 0020 and a new role in `bootstrap.sql`. Design in D-L66 and ADR-0012.

**What changed:**
- **The `kasuwa_sweeper` role:**
  - NOLOGIN, NOBYPASSRLS. Granted to `kasuwa_app` with `INHERIT FALSE, SET TRUE`.
  - It can DELETE, and SELECT a few columns, on the three auth tables only.
  - Its only policies have the retention rule as their predicate.
  - Migration 0020 asserts the role's shape, and that nothing else reaches it.
- **`pruneAuthTables`:** deletes in bounded batches, takes an advisory lock per table, and asserts that no tenant context is set.
- **Worker:** the prune runs every 15 minutes, and job errors are sanitised.
- **Role-forgery guard:** the role is now checked as part of the verified scope, and a connection's role is reset when it is released.
- **One 503:** pool exhaustion and hashing overload both return 503 with `Retry-After: 5`.

**Evidence:**
- **Lead suite:** 14/14, including Part 2, which had never been seen passing.
- **Integration:** 109/109, including 8 new role-guard tests.
- **On current `main`:** tenancy, permissions and adversarial suites 122/122.
- **Security review:** passed with findings, all fixed. The major one was role forgery through `set_config`.
- **Migration review:** passed with findings, all fixed. It ran on real Postgres 16, which showed that only dead rows are reachable and that the bootstrap stays idempotent.

**Hard parts:**
- A policy `TO` a role also applies to members that inherit it, so the grant has to be NOINHERIT.
- `SKIP LOCKED` needs UPDATE privilege, which the role doesn't have, so an advisory lock is used instead.
- Granting any role to `kasuwa_app` opens `set_config('role')` forgery.

**Process:**
- `bootstrap.sql` is lead-owned. The builder stopped at the path guard. The lead reviewed the proposed diff line by line and applied it on a `lead/*` branch, as the guard directs.
- Existing dev databases must re-apply the bootstrap. The command is in 0020's error message and in `packages/db/CLAUDE.md`.

**Open:**
- The residual in-transaction role use, documented in ADR-0012.
- The worker still boots when `DATABASE_MIGRATION_URL` is present; it strips the variable rather than refusing to start.
- The `auth-availability` timing flake on this host.
