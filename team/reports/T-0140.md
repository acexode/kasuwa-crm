# T-0140 — P02 admin console to the design

Builder: agent-11 (Opus 5.5). Branch `agent11/T-0140-p02-admin`. Design: `docs/design/P02/Kasuwa Admin Console.html`
(frames 01–44, 1440 and 1024 light); phone and dark derived from the v1.1 tokens. Per D-L201 no suites were run and no
tests were written; lint and typecheck pass for the web app, the flags package and `tools/demo.mjs`.

Screenshots: `.artifacts/parity/app/p02-*-{1440,1024,360}-{light,dark}.png`, 13 screens: home, programmes, programme
overview and every tab, roles, field security, audit, and audit with a row expanded.

## What changed

- **Shared admin primitives** (`components/admin/admin-ui.tsx`):
  - 40px header/toolbar buttons (14/600, 20px glyphs) in primary, secondary, danger and danger-outline.
  - A `notReady` state for controls with no backend: disabled tokens, `aria-disabled`, no opacity fade.
  - Page header: 28/800 title, 13/600 eyebrow, 15/22 intro at most ~720px.
  - 40px search field with its leading glyph.
  - 36px chips and object tabs, solid primary when selected.
  - Caps table heads on surface-sunken.
  - The floating dark unsaved-changes card. It has two lines (the count, then which section holds the changes), Discard outlined on dark and Save in accent. It sits beside the nav from 1280.
- **Dialogs on the T-0129 Dialog.** `components/admin/dialog.tsx` keeps its API and is now built on `@kasuwa/ui/components` Dialog, which handles focus trap and return, inert page, scroll lock, and full screen on phones. It adds the 40px tone tile and a footer that keeps every action on a phone.
- **Admin home (P02/A):**
  - The health ring is an SVG drawn to the real score, in banded tone.
  - Subtitle is "Tenant · plan · N countries · N users".
  - Fix links appear where the setting's screen exists.
  - Alerts header, rows and per-alert action follow the design.
  - Usage header shows "Today, d of n days" with its rule and "1–31 Oct 2026 · Resets 1 Nov".
  - All four meters are drawn. The three without data show their empty state behind `admin_placeholders`.
  - Recent changes are rows with "27 Sep, 14:32 WAT" times, "Updated · Script" and the record name.
- **Programmes (P02/B, B1):**
  - Solid status chips with counts. Archived appears only once something is archived.
  - Client · country subline (`Intl.DisplayNames`), "None yet" and "Not set", empty SLA track.
  - Chevron column; the whole row opens the programme.
  - Empty state follows the design.
  - SLA bands follow the design: green ≥95, amber ≥85, red below.
- **Programme detail (B2–B9):**
  - Breadcrumb, 28/800 title with the status pill, and client · country · mono reference.
  - 40px actions.
  - Underline tabs with counts only where served. Only the agent count is served, from `people.agentCount`; no totals otherwise.
  - The settings menu follows the tab (SLA policies, Dispositions, Scripts, Retention).
  - Overview: icon-free KPI cards (26/800). Info cards have Edit (disabled, flag), a Client row, and channel/hours/holiday rows.
  - Agents, SLA, Dispositions, Scripts, Retention and Portal tabs, and the archive dialog, are restyled to their frames.
- **Roles (P02/C):**
  - Type tiles (`account_tree` for parents, `badge` for leaves; filled primary when selected).
  - 28px indent per level, 14/500 names with the selected one in 700.
  - Side panel: 380px at 1440, 300px at 1024.
  - The delete dialog uses radio cards.
  - Designed empty state when the tenant has no roles (the demo tenant has none), with `data-testid="roles-empty"`.
- **Field-level security (P02/D):**
  - Read-on is soft primary and edit-on is solid primary; off is bordered.
  - Locked Admin cells keep their colour and get `cursor-not-allowed`.
  - PII is tagged in info, Sensitive in danger.
  - Object tabs are solid when selected.
  - PII filter is a checkbox button, and the legend sits on the search row.
  - Bulk bar follows the design and selected rows are tinted.
  - Sticky field column and v1.1 checkboxes.
- **Audit log (P02/E, E1, E2):**
  - The before/after detail is a full-width row under its event, on the event's tint, aligned to the actor column from `md`.
  - Action badges are toned: created/published green, updated blue, deleted/rejected/failed sign-in red, exported amber.
  - Object types and field names are humanised.
  - Record ids that are bare UUIDs read "Record C2695C".
  - Actor avatars, with a robot glyph for System.
  - "TIME (WAT)" header and "20 Oct, 12:44 WAT" cells.
  - "25 events · Last 30 days" with removable filter chips. "Clear all" shows only while a filter is set.
  - The export dialog uses radio cards and the v1.1 switch.
- **No sideways overflow at 1024 or 360.** The cause was the tables' `sr-only` captions: they are absolutely positioned, so with no positioned ancestor they escaped their scroll containers. Every scroll container is now `relative`.
- **New formatters** (`lib/admin-format.ts`): `formatStamp`, `formatZone`, `formatPeriod`, `periodProgress`, `formatDayMonth`, `formatAgo`, `formatCountry`, `looksLikeId`.
- **New audit helpers** (`lib/admin-audit.ts`): `auditActionTone`, `isLabelledAction`, `AUDIT_OBJECT_TYPES`, `humaniseKey`.
- **API schema:** `AuditEntrySummary` now reads `objectType`, `objectLabel` and `objectId` (already sent by the API).

## Flag added

- `admin_placeholders` (D-L194). It is in `packages/feature-flags`, `flags.test.ts`'s pinned list, `tools/demo.mjs` and `lib/feature-flags.ts` (`adminPlaceholdersShown`).
- It draws, all disabled or empty:
  - the three usage meters without data;
  - Alert settings;
  - the programme cards' Edit links;
  - the role panel's View people.
- Off by default, on in `pnpm demo`.

## Not matched yet / left out

- **Plan name.** The API sends the literal English string "Not set" as `planName` (`apps/api/src/admin/home/home.controller.ts:110`), so the subtitle reads "Not set plan". The API should send null when no plan is set; the screen would then leave that part out.
- **Disabled actions are not solid primary.** New programme, Add role, Add disposition, New script, Invite, Client portal and Pause have no backend, so they are drawn in the disabled tokens rather than solid primary.
- **Dialog layout.** Dialog bodies are full width under the title rather than indented beside the icon tile, because the T-0129 Dialog puts the icon in its header. Dialog width is the 440 form step; the design is 500.
- **Not drawn (no backend):** the disposition drag handles, and per-alert action buttons when the alert's setting has no screen.
- **Reports to stays a native select** (44px, styled). The tests drive it with `selectOption`.
- **Kept on purpose, though not in the design:**
  - the FLS scope note and the audit footer note about IP addresses (both deliberate disclosures with test ids);
  - the "Not known" user counts on FLS columns;
  - the sample-data frame around the KPIs.
- **Shell (T-0130's, not edited):**
  - Every admin page is 365px wide at 360. The header's avatar button and its `before:-inset-1` hit band overflow by 5px.
  - Nav labels still read "Users and access" and "DND and quiet hours".
- **Populated tree not seen live.** The demo tenant has no roles, so the role tree with data has only been checked in code, not in a screenshot.
- **Stale flag pin.** `flags.test.ts`'s pinned list on main was already missing the T-0132 and T-0137 flags. I added mine only.
