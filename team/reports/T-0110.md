## What changed

- **Route** `apps/web/app/deals/[dealId]/page.tsx`. Gated on `crm_pipeline` (read on the server), with `notFound()` when the flag is off or the id is not a uuid. The deal is read in the browser, and the document title never carries its name (R1, R2).
- **Client** `apps/web/lib/deal-detail-api.ts`, with its own module so the board ships none of it:
  - `getDealDetail` and `moveDealDetail` parse checks with `checkedBy.displayName` nullable (D-L127);
  - `updateDeal` sends a PATCH;
  - `listDealTimeline` echoes the cursor and sends no limit;
  - `createDealActivity` links `dealId` and sends the deal's own targets;
  - `getCaller` gets the caller's id for "assign to me".
- **Shared transport** `apps/web/lib/pipelines-api.ts`. `request` is now the exported `pipelineRequest` (line 190) and takes an optional PATCH. `dealPath`, `withSearch` and `moveDealBody` (line 350) are exported.
- **Screen** `apps/web/components/deal/deal-screen.tsx` (P06/05, `Ready` at line 183):
  - header, stage path and current requirements;
  - key fields, with locks, "not set", the former owner and money exactly as T-0109 draws it;
  - checks, showing who ticked each and when, with a former-checker label;
  - "assign to me" (line 315);
  - moves through T-0109's `MoveSheet` and `RequirementPrompt` (`send`, line 226);
  - the composer (`log`, line 338), or `activity-no-target` when there is nothing to log against;
  - the shared `RecordTimeline`, read again after every write.
- **Edit sheet** `apps/web/components/deal/deal-sheet.tsx`. It sends `version` plus changed fields only and `null` to clear. A blank name, a bad amount or a missing currency is a local error. A 409 reads the deal again, rebases the form and marks a field both people changed with `data-conflict`; nothing is resent until the person saves. A 403 names the fields by label.
- **Pure model** `deal-model.ts`, data hook `use-deal-detail.ts` and server message ids `message-ids.ts`, all with unit tests.
- **T-0109 R15** `apps/web/components/pipeline/pipeline-board.tsx:390`. A card's name now links `/deals/<id>` when the id is a uuid. A drag can still start on the name. After a drag, the next click on the dragged card is swallowed; the guard disarms on that click, the next pointerdown, or after 500 ms (`swallowsClick` in `pipeline-model.ts`, unit-tested).
- **No duplication with T-0109.** The move-refusal copy now lives in `components/pipeline/move-refusal.ts`, used by both screens. `PromptState` moved to `pipeline-model.ts:210`. None of the board's review fixes changed.
- **Shared timeline** `components/record/record-timeline.tsx` shows a meeting's start and end times only where a record passes `meetingTimes`. Only the deal does, so the contact and account timelines are unchanged from main.
- **Money input** `deal-money.ts:98` adds `minorToMajorText`, which seeds the amount input using string arithmetic only.
- **i18n.** 29 keys in every design-menu catalogue plus `ar`, awaiting review (D-P1). This includes `pipeline.field.{ownerUserId,stageId,checks}` and a `deal.checker.former` label that differs from `records.owner.former`.

## What was hard

- **Axe at 360 px.** The stage path scrolls inside itself, and axe requires a scroll region to be focusable. It is now wrapped in a labelled, focusable `role="region"`.
- **Rebasing after a 409 without resending untouched values.** The sheet keeps its comparison point as the deal it now stands on, so the second save only sends what the person changed. Contact and account are stored as ids in the form, so a conflict is judged by value, not by object identity.

## Left out, and why

- **The design's move shortcuts** ("Move to …", "Back to …", "Mark as lost"). R14 makes them optional. The move sheet covers every allowed target, lost included.
- **Reassigning to another person, unassigning, completing tasks from the deal, and the hidden list.** These are excluded by R11, R16 and R18.
- **`apps/web/CLAUDE.md` route table.** I left it alone; the lead then added `/pipelines` and `/deals/[dealId]` to it in f709818.
