# T-0123 — A former checker is unnamed in the deal APIs

**Builder:** Agent 3 · **branch** `agent3/T-0123-former-checker` (from `lead/T-0123-acceptance`, 6e38540)
**Decisions:** D-L127, D-P23, D-L132, D-L136

## What changed

The rule is in one place now: `packages/domain/core/src/pipeline/deal-actor.ts`.

- `dealProgrammeMember(alias, refs)` is the D-P23 membership test. It is an `EXISTS` on
  `user_programme`, keyed on the row's tenant, the deal's programme and the user. The
  tenant-admin flag is not part of it, and neither is any other programme.
- `dealActorOf(userId, isMember, displayName)` always returns `{ id }`. It adds the name only
  for a member, and throws `DealActorUnresolvedError` (which carries no identifier) for a
  member whose name cannot be read.

The reads that use it:

- **Board cards** (`deal-board.repository.ts`):
  - `OWNER_MEMBERSHIP` is now built by `dealProgrammeMember`.
  - Each check's JSON carries `checkedByIsMember`, and the name is read only `CASE WHEN`
    member.
  - The owner and each checker both go through `dealActorOf`.
  - The card statement count is unchanged: membership resolves inside the existing card
    statement.
- **Deals API** (`apps/api/src/deals/deal.repository.ts`):
  - `checksFor` serves getDeal, listDeals, and the updateDeal and moveDeal answers. The latter
    two re-read through `findDealById`.
  - `checksFor` now resolves every checker's membership in its single statement, and reads
    the name only for a member.
  - The new exported `checkRowOf` maps each row through `dealActorOf`.
  - The owner subquery in `DEAL_SELECT` now uses the same predicate. It was a JOIN on
    `user_programme` before; the meaning is the same.
- **Wire types:** `checkedBy.displayName` is now `string | null` in `deal-wire.ts` and
  `pipeline-wire.ts`. The contract already allowed it (D-L132).

What did not change: no migration, no table, no contract edit, the timeline (D-L136), and
who may tick a check.

Unit tests (all fail without the change, checked by reverting the two repositories):

- `packages/domain/core/src/pipeline/deal-actor.test.ts` (5 tests);
- `packages/domain/core/src/pipeline/deal-board.repository.test.ts`, one new test:
  - a member is named and a former checker is unnamed, even when a name was read beside a
    non-member;
  - there is one statement, keyed on `deal_check.checked_by_user_id` and `d.programme_id`.
- `apps/api/src/deals/deal-checkers.test.ts` (4 tests):
  - `checkRowOf`;
  - `findDealById` sends 2 statements, with the checker and owner predicates;
  - the wire serves the null;
  - `listDeals` sends exactly one checks statement for many rows.
