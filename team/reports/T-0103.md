## What was hard

- **The lock under 0021.** `FOR KEY SHARE` is filtered for non-admins, so I used an advisory lock on the
  membership key instead, as 0026 does. The lock and the membership read must be separate statements, or the
  read's snapshot predates the wait.
- **Offboarding.** Programme and tenant deletes cascade into `user_programme`.
  - Acting inside those cascades would insert an audit row naming a deleted programme, or unassign contacts
    that are about to be deleted anyway.
  - A "user" delete would turn the owner FK's refusal into a success.
  - So the trigger checks that the tenant, programme and user rows still exist, and does nothing otherwise.
- **The RAM slots.** One run waited 40 minutes for a slot. The sandbox refused a launcher wrapped around
  `git commit`, so I took commit slots with a plain `mkdir` and `rmdir` either side of the commit.
