## What changed

- **`packages/permissions`**: a new programme action, `account.write`. The `admin` set gets it because
  admin holds every programme action. The tenant-admin flag also grants it. No other set holds it: D-P18
  keeps account writes admin-only, and the agent's D-P14 contact rights do not carry over. Unit tests cover
  every set, per-programme scope, the flag, and out-of-scope programmes.
- **`packages/domain/core/src/account/`** (new):
  - **`account.repository.ts`**: the reads and writes.
    - Reads: `listAccounts` (the `q` name search, filters, the six sorts, keyset paging) and
      `findAccountById`.
    - Writes: `insertAccount` and `updateAccountIfVersion`, a conditional UPDATE that sets
      `version = version + 1`.
    - Hierarchy: `checkAccountHierarchy`, a bounded walk of the committed tree. It walks up from the
      proposed parent (to detect a cycle and find the parent's depth) and down from the account (to find
      the height of the subtree that moves with it).
    - Every statement carries the tenant and programme predicates, and every value is bound.
    - The owner's display name is read by a correlated subquery on the row, as contacts do.
    - `q` uses `strpos` over a folded name (NFD, combining marks dropped, lower-cased). So it is a literal
      substring match: `%`, `_` and `.*` are not wildcards.
  - **`account-fields.ts`**: `loadFieldAccess(tx, 'account')` and `fieldLevel` from T-0053, keyed by the
    snake_case of each wire name, and failing closed.
    - Withholdable fields: `ownerUserId`, `industry`, `tier`, `tags`, `phones`, `state`, `lga` and
      `parentAccountId`.
    - `name` is never withholdable, even when a grant row for it says `none`.
  - **`account-hierarchy.ts`**: two pure pieces.
    - `hierarchyVerdict`: a cycle gives `parent_cycle`; `parentDepth + height > 5` gives `parent_depth`.
    - `classifyAccountWriteError` maps database refusals onto reason codes:
      - 0026's guard (23514 `account_hierarchy`) becomes `parent_cycle` or `parent_depth`, chosen by the
        guard's fixed message. Its fail-closed "could not be verified" becomes `unknown_parent`.
      - The self-parent CHECK becomes `parent_cycle`.
      - The two composite FKs (23503) become `unknown_parent` and `unknown_owner`.
    - The repository rethrows these as `AccountWriteRefusedError(reason)`, which carries no Postgres text.
- **`contact.repository.ts`**: `ContactFilters` gains `accountId` and `withinProgrammeIds`, a
  server-derived narrowing filter that cannot widen the session predicate. Both exist for
  `listAccountContacts`.
- **`apps/api/src/accounts/`** (new):
  - **The controller** carries the guard, the interceptor, the admin error filter and `Cache-Control:
    no-store` on every handler. `GET map` is declared before `:accountId` and throws 501
    `not_implemented`; an anonymous call to it still gets 401 from the guard.
  - **The service** applies D-L53's order:
    - create: 404 (no programme reached), then 403 (`account.write` held in no reachable programme, before
      the body is read), then 404 or 400 on the target, 403 for the target, 403 `field_not_editable`, 400
      for the body, 400 for references, then the write;
    - update: 404, 403, 403 `field_not_editable`, 400, references, then 409.
    - A database refusal that slips past the API's own checks (the concurrent half-cycle) still gets the
      same 400 body.
    - Audit: one event per write, `objectType: account`, labelled with the record id. Every change is
      redacted (field names only). Free text and phones are recorded whenever sent; tier, owner and parent
      only when they change, mirroring contacts.
  - **Wire and schemas**:
    - `owner` is withheld together with `ownerUserId`.
    - The query schemas are open (unknown parameters are ignored); the write bodies are strict, so
      `programmeId` on update is 400 (D-L76).
- **`apps/api/src/common/text.ts`** (new): `text(min, max)` refuses a NUL as `invalid_character` and counts
  length in code points, as JSON Schema and `char_length` do. It is used on every free-text account field
  and on the `q`, `industry`, `tag`, `state` and `lga` query values (D-L78).
- **`audit-writer.ts`**: a new `account` object type and label. `admin.openapi.yaml` lists it in the audit
  description and in the export `filters.objectType` enum.
- **`docs/api/records.openapi.yaml`**:
  - Five operations are flipped to `x-kasuwa-implemented: true`. `getAccountMap` stays `false` (501).
  - `parent_depth` is documented in the create and update descriptions, beside `parent_cycle`.
  - The header and `info` no longer say "contract only"; the version is `0.5.0-T-0055`.
- **`team/FEATURES.md`**: regenerated with `pnpm -s features`.

## What was hard

- **Cycle versus depth from the guard.** 0026 raises both with SQLSTATE 23514 and constraint
  `account_hierarchy`; only the message differs. The API runs its own walk first, so the guard path is hit
  only by a genuine race, as in the suite's concurrent half-cycles. For that path I classify on the
  guard's fixed message text. That text is in an applied migration and so cannot change silently. A unit
  test pins both messages, and an integration test drives the real guard.
- **The NUL rule** needed lengths counted in code points as well, or an emoji name valid by the contract
  would be refused. `text()` does both.
