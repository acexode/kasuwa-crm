# T-0198 — zod 3 to 4

Mechanical rewrites, applied everywhere: `z.string().uuid()` to `z.uuid()`, `.url()` to `z.url()`, `.email()` to `z.email()`, `.datetime()` to `z.iso.datetime()`, `z.ZodIssueCode.custom` to `'custom'`, `z.ZodTypeAny` to `z.ZodType`, `.strict()` and `.passthrough()` to `z.strictObject()` and `z.looseObject()`, one-argument `z.record(v)` to `z.record(z.string(), v)`, `z.ZodType<T, z.ZodTypeDef, unknown>` to `z.ZodType<T, unknown>`. No `any`, no new casts; one cast was removed (`customFieldsSchema`).

## Behaviour differences found, and how each was kept the same

1. **Issue codes on the wire.** Both error filters (`ValidationExceptionFilter`, `toDetails` in `admin-errors.ts`) put `issue.code` straight into `details[].code`, and clients switch on it. zod 4 renamed three of them. New `apps/api/src/common/zod-issue-code.ts` (`wireIssueCode`) maps them back, with a unit test:
   - `invalid_format` to `invalid_string` (uuid, regex, email, url, datetime)
   - `invalid_value` to `invalid_literal` (one allowed value) or `invalid_enum_value` (several)
   - `invalid_key` (a record key that fails) to the code of the key's own failure
   Every other code (`invalid_type`, `too_small`, `too_big`, `unrecognized_keys`, `custom`) is unchanged, and `custom` still carries `params.reason`. Status, `validation_failed` and the field paths are unchanged. No message is read.
2. **A key that is absent, with a schema that is only a transform.** In zod 4, `z.unknown().transform(fn)` as an object key refuses an absent key (`nonoptional`); in zod 3 it ran with `undefined`. The notifications query and the mark-all-read body are written this way (the value decides the default). They now read `z.unknown().optional().transform(fn)`, which restores the zod 3 behaviour. `metadata-engine` already had `.optional()` there.
3. **Records keyed by an enum are exhaustive in zod 4.** `z.record(ScriptLocaleSchema, ...)` would have demanded all seven locales. It is `z.partialRecord(...)`, as before.
4. **`.default()` on a pipe.** zod 4 returns the default as the output, skipping the pipe; zod 3 ran it through. `Limit.default('25')` in `scripts.schemas.ts` is `Limit.prefault('25')`, which keeps the zod 3 behaviour (the string is parsed to 25).
5. **UUID strictness.** `z.uuid()` checks the RFC 9562 version and variant bits. zod 3 accepted any `8-4-4-4-12` hex string. Every uuid literal in `apps`, `packages`, `tests` and `tools` (518 distinct) passes `z.uuid()`, except the nil uuid, which zod 4 special-cases and accepts. So `z.guid()` was not needed anywhere. If a later fixture builds an id by template that is not v1 to v8, it will now be a 400. Uppercase is still accepted (the adversarial suite checks it).
6. **`z.number().int()` is now a safe integer.** A JSON integer above 2^53 used to pass `.int()` and is now `too_big`. Fields that also carry a `.max()` (every list `limit`) already refused it. The few that do not (a version or a count) now refuse a value above 2^53. Our own clients never send one, and the database column could not hold it, but this is a real, if tiny, change in what is accepted.
7. **`unrecognized_keys`, closed bodies.** Unchanged. `z.strictObject` refuses an unknown key as one 400 naming the key. `CreateContactBody` keeps the deprecated `.strict()` on purpose, see below.
8. **`invalid_union_discriminator` has no zod 4 equivalent.** A discriminated union that fails is `invalid_union` at the discriminator path. No test, contract or mock uses either code for a request body, so nothing maps it. Noted in case a client switches on it.
9. **`email` with `.trim()`.** `z.string().trim().email().max(320)` in tenant provisioning is `z.string().trim().pipe(z.email().max(320))`, so the trim still runs before the format check.
10. **`@kasuwa/config` enum messages.** `describeIssues` and `storage-env` rebuilt the enum message from `issue.options` so a pasted secret is never echoed. The zod 4 issue is `invalid_value` with `values`; the rewrite keeps the same text and still never reads the input. Env defaults (`.default()` on enums, booleans, coerced numbers) behave the same; the `config-schemas` acceptance and the config unit tests pass unedited.

## Forced choices

- **`CreateContactBody` keeps `.strict()`.** `tests/acceptance/tenancy/adversarial.acceptance.test.ts` reads `apps/api/src/contacts/contacts.schemas.ts` as text, finds `export const CreateContactBody = z`, then requires `.strict();` after it. `z.strictObject(...)` would fail that suite, which may not be edited. The method is deprecated in zod 4 but still closes the object. When the suite is next amended, the schema can move to `z.strictObject`.
- **`.strict()` or `.passthrough()` elsewhere** all moved to `z.strictObject` and `z.looseObject`.
- **Prettier.** Files touched by the object rewrites were passed through prettier (the repo's `.prettierrc`) so the indentation is right; the working tree is CRLF and git normalises it, so the diff is the real change.

## zod/mini for the browser (D-L209)

`apps/web` client code (29 modules under `components/` and `lib/`) now imports `* as z from 'zod/mini'`; the server (`api`, `packages/*`, worker, realtime) stays on classic zod. No `zod/v3`.

- Conversion by a TypeScript-AST codemod, then hand fixes: `.optional/.nullable/.default/.catch` become `z.optional(...)` etc.; `.min/.max/.regex/.trim/.toLowerCase/.positive/.nonnegative/.refine` become `.check(z.minLength|gte|...)`; `z.number().int()` becomes `z.int()`; `.extend` becomes `z.extend(base, shape)`; `.transform` becomes `z.pipe(x, z.transform(fn))`; `object().partial().passthrough()` (audit actor) becomes `z.looseObject`; `z.ZodType` becomes `z.ZodMiniType`. The codemod wrongly rewrote `response.json().catch(...)` on Promises; those were restored.
- Left on classic by design: `lib/server/bff-forward.ts` (route handler, server only) and `lib/locale.ts`, which reaches `@kasuwa/config/feature-flags` (used only by server components). No client module imports classic zod or a classic-zod shared schema.
- New unit test `apps/web/lib/zod-mini.test.ts` pins the pipe/transform and looseObject conversions.
- First-load JS (next build), before to after: `/` 144 to 128 kB; `/deals/[dealId]` 176 to 159 kB; `/leads` 179 to 162 kB; shared 104 kB unchanged. A zod 3 build of `origin/main` was not run.
- Checks: web lint, web typecheck, 84 web unit files (1051+ tests) all pass.
