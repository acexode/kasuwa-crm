# T-0143 — cleanup pass on the merged D-L193 screens

Branch `agent11/T-0143-ui-cleanup`. Agent 11. Testing is deferred under D-L201, so no suites were run on
purpose. Lint and typecheck passed on every commit through the pre-commit hook. `origin/main` was merged
after P28 (#198) and P18 (#199) landed.

## What changed

1. **Admin home "Not set plan" (P02/A).** The subtitle now leaves the plan out when no plan is stored:
   "Sahel BPO · 1 country · 3 users". The plan is still shown when one exists ("Trial plan").
   - **API: the field is an empty string, not null.** `planName` is now `''`, not `null`. The committed
     acceptance suite asserts `expect(tenant.planName).toEqual(expect.any(String))`
     (`tests/acceptance/admin/admin-home.acceptance.test.ts:242`). Null would fail that test, and builders
     may not edit acceptance files.
   - **Web side.** The web contract (`apps/web/lib/admin-api.ts`) already accepts `string | null`. The
     subtitle treats null and empty the same way, using the new key `admin.home.subtitle.noPlan` (added in
     all 8 catalogues and in the admin bundle).
   - **OpenAPI.** `docs/api/admin.openapi.yaml` describes the empty value. Its example is unchanged, so the
     admin mock regenerated with no diff.
   - **Switching to null later** takes two changes: the lead amends the acceptance assertion to allow
     null, and line 110 of `home.controller.ts` sends `null` instead of `''`.
2. **Admin bar at 360.** The page was 365 px wide at 360, for two reasons:
   - The header had about 17 px more content than room, so the avatar's `before:-inset-1` hit band
     overflowed.
   - The residency pill had been squeezed down to 25 px.

   The fix:
   - Phone gaps are 4 px (`gap-1`, `sm:gap-3` unchanged).
   - The pill is a fixed 32 px circle below `md`, and unchanged from `md` up.

   I measured `scrollWidth` on every admin route (admin home, audit, custom fields, field security,
   programmes, a programme, roles) at 360, 390 and 768. It equals the viewport on all of them.
   - **Nav labels.** "Users & Access" and "DND & quiet hours" match the P02 copy. Each key is used only by
     `nav-model.ts`. pcm's `co-dnd` is a declared passthrough, so its value was updated to stay identical.
3. **P07 phones:** the FAB on `/activities` is gone. Only the app-bar `add_circle` remains, as the phone
   frames draw it.
4. **Dates.**
   - **Cause.** Bare `en` is ICU's American English. The new `apps/web/lib/date-locale.ts` formats bare
     `en` as en-NG (day first, 24-hour) and writes "Sep", not "Sept".
   - **Record timeline and related.** `record-core.formatDateTime` now gives "20 Oct 15:00 WAT", with the
     year only when it isn't this year. That covers the timeline "Due", meeting times, the deal's checks,
     the script run's follow-up (`formatWhen`) and P28's import/duplicate times (`import-text.formatWhen`).
   - **Other English dates.** Day headings read "Thu 3 Sep". Created, pipeline, script-list, run date
     answers, admin `formatDate`/`formatDateTime` and custom date values now read "20 Oct 2026".
   - **"GMT+1" removed.** The P10 version banner (`clock()`) and the list "last synced" time now use
     `formatClock`/`zoneName()`, so they read "13:55 WAT".
   - **How it was checked.** I scanned 31 merged routes' rendered text before and after, looking for
     month-first dates, AM/PM and GMT/UTC offsets. Remaining hits are day-first, plus the designed "WAT ·
     UTC+1 · Lagos" pill on P07. I also checked the outputs in fr, ar and yo, and in Africa/Nairobi
     ("20 Oct 17:00 EAT").
5. **P10 compliance tick.** It is now the `@kasuwa/ui` Checkbox:
   - Same `data-action="acknowledge"` and `data-requires-connection`.
   - Checked when the server has the acknowledgement, and disabled after that, as before.
   - Once acknowledged it draws as a success-filled tick on the success row, not as the grey
     disabled box.
   - The row is 48 px, and the label is a 44 px target.
6. **`color-scheme`.** The `css.ts` generator now emits `color-scheme: light` on `:root` and `dark` in
   both dark blocks; `tokens.generated.css` was regenerated with `pnpm ui:tokens`. In dark mode, unstyled
   native selects, date inputs and checkboxes now draw dark; before, they drew white boxes.
   - **Scrollbars and popups are not visually confirmed.** Headless Chromium draws no scrollbars and does
     not capture native select popups. `getComputedStyle(html).colorScheme` reads `dark` under the dark
     preference.
7. **Icons.**
   - `sync` was already in the subset (T-0141). I added `table` and re-ran `pnpm ui:fetch-fonts`. The
     symbols font went from 26,060 to 26,104 bytes, and no other font file changed.
   - **Swaps.** P01's import-in-progress row uses `sync` and the CSV source tile uses `table`.
   - **Render check.** Both glyphs render from the live font; a glyph not in the subset falls back to
     its letters.
   - **Not swapped.** `simple-steps.tsx` still uses `description` for the WhatsApp "registration
     document" line. That is a real document glyph, not a stand-in.

## Open questions

1. Should the acceptance assertion on `planName` allow null? If yes, the API should send null, as the
   brief intended.
2. Wherever several English variants are in use, the locales are inconsistent:
   - `record-core.zoneName` maps zones by their English long name for every locale (French gets "WAT").
   - `admin-format.formatZone` asks the locale itself for the zone name (French gets "UTC+1").

   One rule should win. I left both alone because both predate this task.
