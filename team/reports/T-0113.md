## What changed

  - Two tables:
    - `script`, the draft: name, source locale, `draft_graph`, `draft_translations`, `revision`,
      `published_revision`, timestamps.
    - `script_version`, one row per PUBLISHED version: number, name, source locale, graph,
      translations, `changes`, `published_at`, `published_by_user_id`. It has no `updated_at`.
  - RLS ENABLED and FORCED on both. One FOR ALL policy each, on tenant AND programme, with WITH CHECK =

## What was hard

- **The body limit.** The suite boots the API through `createApi`, so the limit cannot be a
  `NestFactory` option. Nest skips its default JSON parser if a middleware named `jsonParser` is already
  on the router. `HttpAdapterHost.init$` fires when the adapter is attached, which happens before
  `init()` on both boot paths. A provider can therefore install a parser with the higher limit first. A
  unit test pins this.
- **A discriminated union needs plain object members.** The duplicate choice-key and field-key checks
  had to move from the node schemas up to the graph schema.
- **Offboarding against an immutable version.** A version's FKs must be RESTRICT and must never touch a
  version row. The delete guard reads current_user only, never session_user, so that a cascade (which
  runs as the table owner) passes.

## Open questions

1. **`empty_script` is a new publish refusal (my choice, please confirm).** The ruled empty draft, one
   `end` node that is also the start, is a complete graph by the contract's rules. The suite requires the
   empty draft never to publish ("an empty draft ... is never publishable"). So publish now refuses any
   graph whose nodes are all `end` nodes, as `409 script_invalid` with `{ path: 'nodes', code:
   'empty_script' }`. A script with nothing for an agent to read is not a script, so I think this is the
   right rule, but it adds a detail code to the contract (named in publishScript's description, beside
   the others). The alternative was a stored "untouched" flag, which I liked less.
   - The placeholder's title is `End`, server-written draft content (not a UI string). The author
     replaces it with the first saved graph. I used the contract's `type`, not `kind`, and its required
     `title`.
2. **Answered by the coordinator**: the global 512 KiB body limit stands; T-0114 reads `script.run` from
   the policy (until then `SCRIPT_RUN_SET_KEYS` in `scripts.repository.ts`); the listProgrammeScripts
   states (`draft` at version 1, `published` at the latest number, `languages`, no `channels`), the
   script-name audit label and the 64-change cap are fine.
3. **Builder's readings the suite allows**:
   - Changing the source locale to a locale that already has a translation is 400 `translated_locale`.
   - `unchanged` compares name, source locale, graph and translations.
   - A translation of a node that was later removed stays on the draft. Publish then refuses it
     (`unknown_node` and similar) rather than silently dropping a translator's work.
   - A node no path reaches is `unreachable_node`.
   - A duplicate node id is refused on save as `duplicate_id`.
   - An answer condition on anything but a question, or a form field, is `unknown_variable`.
   - createScript with a missing or malformed `programmeId` is 400, not 404.
4. **Not checked**: whether an answer branch's node comes before the branch on every path. A revision at
   2^31-1 cannot advance (`revision + 1` would fail as a scrubbed 500); this is unreachable in practice.
