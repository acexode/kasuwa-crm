## P26 (24 failures in the gate)

The "sent the API something" failures did not come from the poller, timers or params. The mock recorded
exactly one violation in every one of them: `GET /api/v1/auth/me is not an operation the notification
screens use`. That read is T-0130's shell avatar. It reads the signed-in name once per page load, by design.
Once it was answered, every polling, cadence, list, cursor, mark-read and 429 journey passed unchanged. No
violation of any other kind appeared in any run.

- **Spec amended, 21 journeys** (flag-on, polling, throttle ×2, latest, centre ×2, paging, days, sentences,
  markup, mark-read, read-all, lost ×3, privacy, axe, mobile, tablet, pseudo). This is T-0130: the shell's
  identity read is not a notification-screen read. `support/notifications-mock.ts` now answers
  `GET /api/v1/auth/me` with a `CurrentUser` body, validated strictly against `docs/api/auth.openapi.yaml`.
  It records the read in `shellReads` and still runs the scope-header, programme-query and name-in-URL
  checks on it. A non-GET, a query or a body on it is still a violation, and so is anything else under
  `/api/v1`. The spec file itself is unchanged.
- **Bug fixed: "requests still in flight"** (the bell budget, and the cause of the in-flight failures on the
  other shell pages' budget journeys too). The shell's `/auth/me` read ignored the body of a refusal. Where
  the read reached the real BFF (`otherScreens`), its 401 body was never read, so CDP never reported the
  request finished and `measurePageLoad` waited forever. `use-shell-user.ts` now cancels a refusal's body
  (`readShellUserName`, unit test `use-shell-user.test.ts`).
- **Bell budget (D-L182/D-L177):** passes at 7,037 bytes against 8,000, so about 1 KB of headroom. The
  dropdown and centre stay lazy.
- Byte budget and paint: T-0145. Paint passes. The /notifications byte budget fails on bytes only.

## P27 (21 failures in the gate)

**Bugs fixed**
- **Focus trap (`@p27-search-palette`, `@p27-search-focus-trap`, D-L137 M2).** `useOverlay` in `packages/ui`
  counted `tabindex="-1"` links (the palette's Go to rows and hits) as tab stops. Tab from the close button
  therefore walked out of the dialog. `focusables` now keeps only `tabIndex >= 0`. Unit test:
  `packages/ui/src/components/overlay.test.ts`.
- **axe, scrollable-region-focusable (palette with results).** The palette's scrolling rows had no tab stop.
  The region is now `role="region"`, named, `tabIndex=0`, with the focus ring.
- **axe, aria-required-children (dropdown A1).** The per-group "see all" link sat inside the listbox. It is
  now `role="option"` with `aria-selected=false`, in the same place as the design draws it, and keeps its tab
  stop.
- **axe, color-contrast (results page, no matches).** Object facets with no hit were dimmed with
  `opacity-50` while still active, which drew text under 4.5:1. They are now `disabled`, in the Checkbox
  disabled tone. Ticking one would narrow the results to nothing.

**Spec amended** (`tests/e2e/p27-search.spec.ts`; each spot carries a `T-0148 (T-0138 …)` comment)
- Helpers. On `/search` the box is the top bar's `shell-search` field from md up, and the page's own field
  below md (P27/C). `input()` finds either, and `pageOf()` is the screen together with its box. Hits are
  located by `data-hit-type`, because the results page is a flat list. Group order is read from the hits,
  and where groups are drawn, every hit must sit in its own type's group. That keeps the old locator's
  guarantee. Used by flag-on, shell, rate-limited, requests, lookup-email, unicode-identifiers, url, the
  three states, additive, mobile and pseudo, with no assertion removed.
- `@p27-search-shell`: the header's entry from md up is the `shell-search` combobox. `aria-current="page"` is
  still asserted on the app bar's `/search` link.
- `@p27-search-keyboard`: the answer arrives with its first option already active (P27 D `csel: 0`). Down
  then goes to the second option, and Up comes back to the first.
- `@p27-search-same-route` (D-L137 M3) and `@p27-search-see-all`: per-type "see all" now lives in the top
  bar dropdown (A1), because the palette (D1) has none. Both journeys run there, with the same assertions.
  On an empty answer, A5 draws no groups, so the spec now asserts that no per-type "see all" is drawn, and
  that "See all results" is a button with no href (the text never goes in a URL). This replaces "the lists
  are still offered".
- `@p27-search-groups`: runs in the dropdown (A1, as its axe label already said). Count, copy and
  announcement checks run on the dropdown panel.
- `@p27-search-pseudo`: the type label checked is each row's type tag, because the results page has no group
  headers.
- `@p27-search-absent`: amended narrowly (D-L194/D-L195). Now allowed: the results page's Filters card
  with OBJECT boxes, which narrow what was served and count nothing; Sort; the palette's commands and Go to;
  the `dialpad` glyph of the D-L195 phone strip; and the phrase "with or without spaces" in that strip's
  whole-number guidance. Still banned while their flags are off here: recents, scope, Ask AI, owner and date
  filters, calls, tickets, wallboard. Banned everywhere: counts, the hidden-results count, a partial-number
  promise, unserved groups. New checks: every checkbox is an object facet, every sort but the served order
  is disabled, and every create offer is disabled.
- `openPalette` presses the chord again until the palette opens. Right after a navigation the chord could
  land before the shell had hydrated (`@p27-search-url` flaked once that way).
- `expectNoSeriousAxe` now names each violation's nodes in its message. The assertion is unchanged.
