## What changed
- **argon2id now runs off the event loop.** It runs on a bounded `node:worker_threads` pool (`packages/auth-crypto/src/worker-pool.ts`).
  - The parameters are unchanged.
  - Pool size is CPU count − 1, between 1 and 4 workers.
  - The queue caps at 32; past that the request gets a 503.
  - Tasks start in arrival order.
  - A failure rejects only the task it hit.
  - Idle workers are unref'd so CLIs still exit.
- **The worker is inline (`eval: true`) and loads `hash-wasm`** from a path resolved on the main thread. The build bundles `dist/hash-wasm.cjs`, and deploys must ship that file (D-L56).
- **`connectionTimeoutMillis` defaults to 5 s.** Before, pg waited forever for a free connection.
- **Defects fixed, each with a failing-first test:**
  - `dummyPasswordHash()` cached a rejected promise. That meant a lasting 503 for unknown users, which was an account-existence oracle.
  - The pool kept CLIs alive.
- **Review fix (security, major):**
  - The dummy hash is now fetched inside the 503 mapping, so a cold cache plus a full queue gives the same status for unknown and known users.
  - The dummy hash is warmed in `onModuleInit`.
  - The pool gains task and start timeouts, retires a worker that sends a bad reply, and backs off respawns exponentially when workers fail to start.

## Unverified and left out
- **The acceptance timing bounds** (probe latency, the unknown/known ratio of 1.5) depend on the CI runner's core count. This is the most likely failure on the first Docker run.
- **A pool connection timeout surfaces as 500, not 503** (D-L56).
- **Worker memory:** up to 4 isolates, each holding a 19 MiB buffer while hashing.
