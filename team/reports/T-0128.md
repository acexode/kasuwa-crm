## Where the component deliberately differs from the e2e spec (please check)

1. **Tabs.** The e2e expects the active tab at 600 with a 2px `border-bottom`. Every design source draws it at
   **700, inactive 500, with a 3px primary underline drawn inside the tab**:
   - v1.1 Components, script block: `fw: i === s.tab ? 700 : 500`, `bar: 'inset 0 -3px 0 var(--k-primary)'`;
   - P05 record tabs, computed at 360: `font-weight: 700`, `box-shadow: rgb(43,42,140) 0px -3px 0px 0px inset`,
     with inactive tabs at 500;
   - P05 composer tabs at 1440: the same;
   - P07 composer tabs at 1440: the same.

   I built it to the designs, so these e2e assertions fail by design, in both themes: `font-weight '600'`,
   `border-bottom-width '2px'` and `border-bottom-color`. The underline is an `after:` pseudo-element, so the focus
   ring does not replace it. **Suggested assertions:** active `font-weight` `700`; read the `::after` element's
   height (`3px`) and background colour (primary).
2. **Focus ring regex.** The e2e assertion `toMatch(/0px 0px 0px 2px .*0px 0px 0px 4px/)` cannot match the v1.1
   ring in Chromium.
   - The computed value, measured, is `rgb(255, 255, 255) 0px 0px 0px 2px, rgb(78, 75, 190) 0px 0px 0px 4px`.
   - After `2px` comes a comma, never a space.
   - The other focus assertions pass: outline-style `none`, and the focus colour is present.
   - **Suggested regex:** `/0px 0px 0px 2px,.*0px 0px 0px 4px/`.

## Deviations and gaps against v1.1 (decided, not hidden)

- **Select** is the platform `<select>`.
  - Closed, it matches v1.1 exactly: 44px, edge, 15px value, chevron, and every state.
  - The v1.1 drawn list is a menu (radius-10 panel, 40px rows, `check`), and menus are T-0129. The native list is
    the better one on the target phone.
  - In dark mode the native list is light, because nothing sets `color-scheme`. Adding `color-scheme` to the token
    CSS would change scrollbars and native controls on every screen. That is the lead's call.
- **Segmented control.** Inactive items are text-2, as in P04 and in v1.1's own currency picker. v1.1's density
  toggle draws them in text.
- **Tabs** use `0 12px` padding (P05 and P07, measured). v1.1 uses `0 14px`.
- **Presence.** Only `available` and `offline` are built.
  - v1.1's on call, wrap-up and break presences need a 12px glyph in an 18px disc, and there is no 12px icon size.
  - The presence pill ("On call · 03:12") and the avatar stack are not built either. They belong to the shell and
    voice tasks.
- **Interaction colours the designs do not specify,** so I took the nearest specified one:
  - filter chip hover is surface-sunken (the secondary button's hover);
  - ghost icon-button hover is surface-sunken;
  - an icon button's `:active` has no extra style. v1.1's "Active" icon button is drawn as the `pressed` (toggle-on)
    state.
- **Compact buttons** use 13/600 text and 18px icons from `md` up (P04 "Columns" and "All leads"). v1.1 only states
  the 36px height.
- **Error field in focus** takes the primary focus edge, because `field-focus` sets border-color. Neither design
  shows this case.
- **Gallery wording.** State labels are capitalised ("Full name · Default") where v1.1 writes "default". The button
  grid's label column is `auto`, not 78px, because there is no token.
