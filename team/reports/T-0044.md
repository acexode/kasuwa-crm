# T-0044 — Migration runner: marked non-transactional mode (Agent 1)

**State:** merged to `main` as #82. This closes the runner gap in D-L65.

**What changed:**
- **The marker:** a file whose first line is exactly `-- kasuwa:no-transaction` runs without a transaction, one statement at a time, over the extended protocol.
- **What a marked file may contain:** an allowlist matched on tokens. It permits `CREATE [UNIQUE] INDEX CONCURRENTLY`, `DROP INDEX CONCURRENTLY`, and `ALTER TABLE … VALIDATE CONSTRAINT` on its own. Every marked file is checked before anything runs.
- **Failure:** a file that fails is not recorded, and the error explains how to clean up the INVALID index it left behind.
- **The splitter:** `migration-sql.ts`, aligned with PostgreSQL's own lexing rules.
- **Documentation:** the `create-rls-migration` skill now documents the mode.

**Evidence:**
- Lead suite: 41/41 (35 failed on main beforehand).
- Unit tests: 56 new splitter/allowlist tests.
- Integration: 101/101.
- schema-hygiene: 8/8.

**Hard parts:**
- Postgres treats a multi-statement query string as a single implicit transaction, so the runner has to split statements itself.
- Refusal had to happen before any statement runs.

**Open:**
- A file that starts with a UTF-8 byte-order mark is not recognised as marked. It fails loudly, which is the safe direction.
- Only pending marked files are checked against the allowlist.
