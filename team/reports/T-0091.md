# T-0091 — Custom values on the record screens

**Agent 11** · branch `agent11/T-0091-custom-values` (on the T-0090 build, `733d38f`, with `lead/T-0091-acceptance` merged).

## What changed
- `crm_custom_fields` (already registered by T-0090) is read on the server by all eight record routes via `crmCustomFieldsEnabled()`; the screens get a `customFields` prop. No client module names the flag.
- `lib/custom-values-api.ts` reads `listCustomFields` (active only, never `includeRetired`, Zod, same-origin). The studio client now builds its `includeRetired` query as `String(true)` so the record-side static scan (`includeRetired: 'true'`) does not trip on it.
- `lib/custom-values-model.ts` (format, encode, patch, rebase), `custom-values-core.ts` (key paths, refusals), `custom-values-filters.ts` (list query, `field_withheld`). Amounts and decimals are strings end to end; `Intl` gets the decimal string.
- `components/custom/*`: record slots (`CustomValuesPanel`), form inputs, list filter bar, definitions hook, per-kind message subsets.
- Contact (and lead, same screen), account and deal records show values per record from `withheldFields`; their edit sheets send per-key merge patches; a key turns read-only only after 403 `field_not_editable`. Record activity forms and the P07 composer create with values only. Contacts, leads, accounts and the pipeline list view filter (picklist/boolean equality, `is-empty`); the board read never carries a custom filter.
- 14 `custom.*` strings in en, fr, pcm, ha, yo, ig, sw, ar (pcm declares Yes/No as passthrough). Unit tests: `lib/custom-values-model.test.ts`.
- Contact sheet: the emails/phones textarea is marked `data-record-text` (tenant data; the en-XA walker flagged it).

## Byte budgets (the hard part)
Flag on with no definition costs a request, 16 strings and some code. First measurements were over four pinned budgets:

| Screen | Measured | Budget | Over by |
|---|---|---|---|
| contact record | 237,995 | 236,000 | 1,995 |
| contacts list | 228,807 | 226,000 | 2,807 |
| accounts list | 238,057 | 235,000 | 3,057 |
| account record | 249,326 | 245,000 | 4,326 |

Fixed by shipping less: the panel and filter bar load only when a definition exists; message subsets per kind; and the edit sheets, record activity forms, accounts sheet, the contacts phone filter sheet and the column chooser (moved to `records/column-chooser.tsx`) now load when opened. After that every existing records-ui, scripting-ui and studio suite passes inside its pinned budget. Closest runs before the last change: contacts list 226,550 vs 226,000 (then more was moved lazy and it passed). I did not record final measured bytes (the suites print them only on failure); the budgets have little headroom.
