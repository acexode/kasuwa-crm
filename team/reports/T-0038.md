# T-0038 — replacing an MFA factor kills the old backup codes (Agent 1)

**State:** merged to `main` (#73). It implements D-L58.

**What changed:** confirming a replacement factor does three things:
- it marks every unused backup code used (`retireUnusedBackupCodes`);
- it issues a fresh set of ten through the existing path;
- it returns that set once, with `no-store`.

All three happen in the same transaction and under the same per-user lock as the factor swap. The OpenAPI confirm response is now `BackupCodesIssued`.

**Evidence:**
- **Lead suite** (`lead/T-0038-acceptance`): it failed on `main` because no fresh set came back. It passes now, 16/16.
- **Builder's local Docker run:** unit 734/734, integration 98/98.
- **After rebasing on `main`:** the enrolment and authentication suites pass 28/28.

**Hard part:** `issueBackupCodes` already replaces the whole previous set, so the explicit retire is redundant today. It is kept as the intent, so the old codes stay dead if the issue path ever changes.
