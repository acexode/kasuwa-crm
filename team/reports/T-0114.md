## What was hard

- **One status per route in Nest.** startScriptRun's 200/201 cannot be set with
  `@Res({ passthrough: true })` (Nest's reply overwrites it with the route's 201), and `@Res()`
  without passthrough would send before COMMIT, so a client could read an uncommitted run. Hence the
  small outer interceptor. Worth a look by whoever owns `src/tenancy`.
- **What "on the path" means for a stopped or completed run.** The semantic 400s (not_on_path, a
  choice) sit before the 409s in the published order; I judge them on the stored path whatever the
  status, and skip the choice check unless the run is in progress (a stopped run rests on a branch, a
  completed one on nothing).

**Accepted by the lead with no change (D-L107):** the missing FKs on disposition, activity and
follow-up task (below); no audit events for completion's call and task (R1); the completion digest
stays unsalted for now (tracked with erasure); the `Africa/Lagos` default for form dates; a

- **No FK on `disposition_id`, `activity_id` or `follow_up_task_id`.** Neither disposition nor activity
  has a `(tenant_id, programme_id, id)` key to reference, and adding one is a lock on two more tables

- **The tenant's zone for a form `date` field.** The contract counts days ahead "in the tenant's zone";
  no tenant carries a zone, so it is `Africa/Lagos` (`RUN_DATE_TIME_ZONE`, the cell's zone in the auth
  policy). Needs a decision when tenants get a zone.
- **The D-P27 sweeper** (deletes a contact's runs before the contact) does not exist yet; the table
  grants kasuwa_app no DELETE.
- Supervisor/QA reads, call-bound runs and live push: non-goals.

## Risks I am aware of

- **Tenancy.** Runs are programme-scoped by RLS and by every WHERE. Own-agent-only is the API's rule,
  not a policy (a supervisor's M11 read will need the policy as it is). The composite keys stop a run
  naming another programme's contact or version even for a supervisor who sees both; the suite proves
  it.
- **Personal data.** Answers and notes are never logged, audited or echoed; the logs-and-spans test
  passes. The completion digest is a SHA-256 of the request (the note included) stored beside the run;
  the note itself is already stored in the call activity, so it adds no new copy of the text.
- **Advisory lock** keyed on tenant, programme, agent, contact and script ids (a hashed text key; no
  value is logged). A hash collision only serialises two unrelated starts.
- **Size.** Over the PR guideline. It splits naturally into db + permissions (0032, policy) and api,
  if the lead prefers two PRs.
