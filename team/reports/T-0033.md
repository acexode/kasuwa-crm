## What changed

- **Audit writer** (`apps/api/src/admin/audit/audit-writer.ts`): `AUDIT_OBJECT_TYPES`
  gains `sla_policy`, `retention_policy`, `disposition`, `portal_user` (D-L54), with
  labels. The export `filters.objectType` enum follows automatically (it reads the
  same constant); the spec enum is updated to match.
- **One audit helper file per area**, so each controller change is a single call
  and T-0032's merge into the same controllers stays easy:
  `sla-retention/sla-retention.audit.ts`, `dispositions/dispositions.audit.ts`,
  `portal-users/portal-users.audit.ts`.
- **SLA / retention**: one `updated` event per successful save, `objectId` and
  `programmeId` the programme. Changes per moved field, strings; `version` is
  always a change, so every save is exactly one event. SLA targets are flattened
  to `targets.<channel>.<key>`.
- **Dispositions**: `created` (all configuration fields), `updated` (only fields
  that moved; a no-op patch records nothing, as `updateProgramme`), `deleted`
  (`code` before → null; the idempotent repeat records nothing, as
  `archiveProgramme`), and reorder as ONE `updated` event, `objectId` null,
  label `Disposition order`, changes `dispositionCount` and `movedCount`.
- **Portal invite**: one `invited` event per invite AND per resend. Fresh:
  `access` plain, `email` redacted. Resend: redacted `inviteToken`. Label is the
  fixed type label; the address (not even the masked hint) and display name are
  never passed to the audit function — its input type has no field for them.
  The event is written **before** the email is handed to the provider, so no
  email leaves unaudited; a failed send throws 503 and rolls both back.
- **Domain-core (additive, Agent 3's package)**: `replaceProgrammeSlaWithPrevious`,
  `replaceProgrammeRetentionWithPrevious`, `updateDispositionWithPrevious`,
  `deleteDispositionWithPrevious`, `reorderDispositionsWithPrevious`. Each returns
  the state read **under the write's lock**, so `before` is the value the write
  replaced (the `updateProgrammeWithPrevious` precedent). The old functions are
  now thin wrappers; their behaviour is unchanged.
- **Spec**: stale "(The audit row is not written yet…)" replaced; invite text no
  longer promises a masked hint (D-L54 wins); audit sections for SLA, retention,
  reorder and delete; `listAuditEvents` and `createAuditExport` lists updated.
  All seven operations were already `x-kasuwa-audited: true`.

## What was hard

The spec said the invite event records "a masked hint plus an opaque id"; D-L54
and the suite say the address never appears. I followed D-L54 and corrected the
spec text.

## What I left out, and why

- Permission checks (T-0032, in parallel).
- Reorder records counts, not the order itself: a long list's order exceeds the
  writer's 300-character value limit, which would turn a valid reorder into a 500.

## Open questions

- `objectLabel` for SLA/retention is the fixed string (`SLA policy` /
  `Retention policy`), not the programme name; the event's `programmeId` carries
  the context. Using the name would need one more read in the controller.
- A no-op disposition patch records nothing; an SLA/retention save with no
  field change still records one event (the version moved). Consistent with
  "one event per write that changes stored state", but the lead may prefer one
  rule.

## Risks I am aware of

- Every new event carries its programme, so D-L48 visibility holds (members only).
- An audit insert failure now fails the write (500) rather than letting it pass
  unaudited — deliberate.
