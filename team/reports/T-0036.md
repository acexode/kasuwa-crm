# T-0036 — No PII through Nest's exception logger (D-L42)

**Agent 13 · PR #67 → `dev`.** Filed by the lead from the builder's hand-backs.

- `UnexpectedErrorFilter` (global, `APP_FILTER`): any non-HttpException gets one fixed 500 body
  `{statusCode, error, code: 'internal_error', message}` and one log line: class, code, method and
  Express route template only. Shared scrubbing lives in `apps/api/src/common/scrub-error.ts`. Only
  real `Error`s yield a class name or code. SQLSTATEs must start with a real PostgreSQL class
  ('12345' rejected); Node codes match `E[A-Z_]+`.
- HttpExceptions pass through unlogged. Zod and cursor errors are delegated to
  `ValidationExceptionFilter`. http-errors messages are echoed only with `expose === true`.
- The request span gets a scrubbed `exception` event. `collectTelemetry` now returns span events.
- `installProcessErrorHandlers` logs scrubbed `uncaughtException` / `unhandledRejection` lines and exits 1.
- `internal_error` is added to both OpenAPI Error.code enums. The web enum and i18n keys landed with T-0035.

**Verified locally:** lint, typecheck, unit 664/664; an in-process probe found no probe value in any
log, stream, span, span event or body. **Not run:** the 8-test acceptance suite (Docker).

**Follow-ups:** Nest's malformed-JSON 400 echoes a body snippet back to the caller; the bootstrap
catch writes `error.message` at boot (configuration errors only); the worker and realtime processes
have no equivalent filter yet.
