## Deviations and open questions for the lead
1. **Autosave was not built.** The brief asked for debounced autosave. The committed acceptance suite pins the
   opposite: R4 in `script-builder.acceptance.test.ts` ("Saves are explicit, never automatic"; at 256 kbps an
   autosave resends a draft of up to 256 KiB on every pause), and `p10-builder.spec.ts @p10-builder-save` asserts
   "the builder saved without being asked" is false.
   - What I built: the design's "Draft saved · n ago" note in its place. While the draft is dirty, the note reads
     "Not saved yet" and a "Save draft" button (`data-action="save-draft"`) appears beside it. In the clean state
     the header matches the export exactly.
   - If you rule R4 superseded, autosave is a small change in `use-script-editor.ts` (a debounced `save()` on
     draft change), plus an amendment to that test.
2. The name input is the visible title, and the `<h1>` is `sr-only` beside it. The e2e needs both a fillable
   `script-name` and a level-1 heading.
3. The compliance diff (`compliance-diff`) is under the palette, not in the publish popover. The e2e expects it
   visible on open; it is hidden below md.
4. The design's "Edit" on finished steps is "Show"/"Hide", which unfolds the step read-only. The run API has no
   rewind (D-L195).
5. The auto-branch line ("Auto-branch · Over 30 days past due? No…") is not drawn. The builder tells authors
   "Agents never see this step", and showing branch titles to agents would break that promise. It needs a ruling.
6. The palette's Form description is "Fields the agent fills in", not "Fields that write to the record". The
   contract (D-P31) says form fields write nothing to the record.
7. `scripting.nodeType.compliance` is now "Compliance" (from "Compliance statement"), in every locale.
8. The run's compliance checkbox is still native, so it is a light box in dark mode. Swapping in the
   `@kasuwa/ui` Checkbox is the follow-up.
9. The banner time names the browser zone as Intl renders it ("14:55 GMT+1"), not "WAT".
