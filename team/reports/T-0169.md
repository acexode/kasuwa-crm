## What changed

- Migration `0051_payment_links.sql` adds `payment_link` and `payment_event`, and adds `paid` to the quote status check.
- RLS on those two tables is tenant-scoped. A webhook has no user, so a programme-scoped policy would hide every row. The repository still filters `programme_id`. The quote update runs afterwards as the link's creator. No third `SECURITY DEFINER` function.
- `paymentProviderFor` derives a per-tenant fake webhook secret. Production still returns the null provider.
- `POST /api/v1/programmes/:programmeId/quotes/:quoteId/payment-links` requires `quotes.write` and an idempotency key. The amount is the quote total.
- `POST /webhooks/:provider/:tenantSlug` has no session. Unknown slug, bad signature, unreadable body and unknown link all return the same 401.
- A paid event marks the quote `paid`. The deal moves to the existing won stage only when the current stage has a transition there and that stage has no requirements. The seeded deal sits on the first open stage, so `dealMoved` is false. The stage is named Won.
- Flag `payment_links`, default off, not production-ready. Real provider SDKs are not in this change.

## Left out

Refunds, partial payments, reconciliation, and any live provider. A cancelled provider status is not stored.
