# T-0167 — Quote PDF template and send by email

## What changed

- Migration `0050_quote_send.sql`: programme-scoped `quote_send`, RLS enabled and
  forced, `kasuwa_app` SELECT+INSERT only (append-only). Channel CHECK = `email`.
- Drizzle mirror + `TENANT_SCOPED_TABLES` entry.
- Domain: deterministic PDF 1.4 buffer (no new deps); `recordQuoteSend` after a
  successful provider send; draft→`sent` on first send.
- API: `GET /quotes/:id/pdf`, `POST /quotes/:id/send` via channel adapter email
  kind. Fail closed: any `ChannelError` → 503 `service_unavailable`, transaction
  rolls back (no row, no status flip). WhatsApp refused at Zod boundary.
- Flag `quote_send` (off by default, on in `pnpm demo`). Writes still need
  `quotes.write`.
- OpenAPI: `renderQuotePdf`, `sendQuote` (+ repaired Quote schemas that had been
  nested under `security` from T-0165).
- Acceptance suite + task file (lead-authorised on this branch via protect-paths
  allowance).
- Unit tests: PDF determinism; send 404/403/503/validation/`not_sendable`.

## How PDF / fail-closed works

- **PDF:** `renderQuotePdf(quote)` builds a fixed PDF 1.4 document from quote id,
  version, status, currency, line product ids/qty/amounts and totals. Same inputs
  → same bytes. No email addresses in the content stream.
- **Send:** `channel.send({ channel: 'email', … })` first. On success,
  `recordQuoteSend` inserts and may flip draft→sent. On `ChannelError`
  (including production `NullChannelProvider`), map to 503 and throw so the
  tenant transaction rolls back. Fake provider in test/dev records the send.
