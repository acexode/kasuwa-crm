## The one cause

All 56 failures had one cause. In the gate log, 42 of them record "navigated to http://127.0.0.1:<port>/", and the rest are the same thing seen from a different assertion (fill/click timeouts, `dir="ltr"`). Every mocked admin page was sent to sign-in before it rendered:

- Since T-0130 the admin shell reads `GET /api/v1/auth/me` for the avatar (`components/shell/use-shell-user.ts`).
- `installAdminMock` routed only `**/api/v1/admin/**`, so that read reached the real BFF.
- The default e2e web process runs `KASUWA_AUTH_MODE=jwt`. There, a cookieless 401 is marked `x-kasuwa-session: ended`.
- `apiFetch` then sends the page to `/`.

That redirect is correct for a real signed-out visitor, so the screen is fine. The mock was not serving the identity of the admin it simulates. The CRM suites don't hit this because they run on the stub-mode records process.
