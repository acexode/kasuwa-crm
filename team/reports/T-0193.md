# T-0193 — Conversation search types

## What landed (on `feat/t-0191-inbox-realtime`)

- Flag `conversation_search`, default off, not production-ready.
- When the flag is on, `searchRecords` accepts `types=conversation`. Scope is
  `tx.session.programmeIds` only. The query repeats `tenant_id` and
  `programme_id`. A conversation outside the caller's programmes is absent
  (no 403, no count).
- Hits are `{ type, id, programmeId, preview }`. Preview runs through
  `redactMessageBodyForStorage`. Nothing logs the query or a message body.

## Before turning the flag on for any tenant

Hits are ordered by `conversation.last_message_at` (then `id`). The prefix
match on `subject` / `message.body_redacted` has no supporting index today.
An index for that match is needed before `conversation_search` is enabled for
any tenant. That is a **separate migration**, needing lead review. It is not
in this branch.
