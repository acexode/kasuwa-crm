# T-0121 report: error envelope and no-store on every answer

## Changed
- `apps/api/src/common/json-body-limit.ts`, in `JsonBodyLimit`'s `init$` hook, installed in this order on the adapter, before Nest's parsers:
  1. `safePathEncoding`: re-encodes a `%` in any path segment that does not decode (`%25`), so Express never throws "Failed to decode param". The route then answers as it does for `zzz`. The query string is untouched.
  2. `noStoreEverywhere`: `Cache-Control: no-store` on every answer, `/health` included. It runs before the JSON parser (E6).
  3. The JSON parser, then `jsonParseErrorHandler` (unchanged).
  4. `bodyParserErrorHandler`: any 4xx error that reaches it (413, the 415s, the corrupt-gzip 400) becomes `{statusCode, error: <Node reason phrase>, code: validation_failed, message}` with no echo.
  5. The urlencoded no-op, now named explicitly with `Object.defineProperty(..., 'name', ...)`.
- `unexpected-error.filter.ts`: a 404 on a request with no matched route becomes the `not_found` envelope, with no path echoed.
- Unit tests for each of these in `json-body-limit.test.ts` and `unexpected-error.filter.test.ts`. The existing NotFound filter test now supplies a matched route, because an unmatched one is now enveloped.
